# Изменения в строках затрат FinanceDocumentDialog

## Что изменили

В диалоге `FinanceDocumentDialog` переработан грид `Строки затрат` для авансового отчета. Цель правки — сделать ввод строк быстрее и ближе к ручной бухгалтерской работе: пользователь кликает строку, сразу попадает в дату, вручную вводит детали проводки и сумму, а не выбирает лишние служебные привязки в каждой строке.

## Новый порядок колонок

Порядок видимых колонок в гриде теперь такой:

1. `№`
2. `Дата`
3. `Детали проводки`
4. `Счет расхода`
5. кнопка выбора счета `?`
6. `Сумма`

Колонка `Детали проводки` перенесена из конца таблицы в середину и получила растягиваемую ширину с минимальным размером. Это исправляет ситуацию, когда последняя колонка была зажата и не растягивалась нормально.

## Нумерация строк

Добавлено поле `RowNumber` в модель строки затрат `AdvanceExpenseLineRow`.

Нумерация пересчитывается каждый раз:

- при первичной настройке грида;
- после загрузки сохраненных строк;
- после добавления строки;
- после удаления строки.

Номер не хранится как бизнес-данные документа. Это отображаемый порядковый номер строки, который каждый раз начинается с `1`.

## Ввод даты

Колонка `Дата` переведена с календаря `DatePicker` на обычную текстовую колонку.

Теперь дата преимущественно вводится вручную. При выборе строки или добавлении новой строки фокус автоматически ставится в колонку `Дата`, чтобы пользователь мог сразу начать ввод.

## Пара счетов

Колонка `Пара счетов` убрана из грида строк затрат.

Пара счетов остается в шапке документа и продолжает использоваться для формирования проводок. То есть пользователь больше не выбирает пару счетов в каждой строке затрат, а строки содержат только данные самой затраты: дату, детали, счет расхода и сумму.

Сообщения проверки также скорректированы: если пара счетов не выбрана, ошибка теперь относится к шапке документа, а не к конкретной строке.

## Детали проводки

Колонка `Примечание` переименована в `Детали проводки`.

Это ручное поле: пользователь сам вводит текст детали проводки. Внутри модели оно по-прежнему сохраняется в свойство `Description`, чтобы не ломать существующее сохранение и загрузку ранее созданных документов.

## Сумма

Для грида задана культура `ru-RU`, а колонка `Сумма` использует числовой формат `N2`.

Это дает отображение суммы с разделением разрядов пробелом, например:

```text
12 345,67
```

То есть разряды больше не отделяются запятой.

## Проверка сборки

После изменений выполнена сборка:

```powershell
dotnet build .\BIS.ERP.sln
```

Сборка прошла успешно. Остался старый warning `CS1998` в тестовом UI-проекте, он не связан с этой правкой.
