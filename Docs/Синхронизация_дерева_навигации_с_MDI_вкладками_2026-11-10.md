# Дерево навигации следует за активной вкладкой MDI

**Дата:** 10.11.2026
**Версия сборки:** 1.1.897 (Build 897)
**Задача (как сформулировал пользователь):** «При выборе вкладки вверху, где располагаются вкладки MDI, указатель в левой части, где дерево, не перемещается на это окно. В закладках одно, в дереве другое.»
**Итог:** каждая вкладка MDI помнит узел дерева, из которого открыта; при переключении закладок левая панель выделяет этот узел (с раскрытием предков и прокруткой к нему). Кнопка/вкладка открывает документ как раньше — синхронизация односторонняя: **вкладка → дерево**, обратное направление работало и работает.

---

## 1. Что было не так

На скриншоте активна закладка **«Новый документ: Поступление ТМЗ»**, а в дереве подсвечен **«Расходный/Приходный КО»**:

| Где | Что показывалось |
|---|---|
| Закладки MDI | «Поступление ТМЗ», **«Новый документ: Поступление ТМЗ»** (активна), «Внутреннее перемещение ТМЗ», «Выбытие ТМЗ», «Расходный/Приходный КО» |
| Левое дерево | подсвечен «Расходный/Приходный КО» — последний узел, по которому щёлкнули мышью |

Причина — две независимые подсистемы, между которыми не было связи:

```
Views/MainWorkWindow.xaml            Views/Controls/MdiWorkspaceControl.xaml
┌───────────────────────────┐        ┌──────────────────────────────────────┐
│ NavigationTree (TreeView) │        │ DocumentsTabControl (TabControl)     │
│  SelectedItemChanged      │        │  SelectedItem ⇄ SelectedDocument     │
│        ↓                  │        │        (TwoWay-привязка)             │
│ OpenNavigationItemAsync   │        │  Documents (ObservableCollection)    │
│  → _navigation.NavigateTo │───────▶│  OpenDocument(key, title, content)   │
└───────────────────────────┘        └──────────────────────────────────────┘
        дерево знает только про свой последний клик,
        вкладки — только про свой SelectedDocument
```

`MdiWorkspaceControl` при смене активной закладки менял `SelectedDocument`, но никому об этом не сообщал. Дерево ничего не слышало и продолжало показывать узел, выбранный в прошлый раз.

## 2. Как сделано теперь

Три шага:

1. **Вкладка помнит узел.** У `MdiDocumentItem` появилось свойство `Tag`. Когда документ открывается из дерева, в метку кладётся тот `NavigationItem`. Диалоги (карточки документов, окна выбора) наследуют метку у вкладки, из которой их открыли, — поэтому «Новый документ: Поступление ТМЗ» указывает на «Поступление ТМЗ», а не на последний ручной клик.
2. **Рабочая область сообщает о смене вкладки.** У `MdiWorkspaceControl` появилось событие `SelectedDocumentChanged`, которое поднимается из сеттера `SelectedDocument` (щелчок по закладке, закрытие вкладки, «Закрыть все», `ActivateDocumentByKey`).
3. **Оболочка выделяет узел.** `MainWorkWindow` по событию ищет узел (метка → Id → ключ документа), раскрывает предков, ставит `TreeViewItem.IsSelected = true` и прокручивает к нему. Программное выделение поднимает `SelectedItemChanged`, поэтому на время выделения стоит флаг `_synchronizingNavigationSelection`: обработчик выбора не открывает документ второй раз.

### 4.1 Метка узла у вкладки

```csharp
public sealed class MdiDocumentItem
{

    {
        Key = key;
        Title = title;
        Content = content;
    }

    public string Key { get; }

    public string Title { get; }

    public UserControl Content { get; }

    /// <summary>
    /// Узел дерева навигации, из которого открыт документ. Тип — object, чтобы
    /// контрол рабочей области не зависел от типа оболочки (NavigationItem).
    /// По этой метке оболочка подсвечивает левую панель при смене закладки.
```

`object`, а не `NavigationItem`: `MdiWorkspaceControl` — переиспользуемый контрол и не должен знать про класс оболочки (он объявлен в `MainWorkWindow.xaml.cs`). Приведение делает тот, кто читает метку.

### 4.2 Событие смены активной вкладки

```csharp
    public MdiDocumentItem? SelectedDocument
    {
        get => _selectedDocument;
        set
        {
            if (ReferenceEquals(_selectedDocument, value))
                return;

            _selectedDocument = value;
            OnPropertyChanged();
            OnPropertyChanged(nameof(CurrentContent));
            SelectedDocumentChanged?.Invoke(this, value);
        }
    }

    /// <summary>
    /// Активная вкладка сменилась (щелчок по закладке, закрытие вкладки,
    /// «Закрыть все»). Оболочка по этому событию подсвечивает в дереве узел,
    /// из которого открыт документ.
    /// </summary>
    public event EventHandler<MdiDocumentItem?>? SelectedDocumentChanged;
```

Событие поднимается именно в сеттере, поэтому ловятся все пути смены закладки: клик по `TabItem` (TwoWay-привязка пишет в `SelectedDocument`), закрытие текущей/всех вкладок (`CloseDocument` выбирает соседнюю), `ActivateDocumentByKey` (возврат к вкладке-отправителю после закрытия окна выбора), перетаскивание закладок.

### 4.3 `OpenDocument` принимает метку

```csharp
    public MdiDocumentItem OpenDocument(string key, string title, UserControl content, bool activate = true, object? tag = null)
    {
        if (string.IsNullOrWhiteSpace(key))
            key = content.GetType().FullName ?? Guid.NewGuid().ToString("N");
        if (string.IsNullOrWhiteSpace(title))
            title = content.GetType().Name;

        var existing = Documents.FirstOrDefault(document =>
            string.Equals(document.Key, key, StringComparison.OrdinalIgnoreCase));

        if (existing != null)
        {
            // Документ могли открыть раньше без метки — уточняем её сейчас.
            if (tag != null && existing.Tag == null)
                existing.Tag = tag;

            if (activate)
                SelectedDocument = existing;
            return existing;
        }

        var item = new MdiDocumentItem(key, title, content)
        {
            Tag = tag
        };
        Documents.Add(item);
        if (activate)
            SelectedDocument = item;

        return item;
    }
```

Зачем ветка `existing != null`: документ с тем же ключом не открывается второй раз (`catalog:{id}`, `document:{id}`), и если он был создан до появления метки, её надо проставить. Существующую метку не перетираем — она уже указывает на конкретный узел.

### 4.4 `OpenWindow` наследует метку у открывающей вкладки

```csharp
        var actualKey = key;
        // Диалог открыт из уже открытой вкладки — наследует её узел дерева:
        // карточка «Новый документ: Поступление ТМЗ» подсвечивает «Поступление ТМЗ»,
        // а не лист, выбранный последним вручную.
        var inheritedTag = SelectedDocument?.Tag;
        var host = new MdiDialogHostControl(window, () => CloseDocumentByKey(actualKey), documentClosed, fillWorkspace);
        return OpenDocument(actualKey, title, host, activate, inheritedTag);
```

`OpenWindow` вызывается из `MdiDialogService` (`ShowInWorkspaceForResultAsync`, `TryShowInWorkspace`, `ShowInWorkspaceOrDialog`) — то есть все карточки документов и окна выбора, которые открываются закладками. `SelectedDocument` в этот момент — та вкладка, из которой пользователь нажал кнопку, поэтому «Новый документ: Поступление ТМЗ» получает метку списка «Поступление ТМЗ».

### 5.3 Обработчик и вспомогательные методы

Полный блок (вставлен перед `OnWindowClosing`):

```csharp
        // ================= Связь активной вкладки MDI и дерева =================

        /// <summary>
        /// Сменилась активная вкладка — подсвечиваем в дереве узел, из которого
        /// открыт документ. Сейчас вкладки и дерево жили раздельно: закладка
        /// на «Поступление ТМЗ», а в дереве остался «Расходный/Приходный КО».
        /// </summary>
        private void OnWorkspaceSelectedDocumentChanged(object? sender, MdiDocumentItem? document)
        {
            if (_synchronizingNavigationSelection)
                return;

            // Дерево могли пересобрать (смена прав, обновление метаданных): в метке
            // вкладки тогда лежит уже не существующий объект узла — ищем актуальный
            // узел по Id, а если метки нет — по ключу документа.
            var taggedItem = document?.Tag as NavigationItem;
            var item = !string.IsNullOrEmpty(taggedItem?.Id)
                ? FindNavigationItemById(NavigationItems, taggedItem!.Id)
                : null;

            item ??= FindNavigationItemByDocumentKey(document?.Key);
            if (item == null)
                return;

            SelectNavigationItem(item);
        }

        /// <summary>Выделяет узел дерева программно, без открытия документа.</summary>
        private void SelectNavigationItem(NavigationItem item)
        {
            if (ReferenceEquals(NavigationTree.SelectedItem, item))
                return;

            ExpandNavigationAncestors(item);
            if (TrySelectNavigationContainer(item))
                return;

            // Контейнеры дочерних узлов WPF создаёт лениво: после раскрытия предков
            // ждём генерации и повторяем выбор (тот же приём, что в поиске по дереву).
            Dispatcher.BeginInvoke(
                new Action(() => TrySelectNavigationContainer(item)),
                System.Windows.Threading.DispatcherPriority.Loaded);
        }

        private bool TrySelectNavigationContainer(NavigationItem item)
        {
            if (GetNavigationContainer(item) is not TreeViewItem container)
                return false;

            _synchronizingNavigationSelection = true;
            try
            {
                container.IsSelected = true;
                container.BringIntoView();
            }
            finally
            {
                _synchronizingNavigationSelection = false;
            }

            return true;
        }

        /// <summary>Повторяет подсветку после пересборки дерева (узлы — новые объекты).</summary>
        private void SyncNavigationWithActiveDocument() =>
            OnWorkspaceSelectedDocumentChanged(this, ContentArea.SelectedDocument);

        /// <summary>Раскрывает предков узла: без этого контейнер не создан и выделять нечего.</summary>
        private void ExpandNavigationAncestors(NavigationItem target)
        {
            foreach (var root in NavigationItems)
            {
                if (ExpandNavigationPath(root, target))
                    return;
            }
        }

        private static bool ExpandNavigationPath(NavigationItem node, NavigationItem target)
        {
            if (ReferenceEquals(node, target))
                return true;

            foreach (var child in node.Children)
            {
                if (!ExpandNavigationPath(child, target))
                    continue;

                node.IsExpanded = true;
                return true;
            }

            return false;
        }

        /// <summary>
        /// Запасной путь для вкладок, открытых не из дерева: ключ документа —
        /// «catalog:{id}», «document:{id}», «overview:{id}» или просто Id узла.
        /// </summary>
        private NavigationItem? FindNavigationItemByDocumentKey(string? key)
        {
            if (string.IsNullOrWhiteSpace(key))
                return null;

            var id = key;
            foreach (var prefix in new[] { "catalog:", "document:", "overview:" })
            {
                if (!id.StartsWith(prefix, StringComparison.OrdinalIgnoreCase))
                    continue;

                id = id[prefix.Length..];
                break;
            }

            return FindNavigationItemById(NavigationItems, id);
        }

        private static NavigationItem? FindNavigationItemById(IEnumerable<NavigationItem> items, string id)
        {
            if (string.IsNullOrEmpty(id))
                return null;

            foreach (var item in items)
            {
                if (string.Equals(item.Id, id, StringComparison.OrdinalIgnoreCase))
                    return item;

                if (FindNavigationItemById(item.Children, id) is NavigationItem found)
                    return found;
            }

            return null;
        }
```

Используются существующие методы оболочки: `GetNavigationContainer(NavigationItem)` (ищет `TreeViewItem` с обходом вложенных контейнеров) и `NavigationTree.SelectedItem`.

### 5.4 Запоминание узла при открытии из дерева

`OpenNavigationItemAsync` разделён на обёртку и прежний `switch`. Так метка ставится **в одном месте**, а не в шестнадцати вызовах `_navigation.NavigateTo(...)`:

```csharp
        private async Task OpenNavigationItemAsync(NavigationItem item)
        {
            var previousKey = ContentArea.SelectedDocument?.Key;
            await OpenNavigationItemCoreAsync(item);

            // Запоминаем, каким узлом дерева открыт документ: при переключении
            // закладок этот узел подсвечивается в левой панели.
            var activeDocument = ContentArea.SelectedDocument;
            if (activeDocument == null || activeDocument.Tag != null)
                return;
            if (string.Equals(activeDocument.Key, previousKey, StringComparison.OrdinalIgnoreCase))
                return;

            activeDocument.Tag = item;
        }

        private async Task OpenNavigationItemCoreAsync(NavigationItem item)
        {
            switch (item.Type)
            {
                // …прежний код без изменений…
            }
        }
```

Почему именно так:

- покрываются все ветки `switch` (справочники, документы, журналы, отчёты, закрытие периодов, системный журнал, права) — не нужно править каждый `NavigateTo`;
- ветки, которые вообще не открывают вкладку (`Profile`, `Settings`, `AboutSystem`, `SwitchMode`, `Logout`), ничего не портят: активная вкладка не сменилась — ключ тот же, метка не пишется;
- повторное открытие уже открытого документа (тот же ключ) метку не перезаписывает (`Tag != null`), поэтому вкладка продолжает указывать на свой исходный узел.

### 5.5 Защита от повторного открытия документа

Программное `IsSelected = true` поднимает `TreeView.SelectedItemChanged` — тот же обработчик, что и клик мышью. Без флага документ открывался бы повторно (создавался новый `CatalogDataView`/`DynamicDocumentWorkView`, заново читалась БД):

```csharp
            var item = e.NewValue as NavigationItem;
            if (item == null) return;

            // Узел выделен программно (синхронизация с активной вкладкой MDI) —
            // документ уже открыт, второй экземпляр не создаём.
            if (_synchronizingNavigationSelection) return;

            if (_isLoadingReport) return;
```

Флаг ставится и снимается строго вокруг установки `IsSelected` (`try/finally`): `SelectedItemChanged` в WPF поднимается синхронно внутри сеттера, поэтому подавление срабатывает и не «залипает».

### 5.6 Подсветка после перестроения дерева

Узлы дерева пересоздаются (`BuildNavigationTree` → `NavigationItems.Clear()` + новые объекты), поэтому метка вкладки после перестроения указывает на объект, которого в дереве уже нет. Обработчик это учитывает — ищет узел по `Id`. Дополнительно подсветка повторяется после построения дерева:

```csharp
                    initStage = "BuildNavigationTree (дерево навигации)";
                    await BuildNavigationTree();
                    // Дерево строится позже первых вкладок — подсвечиваем узел активной.
                    SyncNavigationWithActiveDocument();
```

```csharp
            // Перестраиваем дерево заново: сначала полное, затем фильтр по свежим правам.
            await BuildNavigationTree();
            SyncNavigationWithActiveDocument();
```

Второй вызов — в `RefreshNavigationAfterPermissionsChangedAsync` (смена прав пользователя пересобирает дерево).

## 6. Решения и почему именно так

| Решение | Причина |
|---|---|
| Метка хранится в `MdiDocumentItem`, а не в отдельном словаре «ключ → узел» | Метка едет вместе с вкладкой: переживает перестановку закладок, закрытие соседних, `ActivateDocumentByKey`. Словарь пришлось бы чистить при каждом закрытии. |
| `object? Tag`, а не `NavigationItem` | `MdiWorkspaceControl` — универсальный контрол; тип оболочки объявлен в другом файле и не должен протекать в него. |
| Диалоги наследуют метку у открывающей вкладки | Карточки документов и окна выбора открываются «из» рабочей формы. Наследование даёт ожидаемое: «Новый документ: Поступление ТМЗ» подсвечивает «Поступление ТМЗ». |
| Метка ставится в обёртке `OpenNavigationItemAsync`, а не в каждом `NavigateTo` | Одна точка вместо 16 вызовов; работает и для веток, где документ открывается не напрямую (`OpenAccountingReportsAsync`, `OpenPeriodClosingAsync`, обзор раздела). |
| Три уровня поиска узла: метка → `Id` → ключ документа | Метка покрывает обычный путь; `Id` — после пересборки дерева (метка «протухла»); ключ — для вкладок, открытых в обход дерева (`TryOpenDocumentInWorkspace`, восстановление). |
| Флаг `_synchronizingNavigationSelection` | Иначе программное выделение запускает повторное открытие документа (дорого: новый view + запросы к БД). |
| Повтор выбора через `DispatcherPriority.Loaded` | Дочерние `TreeViewItem` создаются лениво; после `IsExpanded = true` контейнера ещё нет. Тот же приём уже используется в поиске по дереву (`SelectNavigationMatchContainer`). |
| `BringIntoView()` | Узел может быть за пределами видимой части — подсветка должна быть видна, а не «где-то ниже». |
| Синхронизация только в одну сторону (вкладка → дерево) | Обратное направление (клик по узлу открывает/активирует документ) уже работало; менять его не требовалось. |

### 8.2 Ручные сценарии

1. Открыть в дереве «Расходный/Приходный КО», затем «Поступление ТМЗ».
2. В «Поступлении ТМЗ» нажать «Добавить» — откроется вкладка «Новый документ: Поступление ТМЗ», в дереве останется подсвеченным «Поступление ТМЗ».
3. Переключиться на закладку «Расходный/Приходный КО» → в дереве подсветится «Расходный/Приходный КО» и родительские группы раскроются.
4. Вернуться на «Новый документ: Поступление ТМЗ» → подсветка вернётся на «Поступление ТМЗ» (это и есть кейс со скриншота: раньше дерево оставалось на «Расходный/Приходный КО»).
5. Закрыть активную вкладку (`x` или Esc) → подсветка уйдёт на узел вкладки, которая стала активной.
6. «Закрыть все» → дерево остаётся на последнем узле (активных вкладок нет — синхронизировать нечего).
7. Переключить пользователя/права так, чтобы дерево перестроилось, затем переключить закладку — подсветка находится по `Id` и работает на новых объектах узлов.

Ожидаемо: подсветка всегда совпадает с активной закладкой; повторных открытий документов при переключении закладок нет (вкладки не множатся, данные не перезагружаются).

## 9. Ограничения

| Ситуация | Поведение |
|---|---|
| Вкладка без узла (окна выбора `ReferenceSelectionDialog`, `ShowControlInWorkspaceForResultAsync`, отчёты, окна без ключа вида `Тип:Guid`) | Подсветка не меняется — остаётся на узле-родителе. Это ожидаемо: окно выбора открыто «из» этой формы. |
| Узел скрыт фильтром быстрого поиска по дереву | Программное выделение не сработает (контейнера нет). После очистки поиска подсветка вернётся при следующем переключении закладки. |
| Документ открыт программно в обход дерева и без ключа `catalog:/document:/overview:` | Узел не определяется — дерево не меняется. |
| Смена прав пересобрала дерево | Метка вкладки указывает на старый объект, поэтому узел ищется по `Id`; после `SyncNavigationWithActiveDocument()` подсветка восстанавливается. |
