# Касса: кассовая книга, печатные формы и проведение документов

**Дата:** 1 ноября 2026 г.  
**Сборка, в которой описываемые изменения скомпилированы:** `1.1.853`  
**Основное окно:** `Views/CashOrderWorkView.xaml` и `Views/CashOrderWorkView.xaml.cs`

## 1. Назначение документа

Этот документ описывает сделанные изменения в окне единого журнала приходных и расходных кассовых ордеров (ПКО/РКО): размещение команд, массовую отметку и проведение, кассовые отчеты, ClosedXML-макет кассовой книги и выбор PDF/Excel. Приведены реальные выдержки из исходников проекта на дату сборки. Фрагменты сокращены до относящейся к теме логики.

Документ фиксирует реализацию, а не задает требования к будущим изменениям. UX-предложения, составленные до реализации, находятся отдельно в `DOCS/UX_REVIEW_CASH_ORDER_WORK_VIEW.md`.

## 2. Кратко: что сделано

- Команда «Проводки по кассе» оставлена в панели периода и кассы и не отключается только из-за пустого списка касс.
- Основные действия ПКО/РКО собраны в блоке «Документы».
- Кнопка проведения/отмены проведения удалена из панели. Правый клик по строке документа открывает команды редактирования, печатной формы, проведения/отмены проведения и удаления.
- Для даты внутри закрытого периода команды изменения и удаления неактивны. Любая дата после последнего закрытия считается открытой; редактирование и удаление доступны также для проведенного документа.
- Отдельная кнопка «Провести выбранные» удалена. Массовые команды доступны из контекстного меню заголовка колонки «Выбор».
- Выбор документа для изменения проведения доступен, когда его кассовый день открыт, независимо от текущего статуса. Для проведенного документа доступно снятие проведения.
- Выбор кассового отчета выполняется из выпадающего списка в блоке документов.
- Флажок «Печатные формы» задает сценарий отчета: без флажка открывается PDF-предпросмотр, с флажком сначала показывается диалог варианта и формата.
- В PDF-предпросмотре кассовых отчетов и печатных форм ПКО/РКО доступна кнопка «Открыть в Excel».
- Для кассового журнала формируется табличный набор данных с остатками на начало и конец, строками ордеров, итогами и количеством документов.
- Макет кассовой книги и реестра задан в ClosedXML layout factory и сохраняется в конфигурации отчетов. Сами данные не подменяются статичным примером.
- Отчеты кассового окна помечены `ShowInAccountingReports: false`, чтобы не показывать их в общем окне бухгалтерской отчетности.
- «Кассовая книга» и «Реестр приходов / расходов» скрыты из дерева элементов по типу отчета, но доступны в списке отчетов окна ПКО/РКО.
- Чекбокс массового выбора перенесен непосредственно в заголовок колонки «Выбор» таблицы.
- Контекстное меню заголовка колонки содержит команды «Провести все доступные», «Провести выбранные» и «Снять проведение выбранных».
- Дополнительная таблица проводок и сводка оборотов находятся в нижних блоках окна.

## 3. Структура окна

Разметка находится в `Views/CashOrderWorkView.xaml`.

### 3.1. Верхние группы

Окно разделено на рабочие группы:

1. **Период и касса** — начальная/конечная даты, обновление, фильтр кассы, переход к проводкам.
2. **Документы** — создание ПКО/РКО, список отчетов и флажок печатных форм. Редактирование, печать, проведение и удаление выбранной строки вызываются правой кнопкой мыши. Массовое изменение статуса находится в контекстном меню заголовка колонки.
3. **Работа с кассовым днем** — дата, открытие/закрытие дня, обороты за день и по закрытым дням.
4. **Таблица документов** — отфильтрованные кассовые ордера.
5. **Обороты** и **Дополнительная информация о проводке** — нижние сводные/детальные панели.

Фрагмент размещения списка отчетов после команд документов:

```xml
<TextBlock Text="Отчеты:" FontWeight="Bold" />
<ComboBox x:Name="CashReportCombo"
          DisplayMemberPath="Name"
          SelectionChanged="OnCashReportSelectionChanged" />
<CheckBox x:Name="PrintFormsCheckBox"
          Content="Печатные формы" />
```

### 3.2. Проводки и отображение сведений

Команда «Проводки по кассе» находится рядом с фильтром кассы. Ее состояние теперь не зависит от условия «касс больше одной»:

```csharp
CashPostingsButton.IsEnabled = _cashDeskFilterItems.Count > 0;
```

Таблица «Дополнительная информация о проводке» не удалялась: ее `PostingDetailsGrid` остается в нижней части окна и заполняется при выборе строки документа. Двойной щелчок по документу продолжает открывать карточку проводки (`PostingDetailsDialog`), если проводка существует, либо показывает сформированные сведения для непроведенного документа.

## 3.3. Контекстное меню кассового документа

Правый клик по строке сначала выделяет эту строку. Контекстное меню содержит команды редактирования и печати, затем разделитель, команду изменения статуса проведения, еще один разделитель и удаление:

```xml
<DataGrid.ContextMenu>
    <ContextMenu Opened="OnCashOrderContextMenuOpened">
        <MenuItem Header="Изменить" Tag="Edit" Click="OnEditClick" />
        <MenuItem Header="Печатная форма" Tag="Print" Click="OnPrintClick" />
        <Separator />
        <MenuItem Header="Провести" Tag="PostingState" Click="OnPostClick" />
        <Separator />
        <MenuItem Header="Удалить" Tag="Delete" Click="OnDeleteClick" />
    </ContextMenu>
</DataGrid.ContextMenu>
```

Чтобы контекстное меню всегда относилось к строке, на которой был правый клик, обработчик мыши выделяет эту строку до открытия меню:

```csharp
private void DataGrid_PreviewMouseRightButtonDown(object sender, MouseButtonEventArgs e)
{
    if (e.OriginalSource is not DependencyObject source)
        return;

    var row = FindVisualParent<DataGridRow>(source);
    if (row == null)
        return;

    row.IsSelected = true;
    DataGrid.SelectedItem = row.Item;
    DataGrid.Focus();
}
```

При открытии меню текст команды статуса зависит от `IsPosted`. Редактирование, удаление и смена статуса включаются, если дата документа позже последней закрытой даты либо закрытий пока нет. Это правило проверяется повторно по БД при каждом открытии меню, чтобы избежать серого меню из-за устаревшего `CashDayStatusDisplay`. Проведенный статус не отключает редактирование/удаление в открытом периоде. Печатная форма доступна для любой выбранной строки:

```csharp
private async void OnCashOrderContextMenuOpened(object sender, RoutedEventArgs e)
{
    if (sender is not ContextMenu menu)
        return;

    var row = DataGrid.SelectedItem as CashOrderRow;
    var canChangeForOpenDay = row != null && await IsCashDayOpenForDocumentAsync(row);
    foreach (var item in menu.Items.OfType<MenuItem>())
    {
        switch (item.Tag as string)
        {
            case "Edit":
                item.IsEnabled = canChangeForOpenDay;
                break;
            case "Print":
                item.IsEnabled = row != null;
                break;
            case "PostingState":
                item.Header = row?.IsPosted == true ? "Отменить проведение" : "Провести";
                item.IsEnabled = canChangeForOpenDay;
                break;
            case "Delete":
                item.IsEnabled = canChangeForOpenDay;
                break;
        }
    }
}
```

Проверка свежего состояния дня сверяется с кассой, датой документа и последней закрытой датой. Наличие отдельной записи открытия не ограничивает период:

```csharp
private async Task<bool> IsCashDayOpenForDocumentAsync(CashOrderRow row)
{
    if (!Guid.TryParse(row.CashDeskId, out var cashDeskId) || cashDeskId == Guid.Empty)
        return false;

    using var context = await ServiceLocator.InfoBaseManager.GetCurrentDbContextAsync();
    var cashDayService = new CashDayClosureService(context);
    var lastClosedDate = await cashDayService.GetLastClosedDayDateAsync(cashDeskId);
    if (lastClosedDate.HasValue && row.DocDate.Date <= lastClosedDate.Value.Date)
        return false;

    return !lastClosedDate.HasValue || row.DocDate.Date > lastClosedDate.Value.Date;
}
```

Кнопка проведения больше не показывается в верхнем ряду. Действие строки вызывает обработчик переключения статуса, который использует штатную проверку кассового дня и `PostDocumentAsync`/`UnpostDocumentAsync`. Отмена проведения запрашивает подтверждение с реквизитами документа:

```csharp
var actionText = selectedRow.IsPosted
    ? $"Отменить проведение этого документа?{Environment.NewLine}{Environment.NewLine}" +
      $"Тип: {selectedRow.OrderTypeDisplay}{Environment.NewLine}" +
      $"Дата: {selectedRow.DocDate:dd.MM.yyyy}{Environment.NewLine}" +
      $"Номер: {selectedRow.DocNumber}{Environment.NewLine}" +
      $"Дебет: {selectedRow.DebitAccount}{Environment.NewLine}" +
      $"Кредит: {selectedRow.CreditAccount}{Environment.NewLine}" +
      $"Сумма: {selectedRow.Amount:N2} {selectedRow.CurrencyName}"
    : $"Провести выбранный документ?{Environment.NewLine}{Environment.NewLine}" +
      $"Тип: {selectedRow.OrderTypeDisplay}{Environment.NewLine}" +
      $"Дата: {selectedRow.DocDate:dd.MM.yyyy}{Environment.NewLine}" +
      $"Номер: {selectedRow.DocNumber}{Environment.NewLine}" +
      $"Дебет: {selectedRow.DebitAccount}{Environment.NewLine}" +
      $"Кредит: {selectedRow.CreditAccount}{Environment.NewLine}" +
      $"Сумма: {selectedRow.Amount:N2} {selectedRow.CurrencyName}";
```

Редактирование открывает `CashOrderDialog` в режиме изменения (конструктор без `isReadOnly: true`). Для проведенного документа форма сохраняет признак проведения и перепроводит его, чтобы проводки соответствовали измененным данным. Удаление в открытый день доступно также для проведенного документа; `DeleteDynamicRecordAsync` удаляет связанные проводки перед удалением самого документа. В закрытый день эти действия отключены.

## 4. Выбор всех документов в колонке «Выбор»

Чекбокс перенесен из общей полосы кнопок в заголовок первого столбца DataGrid. Строка документа доступна для выбора, если кассовый день открыт. Проведенный документ можно выбрать для отмены проведения; непроведенный — для проведения. В закрытом или неоткрытом дне менять статус нельзя.

```xml
<DataGridTemplateColumn Width="85"
                        IsReadOnly="False"
                        CanUserSort="False">
    <DataGridTemplateColumn.Header>
        <CheckBox x:Name="SelectAllBatchPostCheckBox"
                  Content="Выбор"
                  Click="OnSelectAllBatchPostClick">
            <CheckBox.ContextMenu>
                <ContextMenu>
                    <MenuItem Header="Провести все доступные"
                              Click="OnPostAllFromSelectionHeaderClick" />
                    <MenuItem Header="Провести выбранные"
                              Click="OnPostSelectedFromSelectionHeaderClick" />
                    <MenuItem Header="Снять проведение выбранных"
                              Click="OnUnpostSelectedFromSelectionHeaderClick" />
                </ContextMenu>
            </CheckBox.ContextMenu>
        </CheckBox>
    </DataGridTemplateColumn.Header>
    <!-- Чекбокс строки связан с CashOrderRow.IsSelectedForBatchPost. -->
</DataGridTemplateColumn>
```

Чекбокс заголовка отмечает все документы текущего фильтра, у которых открыт кассовый день. `CanChangePosting` не зависит от `IsPosted`, что позволяет выбрать проведенный документ для отмены проведения:

```csharp
private void OnSelectAllBatchPostClick(object sender, RoutedEventArgs e)
{
    var shouldSelect = SelectAllBatchPostCheckBox.IsChecked == true;
    foreach (var row in GetCurrentFilteredRows())
        row.IsSelectedForBatchPost = shouldSelect && row.CanChangePosting;

    DataGrid.Items.Refresh();
    UpdateButtonsState();
}
```

«Провести все доступные» выбирает непроведенные документы открытого кассового дня. «Провести выбранные» обрабатывает отмеченные непроведенные строки, а «Снять проведение выбранных» — отмеченные проведенные документы.

```csharp
private async void OnPostAllFromSelectionHeaderClick(object sender, RoutedEventArgs e)
{
    foreach (var row in GetCurrentFilteredRows())
        row.IsSelectedForBatchPost = !row.IsPosted && row.CanChangePosting;

    DataGrid.Items.Refresh();
    UpdateButtonsState();
    await ChangeSelectedPostingStateAsync(posted: false);
}
```

Команды массового изменения используют один обработчик и различаются целевым статусом. `posted: false` вызывает `PostDocumentAsync`, `posted: true` — `UnpostDocumentAsync`. Перед изменением каждого документа проверяется кассовый день. Перед проведением дополнительно проверяется корреспондирующий счет. После обработки список перечитывается.

```csharp
public bool CanChangePosting => IsCashDayOpen;
```

Проведение/отмена проведения одного выбранного документа доступно через пункт контекстного меню строки; его подпись меняется между «Провести» и «Отменить проведение». Кнопки проведения в верхнем ряду нет. Массовое проведение и снятие проведения отмеченных строк выполняются из контекстного меню заголовка «Выбор».

## 5. Список отчетов и печатные формы

### 5.1. Формирование списка

Список загружается при открытии окна после загрузки документов. Перед чтением вызывается `EnsureCashOrderReportsAsync()`, который обеспечивает наличие стандартных кассовых определений/макетов. В ComboBox попадают активные записи, помеченные не как отдельные печатные формы и имеющие тип кассовой книги или реестра. Отдельный пункт открывает печатную форму выбранного документа.

```csharp
var choices = await context.Reports
    .AsNoTracking()
    .Where(report => report.IsActive && !report.IsPrintForm &&
        (report.ReportType == "CashBook" ||
         report.ReportType == "CashReceiptExpenseRegister"))
    .OrderBy(report => report.Order)
    .ThenBy(report => report.Name)
    .Select(report => new CashReportChoice
    {
        Name = report.Name,
        Code = report.Code,
        ReportType = report.ReportType
    })
    .ToListAsync();
```

`Code` и `ReportType` берутся из объекта конфигурации `Report`; имя в меню также берется из конфигурации. Технические типы `CashBook` и `CashReceiptExpenseRegister` связывают соответствующий вариант отчета с подготовкой специфического набора данных.

### 5.2. Поведение флажка

Обработчик выбора сбрасывает выделение ComboBox, определяет, включен ли `PrintFormsCheckBox`, и направляет выбор к построителю соответствующего отчета.

```csharp
var choosePrintForm = PrintFormsCheckBox.IsChecked == true;

if (choice.ReportType == "CashBook")
    await OpenCashBookReportAsync(choice.Code, choosePrintForm);
else if (choice.ReportType == "CashReceiptExpenseRegister")
    await OpenReceiptExpenseRegisterReportAsync(choice.Code, choosePrintForm);
```

При выключенном флажке в качестве формы берется выбранный отчет, формат устанавливается в PDF и открывается встроенный предпросмотр. При включенном флажке открывается `PrintFormSelectionDialog` только со списком активных отчетов того же `ReportType`; пользователь выбирает вариант, затем нажимает Excel или PDF в самом диалоге.

```csharp
Report selectedReport = report;
var selectedFormat = PrintFormOutputFormat.Pdf;

if (choosePrintForm)
{
    var selectionDialog = new PrintFormSelectionDialog(reportVariants)
    {
        Owner = Window.GetWindow(this)
    };

    if (selectionDialog.ShowDialog() != true ||
        selectionDialog.SelectedReport == null)
        return;

    selectedReport = selectionDialog.SelectedReport;
    selectedFormat = selectionDialog.SelectedFormat;
}
```

Таким образом, набор альтернатив ограничен выбранным отчетом по его типу, а не объединяется со всеми формами приложения. Если пользователь отменяет диалог, генерация прекращается.

### 5.3. PDF-предпросмотр и Excel

Для PDF вызывается генерация preview-байтов по ClosedXML макету и открывается `PdfPreviewWindow`. В окно передается callback экспорта в Excel для того же набора данных и той же выбранной формы:

```csharp
var previewWindow = new PdfPreviewWindow(output, selectedReport.Name, async () =>
{
    var excel = await Task.Run(() =>
        printFormService.ExportReportTemplateExcel(
            dataSnapshot.Copy(), selectedReport));

    await PrintFormOutputFileService.SaveAndOpenAsync(
        excel, selectedReport.Name, PrintFormOutputFormat.Excel);
});
```

`PdfPreviewWindow` принимает необязательный callback. Для PDF-предпросмотра кассовых отчетов и печатных форм ПКО/РКО callback передается всегда, поэтому появляется кнопка «Открыть в Excel». При нажатии окно блокирует повторный запуск на время экспорта и сообщает об ошибке в диалоге. Ширина окна увеличена, нижняя панель переведена на Grid с отдельными колонками статуса и кнопок; сообщение статуса больше не может наехать на группу кнопок.

```csharp
public PdfPreviewWindow(
    byte[] pdfData,
    string? documentName = null,
    Func<Task>? openExcelAsync = null)
{
    InitializeComponent();
    _pdfData = pdfData ?? Array.Empty<byte>();
    _openExcelAsync = openExcelAsync;
    OpenExcelButton.Visibility = openExcelAsync == null
        ? Visibility.Collapsed
        : Visibility.Visible;
    // Настройка заголовка и загрузки просмотра PDF.
}
```

Печатная форма выбранного ПКО/РКО использует `GetCashOrderPrintFormsAsync` с метаданными документа и признаком прихода/расхода. При включенном «Печатные формы» диалог предлагает варианты этого документа и Excel/PDF. Команда контекстного меню «Печатная форма» формирует PDF и открывает `PdfPreviewWindow`, откуда доступен экспорт той же формы в Excel:

```csharp
private async void OnPrintClick(object sender, RoutedEventArgs e) =>
    await PrintCashOrderFormAsync(toExcel: false, preview: true);
```

Внутри генератора при `preview == true` байты PDF передаются окну просмотра, а не `SaveAndOpenAsync` и ассоциированному браузеру:

```csharp
var pdfBytes = await printFormService.ExportDocumentAsync(report, selectedRow.Id);
if (preview)
{
    var previewWindow = new PdfPreviewWindow(pdfBytes, report.Name, async () =>
    {
        var excel = await printFormService.ExportDocumentExcelAsync(report, selectedRow.Id);
        await PrintFormOutputFileService.SaveAndOpenAsync(
            excel, report.Name, PrintFormOutputFormat.Excel);
    })
    {
        Owner = Window.GetWindow(this)
    };
    previewWindow.ShowDialog();
    return;
}
```

## 6. Данные кассовой книги

### 6.1. Граница закрытого и открытого периода

Закрытие привязано к сохраненной дате закрытия по конкретной кассе. Для статуса документа используется последняя закрытая дата этой кассы (`MAX(CloseDate)`): документ с датой не позже нее относится к закрытому периоду; любой документ позже нее относится к открытому периоду. Если закрытий еще нет, документы считаются открытыми. Открытый период может охватывать произвольное число дней — отдельная запись `IsClosed = false` нужна для регистрации открытия, но не ограничивает период одним календарным днем.

```csharp
var lastClosedDate = await cashDayService.GetLastClosedDayDateAsync(cashDeskId);
foreach (var row in rowList)
{
    row.IsCashDayClosed = lastClosedDate.HasValue &&
                          row.DocDate.Date <= lastClosedDate.Value.Date;
    row.IsCashDayOpen = !row.IsCashDayClosed;
}
```

Такое же правило используется при открытии контекстного меню и перед редактированием, удалением или изменением проведения. Закрытие можно выполнить без предварительной записи открытия: в таком случае `CloseDayAsync` создает закрытие сразу с итоговыми остатками. Если запись открытия есть, она обновляется методом `CloseOpenDayAsync`.

### 6.2. Перенос остатков между закрытиями

Начало текущего открытого периода берется со дня, следующего за последней закрытой датой. Если закрытий нет, начало периода — первая дата кассового документа (или дата расчета, если документов пока нет). Входящее сальдо рассчитывается по всем проводкам счета кассы до начала периода; обороты суммируются внутри периода; конечное сальдо получается по формуле:

```csharp
var openingNet = openingDebit - openingCredit;
var closingNet = openingNet + debitTurnover - creditTurnover;
```

Значит, закрывающий остаток предыдущего периода переносится в начальный остаток следующего через накопленные проводки до `startDate`. Если до первого периода остатка и проводок нет, начальное сальдо равно нулю, далее накапливаются дебетовый и кредитовый обороты. При закрытии вычисленные начальные/конечные остатки и обороты сохраняются в `CashDayClosures` вместе с датой закрытия.

Построитель `BuildCashBookReportDataTable` принимает строки текущего фильтра, период, выбранную кассу и сводку оборотов. Ордеры сортируются по дате, затем по числовой части номера, если она распознается, и после по тексту номера.

Используются поля данных:

| Поле | Содержимое |
|---|---|
| `book_date` | Дата документа |
| `book_document` | Номер ПКО/РКО |
| `book_description` | От кого получено или кому выдано: контрагент/сотрудник и основание |
| `book_correspondent` | Код корреспондирующего счета |
| `book_income` | Сумма ПКО; для остальных строк пусто |
| `book_expense` | Сумма РКО; для остальных строк пусто |
| `period_title` | Заголовок с датами периода |
| `cash_desk_title` | Наименование кассы |
| `generated_at` | Дата подготовки |
| `receipt_count` / `payment_count` | Число приходных и расходных документов за период |

Для книги создаются отдельные строки «ОСТАТОК НА НАЧАЛО», каждый кассовый ордер, «ИТОГО» и «ОСТАТОК НА КОНЕЦ»:

```csharp
var incomeTotal = receipts.Sum(row => row.Amount);
var expenseTotal = payments.Sum(row => row.Amount);
var openingBalance = turnoverSummary.OpeningDebit - turnoverSummary.OpeningCredit;
var closingBalance = turnoverSummary.ClosingDebit - turnoverSummary.ClosingCredit;

AddRow(string.Empty, string.Empty, "ОСТАТОК НА НАЧАЛО", string.Empty,
    openingBalance >= 0 ? openingBalance : string.Empty, "X");

foreach (var row in orders)
    AddRow(
        row.DocDate.ToString("dd.MM.yyyy", CultureInfo.InvariantCulture),
        row.DocNumber,
        BuildCashBookText(row),
        ExtractAccountCode(ResolveCorrespondentAccount(row)),
        row.IsReceipt ? row.Amount : null,
        row.IsReceipt ? null : row.Amount);

AddRow(string.Empty, string.Empty, "ИТОГО", string.Empty,
    incomeTotal, expenseTotal);
AddRow(string.Empty, string.Empty, "ОСТАТОК НА КОНЕЦ", string.Empty,
    closingBalance >= 0 ? closingBalance : string.Empty, "X");
```

Значения начального и конечного остатка рассчитываются на основе `CashTurnoverSummary`, полученной для выбранного периода/кассы. Это не сумма строк текущего экрана: при изменении источника оборотов изменится и остаток в книге.

## 7. ClosedXML-макет книги

Шаблон определяется в `Services/ClosedXmlLayoutTemplates.cs`, метод `CreateCashBook`. Он задает страницу альбомной ориентации, шрифт Times New Roman, отсутствие сетки листа, шапку, таблицу из шести колонок и блок подписей.

Ключевая схема таблицы:

```csharp
Columns =
{
    new ClosedXmlColumn { Field = "book_date", Header = "Дата", Width = 13, Align = "Center" },
    new ClosedXmlColumn { Field = "book_document", Header = "Документ", Width = 12, Align = "Center" },
    new ClosedXmlColumn { Field = "book_description", Header = "От кого получено или кому выдано", Width = 42 },
    new ClosedXmlColumn { Field = "book_correspondent", Header = "Корр. счет", Width = 16, Align = "Center" },
    new ClosedXmlColumn { Field = "book_income", Header = "Приход", Width = 16, NumberFormat = "#,##0.00", Align = "Right" },
    new ClosedXmlColumn { Field = "book_expense", Header = "Расход", Width = 16, NumberFormat = "#,##0.00", Align = "Right" }
}
```

Остатки и итог визуально акцентируются правилами `EmphasisRules`. После таблицы добавляются строки для кассира, количества проверенных приходных/расходных документов и бухгалтера. В заголовке листа печатаются название периода и касса.

Сходство с приложенным образцом кассовой книги реализуется структурой листа, названиями колонок, строками остатков/итога, подписью кассира/бухгалтера и правилами печати. Фактические данные и названия организации/кассы берутся из текущей конфигурации и журнала; даты в примере не зашиты.

## 8. Конфигурация отчетов и бухгалтерская отчетность

Стандартные определения кассовой книги и реестра находятся в `Services/MetadataService.Reports.cs`. Для обоих используется `SourceFormat: "ClosedXml"`, стартовый макет создается флагом `SeedClosedXmlLayout: true`, а поле `ShowInAccountingReports` выключено:

```csharp
new StandardReportDefinition(

    Name: "Кассовая книга",
    ReportType: "CashBook",
    SourceFormat: "ClosedXml",
```

```csharp
new StandardReportDefinition(

    Name: "Реестр приходов / расходов",
```

`ShowInAccountingReports` — конфигурационный флаг модели `Report`, которым определяется, показывать ли отчет в бухгалтерской отчетности. Для этих двух кассовых отчетов он изначально выключен; их точка входа — окно ПКО/РКО.

## 9. Состав полей реестра

`BuildReceiptExpenseRegisterReportDataTable` формирует набор колонок для реестра ПКО/РКО. Помимо основных дат, номера, типа документа, основания, счета и суммы он включает общие значения кассы/периода, валюты, дебета/кредита, остатков и оборотов. Метод `FillCashReportCommonValues` присваивает значения по алиасам для совместимости с полями настраиваемых макетов.

Это важно для старых и альтернативных форм: макет может ссылаться на `sum`, `amount`, `debit_amount`, `sum_debet` и другие поля, а подготовитель данных обеспечивает их заполнение там, где они соответствуют одной и той же величине. Конкретный состав и видимый набор колонок определяет выбранный `ClosedXmlLayout`.

### Название банковских операций в дереве навигации

Узел документа «Платежное поручение» в дереве показывается как «Банковские операции», совпадая с уже существующим названием рабочего окна. Переименовано только отображаемое имя навигационного узла. Системное имя объекта метаданных по-прежнему «Платежное поручение»: по нему выбирается тип `PaymentOrder`, а `Id` и `Tag` содержат исходный объект. Поэтому обработчик перехода продолжает создавать `PaymentOrderWorkView` без изменения схемы, отчетов и документов.

В `Views/MainWorkWindow.xaml.cs`, метод `CreateDocumentNavigationItem`, подпись выбирается по типу рабочего раздела:

```csharp
var type = document.Name switch
{
    "Расходный/Приходный КО" => "CashOrder",
    "Платежное поручение" => "PaymentOrder",
    "Авансовый отчет" or "Авансовые платежи" or "Платежная ведомость" => "FinanceDocument",
    "Проводки" => "PostingsDocument",
    InvoiceDocumentTypes.SalesIssue or InvoiceDocumentTypes.PurchaseRegistration => "InvoiceDocument",
    _ => "DynamicDocument"
};

return new NavigationItem
{
    Id = document.Id.ToString(),
    Name = type switch
    {
        "CashOrder" => CashOrderWorkView.SectionTitle,
        "PaymentOrder" => PaymentOrderWorkView.SectionTitle,
        _ => document.Name
    },
    Icon = document.Icon,
    Type = type,
    Tag = document,
    Order = document.Order
};
```

Значение подписи уже централизовано в `PaymentOrderWorkView.SectionTitle` (`"Банковские операции"`), поэтому строка не дублируется в построителе дерева. В альтернативном построителе дерева разделов узел также использует это свойство. Обработчик открытия маршрутизирует его по `Type` и объекту `Tag`:

```csharp
case "PaymentOrder":
    if (item.Tag is MetadataObject paymentDocument)
    {
        var paymentView = new PaymentOrderWorkView(paymentDocument, _metadataService);
        _navigation.NavigateTo(paymentView, item.Name, $"document:{item.Id}");
    }
    break;
```
### Кассовые отчеты скрыты из дерева элементов

Кассовая книга и реестр приходов/расходов не отображаются в дереве элементов (в группах отчетов и общем разделе отчетов). Это ограничение только навигации: `CashOrderWorkView` по-прежнему загружает их по типам `CashBook` и `CashReceiptExpenseRegister`, поэтому команды отчетов в окне ПКО/РКО сохраняются. Фильтр сравнивает тип отчета из конфигурации, а не его отображаемое название.

В `Views/MainWorkWindow.xaml.cs` оба построителя дерева используют общий `IsReportAvailableForNavigation`. Он исключает эти типы наравне с недоступными legacy-отчетами:

```csharp
private static bool IsReportAvailableForNavigation(Report report) =>
    report != null &&
    !IsFrxLayoutReport(report) &&
    !IsCashOrderReport(report);

private static bool IsCashOrderReport(Report report) =>
    string.Equals(report.ReportType, "CashBook", StringComparison.OrdinalIgnoreCase) ||
    string.Equals(report.ReportType, "CashReceiptExpenseRegister", StringComparison.OrdinalIgnoreCase);
```

Список отчетов ПКО/РКО загружается отдельно и не вызывает этот фильтр:

```csharp
.Where(report => report.IsActive && !report.IsPrintForm &&
                 (report.ReportType == "CashBook" ||
                  report.ReportType == "CashReceiptExpenseRegister"))
```
## 11. Наблюдавшаяся ошибка «отчет не загружен» и обработка макета без элементов

В журнале фиксировалось сообщение вида:

> Отчет «Реестр приходов / расходов» не загружен в конфигурации.

В текущем окне перед запросом отчета вызывается `EnsureCashOrderReportsAsync()`, после чего отчет ищется по коду конфигурации. Отсутствующий отчет приводит к явному `InvalidOperationException` с именем отчета; неактивный отчет также отклоняется до экспорта. Загрузка вариантов ограничена тем же `ReportType`.

Ранее также возникало исключение при экспорте шаблона, если `Template.Elements.Count == 0`. Для кассовых отчетов предусмотрен ClosedXML layout, который содержит `Sheets` и `Blocks`; это отдельная структура визуального макета. Она создается через `ClosedXmlLayoutTemplates.CreateForReport(report)` и seeded в конфигурацию. Не следует путать пустые элементы legacy-шаблона печатной формы с пустой разметкой `ClosedXmlLayout`.

Если пользователь добавит новую форму, для корректного отображения в диалоге она должна быть активной, иметь тот же `ReportType`, что отчет-источник, и быть помечена как печатная форма в конфигурации, если эта классификация применяется к ней. Для экспорта ее `ClosedXmlLayout` должен содержать лист и блоки/колонки, совместимые с набором данных данного типа.

## 12. Последовательности действий

### Обычный отчет в PDF с возможностью открыть Excel

1. Пользователь выбирает кассу и период.
2. Выбирает «Кассовая книга» либо «Реестр приходов / расходов» в списке.
3. При снятом флажке «Печатные формы» подготавливаются строки журнала и сводка оборотов.
4. Выбирается конфигурационный отчет, строится PDF по ClosedXML макету.
5. PDF показывается в окне предпросмотра. Кнопка Excel повторно вызывает экспорт для того же набора данных/макета и открывает сохраненный файл.

### Выбор альтернативного варианта

1. Пользователь включает «Печатные формы».
2. Выбирает отчет.
3. Открывается окно со списком активных форм этого типа и действиями Excel/PDF.
4. Для Excel формируется XLSX, для PDF открывается окно предпросмотра.

### Проведение всех доступных строк фильтра

1. Пользователь наводит указатель на заголовок «Выбор» и нажимает правую кнопку мыши.
2. Выбирает «Провести все доступные».
3. Непроведенные строки текущего фильтра с открытым кассовым днем отмечаются.
4. Общая процедура проверяет корреспондирующий счет и открытость дня, запрашивает подтверждение и проводит документы.
5. Данные перезагружаются, результат и ошибки отображаются в строке состояния/сообщении.

### Снять проведение с выбранного документа

1. Убедиться, что день кассы открыт.
2. Отметить проведенный документ в колонке «Выбор».
3. Нажать правой кнопкой на заголовке «Выбор» и выбрать «Снять проведение выбранных».
4. Подтвердить действие. Если выбранных проведенных документов несколько, обработаются они все; непроведенные строки пропускаются.

## 14. Известные границы

- Список стандартных кассовых отчетов отбирается по типам `CashBook` и `CashReceiptExpenseRegister`; для подключения нового типа потребуется добавить поддержку соответствующей подготовки набора данных в окне.
- Альтернативная форма должна иметь структуру полей, соответствующую набору данных отчета. Настройка внешнего вида хранится отдельно от подготовки строк данных.
- Кнопка Excel отображается в тех PDF-предпросмотрах, для которых вызывающий код передал callback экспорта; кассовые отчеты и печатные формы ПКО/РКО передают его.
- Кассовая книга строится по строкам, выбранным активными фильтрами окна, и оборотам, рассчитанным для указанного периода/кассы.
