# Оборотная ведомость по счёту: как устроена и как собрать свою

Документ в двух частях.

**Часть I** — полное описание того, что сделано для отчёта
**«Оборотная ведомость (ClosedXML)»** в окне «Бухгалтерская отчётность».

**Часть II** — пошаговая инструкция, как администратор собирает **такой же отчёт
без разработчика**, на примере отчёта **по паре счетов**.

Выполнено в версии **1.1.415**.

---

# Часть I. Что сделано

## 1. Задача

Отчёт должен выводить **проводки по выбранному счёту** за период:

| Колонка | Что показывает |
|---|---|
Дата | Дата проводки |
Документ | Номер документа |
Корр. счет | Счёт, с которым связан выбранный счёт |
Оборот Дт | Сумма, если выбранный счёт стоит в дебете |
Оборот Кт | Сумма, если выбранный счёт стоит в кредите |
Содержание | За что проведено |
Валюта, Сумма в валюте, Курс | Для валютных счетов |
Код АРМ | Модуль проводки |

**Плюс группировка по организациям:** заголовок организации, её проводки,
подытог `ИТОГО по N`, в конце — общий итог.

**Плюс шапка бланка:** наименование, счёт и период, организация и номер листа.

## 3. Набор данных `system.movements`

**Системный расчёт** `Services/SystemReportCalculators.cs`.

### Параметры

| Параметр | Название | Обязателен |
|---|---|---|
`PeriodStart` | Начало периода | да |
`PeriodEnd` | Конец периода | да |
`OrganizationId` | Организация | нет |
`AccountCode` | Счёт | нет |

**`AccountCode` добавлен специально для этого отчёта.** Счёт необязателен:
без него возвращаются движения по всем счетам.

### Отбор по счёту

Проводка попадает в набор, если счёт стоит **в дебете или в кредите**:

```csharp
rows = rows
    .Where(movement =>
        SameAccount(movement.DebitAccount, accountCode) ||
        SameAccount(movement.CreditAccount, accountCode))
    .ToList();
```

**Оборот записывается в ту сторону, где стоит счёт:**

```csharp
var inDebit = SameAccount(movement.DebitAccount, accountCode);
var inCredit = SameAccount(movement.CreditAccount, accountCode);

var debitAmount = string.IsNullOrWhiteSpace(accountCode) || inDebit ? movement.Amount : 0m;
var creditAmount = !string.IsNullOrWhiteSpace(accountCode) && inCredit ? movement.Amount : 0m;
```

**Противоположный счёт становится корреспондентским:**

```csharp
var counterAccount = inDebit ? movement.CreditAccount : movement.DebitAccount;
```

### Колонки набора — 27

**Для экрана и общего вывода:**

`Дата`, `Организация`, `N докум`, `Вид документа`, `Дебет`, `Кредит`,
`Сумма`, `Содержание`, `Модуль`

**Для макета — с подчёркиваниями:**

| Колонка | Что содержит |
|---|---|
`posting_date` | Дата проводки |
`organization_id` | Наименование организации |
`organization_code` | **Номер** организации — для заголовка группы |
`organization_name` | Наименование организации |
`doc_number` | Номер документа |
`document_type` | Вид документа |
`debit_account` | Счёт дебета |
`credit_account` | Счёт кредита |
`amount_kgs` | Сумма в сомах |
`description` | Содержание |
`module_code` | Модуль |
`account_code` | **Выбранный счёт** — из параметра |
`counter_account_code` | **Корреспондентский счёт** |
`debit_amount` | **Оборот Дт** — сумма, если счёт в дебете |
`credit_amount` | **Оборот Кт** — сумма, если счёт в кредите |
`currency_code` | Код валюты: RUB, USD, EUR |
`amount_currency` | Сумма в валюте |
`exchange_rate` | Курс: сом ÷ валюта |

**Курс считается из самой проводки**, а не берётся из справочника: отчёт
показывает то, что реально прошло по учёту.

```csharp
var rate = movement.AmountCurrency != 0m
    ? Math.Round(movement.Amount / movement.AmountCurrency, 4)
    : 0m;
```

```xml

    <ByFields>organization_id, organization_code</ByFields>
    <HeaderFormat>{organization_code} {organization_id}</HeaderFormat>
    <SubtotalValueField>organization_code</SubtotalValueField>
    <Subtotal Label="ИТОГО по" SumFields="debit_amount, credit_amount"/>
</ClosedXmlGroup>

<GrandTotal Label="ИТОГО" SumFields="debit_amount, credit_amount"/>
```

**Что получается:**

```

  30.09.26  10  31100000  55 555,55        Строка 2: fgds
  30.09.26  10  34300000   6 666,67        НДС: Строка 2
```

| Правило | Зачем |

## 5. Подстановка параметров в шапку — что было сломано

### Симптом

```
Шаблон:  по счету {AccountCode} с {PeriodStart:dd/MM/yyyy} по {PeriodEnd:dd/MM/yyyy}
Вывод:   по счету  с  по
```

**Счёт и период печатались пустыми.**

### Причина

**Параметры берутся из `report.Parameters`:**

```csharp
public async Task<Dictionary<string, object>> ResolveParametersForPreviewAsync(Report report)
{
    var saved = await new ReportUserSettingService(_context).GetValuesAsync(...);
    return ReportParameterResolver.ResolvePreviewValues(report, saved);
    //                                              ↑ только из report.Parameters
}
```

**Построитель набивал только `Fields`:**

```csharp
var report = CreateReport(table, title, true);
report.Fields.Add(...);        // ← колонки есть
// report.Parameters         ← а параметров нет
```

**Словарь приходил пустым**, и `ResolveText` вырезал подстановки.

### Исправление

**Параметры записываются при построении отчёта:**

```csharp
// Параметры для подстановок в шапке макета: «по счету {AccountCode}
// с {PeriodStart:dd/MM/yyyy} по {PeriodEnd:dd/MM/yyyy}». Без них
// в шапке печаталось «по счету с по».
SetRenderParameters(current,
    ("AccountCode", _trialBalanceAccountCode),
    ("PeriodStart", start),
    ("PeriodEnd", end));
```

**Даты пишутся в неизменном формате:**

```csharp
parameter.DefaultValue = value switch
{
    // Дата пишется в неизменном формате: его понимает разбор
    // значения по умолчанию независимо от культуры системы.
    DateTime date => date.ToString("yyyy-MM-dd", CultureInfo.InvariantCulture),
    _ => value.ToString() ?? string.Empty
};
parameter.ParameterType = value is DateTime
    ? ReportParameterTypes.Date
    : ReportParameterTypes.String;
```

**Формат вывода задаёт макет** (`{PeriodStart:dd/MM/yyyy}`), поэтому
в шапке получается **01.01.2026**, а не ISO.

### Разбор подстановок

`ResolveText` в `ClosedXmlReportRenderer`:

| Запись | Что подставляет |
|---|---|
`{AccountCode}` | Значение параметра |
`{param.AccountCode}` | То же — старая запись |
`{PeriodStart:dd/MM/yyyy}` | Значение с форматом |
`{Organization}` | Организация из данных отчёта |
`{Дата}` | Дата печати |

**Неизвестная подстановка → пустая строка**, чтобы в документе
не осталось фигурных скобок.

### Результат — проверено на выводе

```
стр.1: Оборотная ведомость синтетического и аналитического учета
стр.2: по счету 15301000 с 01.01.2026 по 31.12.2026
```

### Проверка остальных отчётов

| Отчёт | Подстановки в шапке |
|---|---|
Оборотная ведомость | `{AccountCode}`, `{PeriodStart}`, `{PeriodEnd}` |
Акт сверки | нет |
Журнал счет-фактур | нет |
Счёт-фактура СТ-1 | нет |

**Дефект был только в ведомости.** У остальных шапка берётся из данных
через `TakeFromField`.

## 6. Экранная таблица

**Грид показывает только колонки отчёта.** Служебные колонки скрываются
списком `ServiceColumnNames`:

```csharp
private static readonly HashSet<string> ServiceColumnNames = new(StringComparer.OrdinalIgnoreCase)
{
    // Оборотная ведомость по счёту.
    "posting_date", "doc_number", "counter_account_code", "description",
    "module_code", "report_org", "report_period",
    "opening_balance", "closing_balance",
    "currency_code", "amount_currency", "exchange_rate",
    "organization_name", "row_kind"

```

**Правило:** колонка, которой нет в списке, **появится в гриде**. Сейчас
в гриде видны `organizationid`, `documenttype`, `amountkgs` — алиасы
без подчёркиваний, которые в список не попали.

## 7. Выбор данных в окне

| Поле | Что делает |
|---|---|
**Отчет** | Список из базы: `Reports` где `ShowInAccountingReports` |
**С** / **По** | Период |
**Счет** + «?» | Выбор счёта из плана счетов |
**Организация** | Номер вручную или «?» |
**Все организации** | Отчёт по всем; снять — выбрать одну |

**Набор данных подбирается по типу отчёта:**

```csharp
private static string ResolveDataSetCodeForReport(string? reportType)
{
    if (string.Equals(reportType, "InvoiceJournal", ...))
        return ReportDataSetService.InvoiceJournalDataSetCode;

    if (string.Equals(reportType, "VatInvoiceSt1", ...))
        return ReportDataSetService.VatInvoiceSt1DataSetCode;

    if (IsReconciliationType(reportType))
        return SystemReportCalculators.ReconciliationActCode;

    // Ведомость по счёту и прочие табличные отчёты — движения по проводкам.
    return SystemReportCalculators.MovementsCode;
}
```

## 8. Ограничения механизма

### Закрытый список параметров SQL-наборов

**Для SQL-наборов** доступны **только** эти параметры:

`@PeriodStart`, `@PeriodEnd`, `@CashDeskId`, `@OrganizationId`, `@EmployeeId`,
`@AccountCode`, `@UserName`

**Свой `@MyParam` вызовет ошибку** `42703: столбец "xxx" не существует`.

**Для системных расчётов** список задаётся в коде калькулятора.

### Колонка — это контракт

**Макет обращается к данным по именам колонок.** Не совпало имя — **колонка
молча исчезает**, без ошибки.

### Один набор на отчёт

Набор подбирается по **типу отчёта**. Два отчёта с одним типом получат
один набор данных.

# Часть II. Как собрать такой отчёт администратору

## Что понадобится

**Пример:** отчёт **по паре счетов** — например `12100000` (расчётный счёт)
и `322000` (авансы полученные). Нужно видеть, кто и сколько перечислил.

**Инструменты:** «Наборы данных отчётов», «Конструктор отчётов».

**Ни одной строки кода.**

---

## Шаг 1. Выбрать источник данных

**Открой:** раздел с наборами данных отчётов.

**Найди `system.movements`** — «Движения по проводкам».

**Что он умеет:**

| Возможность | Как |
|---|---|
Период | Параметры `PeriodStart`, `PeriodEnd` |
Организация | Параметр `OrganizationId` |
**Отбор по счёту** | Параметр **`AccountCode`** |
Валюта | Колонки `currency_code`, `amount_currency`, `exchange_rate` |
Корреспондентский счёт | Колонка `counter_account_code` |

**Для отчёта по счёту — этого достаточно.** Ничего создавать не надо.

**Если нужен отбор сразу по двум счетам** — см. Шаг 6.

| Место в списке | Зачем |
|---|---|
**Последнее** поле | Задаёт значение в подписи подытога |
Остальные | Подставляются в заголовок через `{имя}` |

**Здесь:** `organization_id` первый — наименование, `organization_code` последний —
номер. Получается заголовок `3 324211` и подытог `ИТОГО по 3`.

### Общий итог

| Поле | Значение |
|---|---|
**Подпись** | `ИТОГО` |
**Суммировать** | `debit_amount`, `credit_amount` |
**Жирный** | да |

## Шаг 7. Заголовок бланка с счётом и периодом

**Добавь блок «Заголовок» и две строки:**

| Строка | Колонка | Объединить до | Текст | Оформление |
|---|---|---|---|---|
1 | 1 | 8 | `Оборотная ведомость синтетического и аналитического учета` | жирный, по центру |
2 | 1 | 8 | `по счету {AccountCode} с {PeriodStart:dd/MM/yyyy} по {PeriodEnd:dd/MM/yyyy}` | жирный, по центру |

**Подстановки работают сами** — параметры набора передаются в макет.

| Подстановка | Что подставит |
|---|---|
`{AccountCode}` | Выбранный счёт |
`{PeriodStart:dd/MM/yyyy}` | Начало периода |
`{PeriodEnd:dd/MM/yyyy}` | Конец периода |
`{Organization}` | Первичная организация |
`{Дата}` | Дата печати |

**Формат после двоеточия** — любой формат даты .NET: `dd.MM.yyyy`, `MM/yyyy`.

## Отбор по **паре** счетов

**Механизм даёт отбор по одному счёту.** Для пары есть два пути.

### Путь 1. Отчёт по одному счёту, второй — в корреспонденции

**Проще всего.** Выбери счёт `12100000`, и колонка **`counter_account_code`**
покажет парный счёт `322000`.

**Плюс:** ничего создавать не надо.
**Минус:** второй счёт виден только у своих проводок.

### Путь 2. SQL-набор с отбором по двум счетам

**Нужен администратор, знающий SQL.**

**Создай набор данных** с запросом:

```sql
WITH movements AS (
    SELECT p.posting_date,
           p.doc_number,
           p.debit_account,
           p.credit_account,
           COALESCE(p.amount_kgs, 0)      AS amount_kgs,
           COALESCE(p.amount_currency, 0) AS amount_currency,
           COALESCE(p.description, '')    AS description,
           COALESCE(p.module_code, '')    AS module_code,
           COALESCE(c."code", '')         AS currency_code,
           COALESCE(o."code", '')         AS organization_code,
           COALESCE(NULLIF(o."name", ''), 'Без организации') AS organization_name
    FROM doc_postings p
    LEFT JOIN catalog_currencies c ON c."Id"::text = p.currency_id
    LEFT JOIN catalog_organizations o ON o."id"::text = p.organization_id::text
    WHERE COALESCE(p.is_active, true) = true
      AND p.posting_date >= @PeriodStart
      AND p.posting_date <  @PeriodEnd + INTERVAL '1 day'
      -- ПАРА СЧЕТОВ: проводка, где один счёт из пары в дебете, второй в кредите
      AND (
            (p.debit_account = '12100000' AND p.credit_account = '322000')
         OR (p.debit_account = '322000'   AND p.credit_account = '12100000')
      )
)
SELECT posting_date,
       doc_number,
       CASE WHEN debit_account = '12100000' THEN credit_account ELSE debit_account END AS counter_account_code,
       CASE WHEN debit_account = '12100000' THEN amount_kgs ELSE 0 END                 AS debit_amount,
       CASE WHEN credit_account = '12100000' THEN amount_kgs ELSE 0 END                AS credit_amount,
       description,
       module_code,
       currency_code,
       amount_currency,
       CASE WHEN amount_currency <> 0 THEN ROUND(amount_kgs / amount_currency, 4) ELSE 0 END AS exchange_rate,
       organization_code,
       organization_name
FROM movements
ORDER BY posting_date, doc_number;
```

**Что делает:**

| Часть | Зачем |
|---|---|
`AND (...)` | Отбор **только парных** проводок между двумя счетами |
`CASE WHEN` для `counter_account_code` | Показывает парный счёт |
`CASE WHEN` для `debit_amount` / `credit_amount` | Оборот по выбранному счёту |

**Правила SQL-наборов:**

| Правило | Значение |
|---|---|
Разрешено | Только `SELECT` или `WITH` |
Несколько команд | Запрещено |
Запрещённые слова | `INSERT`, `UPDATE`, `DELETE`, `DROP` и подобные |
Параметры | **Только из закрытого списка** |

**Закрытый список параметров:**

```
@PeriodStart, @PeriodEnd, @CashDeskId, @OrganizationId,
@EmployeeId, @AccountCode, @UserName
```

**Свой `@НовыйПараметр` вызовет ошибку** `42703`.

**Дальше** — колонки нового набора подставь в макет по Шагам 4–9.
**Имена колонок в макете = имена колонок из `SELECT`.**

## Проверка перед сохранением

| Проверка | Как |
|---|---|
**Имена колонок совпадают** | Сверь поле макета с колонкой набора **по буквам** |
**Счёт и период видны** | Непустые подстановки в шапке |
**Итоги считаются** | В Excel формула `SUM` — нажми F9 |
**Отчёт в списке** | Галка «Показывать в бухгалтерской отчетности» |
**Макет сохранён** | Вкладка макета не пустая |

**Самая частая ошибка: имя колонки не совпало.** Тогда колонка
**молча исчезнет** — без ошибки и предупреждения.

## Коротко: порядок действий

```
1. Набор данных   → выбрать system.movements (отбор по счёту уже есть)
2. Конструктор    → создать отчёт
3. Галка          → «Показывать в бухгалтерской отчетности»
4. Таблица        → 10 колонок, поля = имена колонок набора
5. Шапка          → 2 уровня: «ОБОРОТЫ-сом» над Дебет и Кредит
6. Группировка    → по organization_id + organization_code
                    подытог «ИТОГО по» + поле organization_code
7. Общий итог     → «ИТОГО»
8. Заголовок      → с {AccountCode} и {PeriodStart}/{PeriodEnd}
9. Колонтитул     → организация и листы вверху справа
10. Сохранить     → отчёт в списке окна
```

**Пересборка программы не нужна.**
