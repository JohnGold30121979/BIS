# Инструкция: «Справочник типов услуг» в модуле «Абонентский отдел» (пользовательский справочник)

> **Область:** этот документ — про **пользовательский** справочник, который создаётся
> администратором в конкретной базе (через SQL или конфигуратор).
> Про **системный** справочник, который описан в коде метаданных и разворачивается сам
> во всех базах, — отдельный документ:
> [Инструкция_Системный_справочник_типов_услуг.md](<Docs/Инструкция_Системный_справочник_типов_услуг.md>).

Документ для самостоятельного создания справочника с метаданными. Два пути:

* **Путь A — SQL** (можно сделать самому, без программиста, 10–15 минут);
* **Путь B — код** (краткая версия; подробно — в документе про системный справочник).

---

## 0. Что должно получиться

| Что | Значение |
|---|---|
| Объект метаданных | `Справочник типов услуг`, `ObjectType = Catalog` |
| Таблица данных | `catalog_service_types` |
| Поле 1 | `Код` → `code`, String(50), обязательное, уникальное |
| Поле 2 | `Тип услуги` → `service_type`, String(300), обязательное |
| Записи | `1` — Холодное водоснабжение, `2` — Канализация, `3` — Отопление |
| Модуль | `Абонентский отдел` (код `abonent`) |
| Где будет видно | навигация: раздел «СПРАВОЧНИКИ» и «АБОНЕНТСКИЙ ОТДЕЛ → Справочники» |

---

## 1. Важно знать до начала: почему «только мышкой» не получится

В текущей версии конфигуратора нет полноценного конструктора справочников:

1. **«Создать → 📚 Справочник» — заглушка.** Диалог `CreateCatalogDialog` собирает имя, поля
   и тип, но обработчик `OnCreateCatalogClick` просто перезагружает дерево и **ничего не
   создаёт** ([ConfiguratorWindow.xaml.cs:3456](<Views/ConfiguratorWindow.xaml.cs>)).
2. **«Создать → Создать Динамически → 📚 Справочник»** создаёт реальный объект и пустую
   таблицу, но **без полей** (`Fields = new List<MetadataField>()`,
   [ConfiguratorWindow.xaml.cs:1073](<Views/ConfiguratorWindow.xaml.cs>)).
3. **Добавить поле в редакторе объекта нельзя:** кнопка «➕ Добавить поле» показывает
   «Добавление полей в разработке»
   ([DynamicObjectsConfigView.xaml.cs:109](<Views/Configurator/DynamicObjectsConfigView.xaml.cs>)).
4. **Привязать справочник к модулю через интерфейс нельзя:** во вкладке «Неназначенные»
   редактора модулей только документы и отчёты, а сохранение принимает только их
   (`SaveAssignmentsAsync(moduleId, documentIds, reportIds)`,
   [ModuleManagementView.xaml.cs](<Views/Configurator/ModuleManagementView.xaml.cs>)).
   Справочники привязываются списками имён в коде
   (`ModuleMetadataService.FinanceCatalogNames` и т. п.).

Поэтому создавать справочник будем в базе данных (Путь A) либо в коде (Путь B).
**Модуль** при этом можно создать штатно через конфигуратор — это поддерживается.

## 2. Подготовка (5 минут)

### 2.1. Найдите нужную базу и её параметры подключения

Метаданные лежат **в базе информационной базы**, а не в `bis_master`.

1. Откройте программу — в окне выбора информационной базы видно её наименование
   (например «ОсОО3»).
2. Параметры подключения этой базы — в системной базе `bis_master`, таблица `InfoBases`:

```sql
-- выполнить в базе bis_master
SELECT "Name", "DatabaseName", "Host", "Port", "Username"
FROM "InfoBases"
ORDER BY "Name";
```

3. Запомните `DatabaseName` нужной базы (например `bis_OsOO3_20261026_133202`),
   а также Host/Port/Username/Password — это реквизиты подключения к серверу.

> Пароль в базе хранится в открытом виде в поле `Password`, либо возьмите его из
> `appsettings.json` в папке программы.

### 2.2. Сделайте резервную копию

Любым привычным способом:

* **pgAdmin**: правая кнопка по базе → **Backup…** → формат `Custom` или `Tar` → файл;
* **pg_dump** (утилита из комплекта PostgreSQL, путь зависит от установки):

```powershell
pg_dump -h localhost -p 5432 -U postgres -F c `
  -f "D:\backup\bis_before_service_types.dump" "bis_OsOO3_20261026_133202"
```

### 2.3. Закройте программу

Метаданные читаются при запуске. Пока приложение открыто, изменения в базе оно не увидит,
а после скрипта программу нужно **запустить заново**.

### 2.4. Чем выполнять SQL

Подойдёт pgAdmin 4 (Query Tool), DBeaver, HeidiSQL или `psql`.
**Все скрипты выполняются в базе информационной базы** из п. 2.1 (не в `bis_master`).

## 3. Путь A. SQL по шагам

Скрипт идемпотентный: его можно прогнать повторно, дубликатов не будет.
Каждый шаг можно выполнять отдельно, но удобнее — целиком (§3.8) в одной транзакции.

> **Скрипт проверен** на структуре рабочей базы: выполнен внутри транзакции с откатом,
> повторный прогон дубликатов не создаёт, скрипт отката (§3, шаг 9) удаляет всё без остатка.

### Шаг 1. Модуль «Абонентский отдел»

**Вариант 1 (рекомендуемый, штатный UI).** В конфигураторе: меню
**«Создать → Модуль»** — откроется вкладка **«Модули и разделы»** → кнопка **«Добавить»** →
заполнить:

| Поле | Значение |
|---|---|
| Наименование | `Абонентский отдел` |
| Код | `abonent` (латиницей, без пробелов) |
| Иконка | `🚿` (или любой символ) |
| Описание | `Абоненты и услуги` |
| Порядок | `100` |
| Доступен в инфобазе | ✅ обязательно |
| Участвует в закрытии периода | можно снять — это справочник, не расчётный модуль |

→ **«Сохранить модуль»**.

> «Доступен в инфобазе» = `IsActive`. Если модуль отключён, привязанный к нему
> справочник **исчезает из навигации** (логика `IsHiddenByUnavailableModule`,
> [MainWorkWindow.xaml.cs:807](<Views/MainWorkWindow.xaml.cs>)).
>
> Порядок `100` ставит модуль после существующих (в типовой базе: Финансы 10, Баланс 20,
> Основные средства 30, Материалы 40, Зарплата 50, Сбыт 60, Сырьё 70, Себестоимость 80).

**Вариант 2 (SQL).** Если удобнее всё одним скриптом:

```sql
INSERT INTO "MetadataModules"
    ("Id", "Code", "Name", "Description", "Icon",
     "Order", "CloseOrder", "IsActive", "ParticipatesInPeriodClose",
     "RequirePreviousModulesClosed", "IsSystem")
SELECT gen_random_uuid(), 'abonent', 'Абонентский отдел',
       'Абоненты и услуги абонентского отдела', '🚿',
       100, 100, true, false, false, false
WHERE NOT EXISTS (SELECT 1 FROM "MetadataModules" WHERE "Code" = 'abonent');
```

### Шаг 2. Таблица данных справочника

```sql
CREATE TABLE IF NOT EXISTS "catalog_service_types" (
    "Id"         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    "code"       varchar(50)  NOT NULL,
    "service_type" varchar(300) NOT NULL,
    "CreatedAt"  timestamp DEFAULT CURRENT_TIMESTAMP,
    "UpdatedAt"  timestamp DEFAULT CURRENT_TIMESTAMP
);

-- необязательно: уникальность кода на уровне базы
CREATE UNIQUE INDEX IF NOT EXISTS "ux_catalog_service_types_code"
    ON "catalog_service_types" ("code");
```

Имена колонок = `DbColumnName` полей из шага 4. `"Id"`, `"CreatedAt"`, `"UpdatedAt"` —
стандарт для таблиц справочников (по `CreatedAt` список сортируется).

### Шаг 3. Объект метаданных

```sql
INSERT INTO "MetadataObjects"
    ("Id", "Name", "TableName", "ObjectType", "Description", "Icon", "Order",
     "IsSystem", "ParentId", "MetadataConfigId",
     "UsePostings", "UseBalances", "UseMovements",
     "BalanceTable", "MovementTable", "ReferenceFields")
SELECT gen_random_uuid(),
       'Справочник типов услуг',
       'catalog_service_types',
       'Catalog',
       'Типы услуг абонентского отдела: водоснабжение, канализация, отопление',
       '🚿',
       (SELECT COALESCE(MAX("Order"), 0) + 1
          FROM "MetadataObjects" WHERE "ObjectType" = 'Catalog'),
       false,                                  -- IsSystem: не системный, можно править
       NULL,                                   -- ParentId
       (SELECT "Id" FROM "MetadataConfigurations"
         ORDER BY "IsInitialized" DESC, "CreatedAt" LIMIT 1),
       false, false, false,                    -- проводки/балансы/движения не нужны
       NULL, NULL, NULL
WHERE NOT EXISTS (
    SELECT 1 FROM "MetadataObjects"
     WHERE "ObjectType" = 'Catalog' AND "TableName" = 'catalog_service_types');
```

### Шаг 4. Поля справочника

```sql
-- Поле 1: Код
INSERT INTO "MetadataFields"
    ("Id", "Name", "DbColumnName", "FieldType", "Length", "Precision", "Scale",
     "IsRequired", "IsUnique", "Order", "MetadataObjectId",
     "ReferenceCatalog", "Formula", "DisplayPattern", "DisplayFields")
SELECT gen_random_uuid(), 'Код', 'code', 'String', 50, 18, 2,
       true, true, 1, o."Id", NULL, NULL, NULL, NULL
FROM "MetadataObjects" o
WHERE o."ObjectType" = 'Catalog' AND o."TableName" = 'catalog_service_types'
  AND NOT EXISTS (SELECT 1 FROM "MetadataFields" f
                   WHERE f."MetadataObjectId" = o."Id" AND f."DbColumnName" = 'code');

-- Поле 2: Тип услуги
INSERT INTO "MetadataFields"
    ("Id", "Name", "DbColumnName", "FieldType", "Length", "Precision", "Scale",
     "IsRequired", "IsUnique", "Order", "MetadataObjectId",
     "ReferenceCatalog", "Formula", "DisplayPattern", "DisplayFields")
SELECT gen_random_uuid(), 'Тип услуги', 'service_type', 'String', 300, 18, 2,
       true, false, 2, o."Id", NULL, NULL, NULL, NULL
FROM "MetadataObjects" o
WHERE o."ObjectType" = 'Catalog' AND o."TableName" = 'catalog_service_types'
  AND NOT EXISTS (SELECT 1 FROM "MetadataFields" f
                   WHERE f."MetadataObjectId" = o."Id" AND f."DbColumnName" = 'service_type');
```

Пояснения:

* `FieldType` — `String`, `Int`, `Decimal`, `DateTime`, `Bool`, `Reference`;
* `Length` используется только для `String` (varchar), `Precision/Scale` — для `Decimal`;
* `Order` = место поля в форме и в списке;
* `IsRequired` = звёздочка и проверка при сохранении;
* у поля с именем **`Код`** диалог автоматически генерирует следующий код и делает поле
  только для чтения — это штатное поведение (`ApplyGeneratedCodeAsync`).

### Шаг 5. Привязка справочника к модулю

```sql
INSERT INTO "MetadataModuleItems" ("Id", "ModuleId", "ObjectId", "ObjectType", "Order")
SELECT gen_random_uuid(), m."Id", o."Id", 'Catalog',
       COALESCE((SELECT MAX(i."Order") FROM "MetadataModuleItems" i
                  WHERE i."ModuleId" = m."Id"), 0) + 1
FROM "MetadataModules" m, "MetadataObjects" o
WHERE m."Name" = 'Абонентский отдел'
  AND o."ObjectType" = 'Catalog' AND o."TableName" = 'catalog_service_types'
  AND NOT EXISTS (
      SELECT 1 FROM "MetadataModuleItems" i
       WHERE i."ObjectType" = 'Catalog' AND i."ObjectId" = o."Id");
```

Ограничение базы: у пары `(ObjectType, ObjectId)` — уникальный индекс, то есть справочник
может принадлежать **только одному** модулю. Повторный запуск скрипта ничего не сломает.

### Шаг 6. Стартовые записи

```sql
INSERT INTO "catalog_service_types" ("Id", "code", "service_type")
SELECT gen_random_uuid(), v.code, v.name
FROM (VALUES ('1', 'Холодное водоснабжение'),
             ('2', 'Канализация'),
             ('3', 'Отопление')) AS v(code, name)
WHERE NOT EXISTS (
    SELECT 1 FROM "catalog_service_types" t WHERE t."code" = v.code);
```

Коды можно взять другие (`ХВС`, `КАН`, `ОТП`) — это строковое поле, длина до 50.

### Шаг 7. Проверка в базе

```sql
-- 1) объект и поля
SELECT o."Name", f."Order", f."Name", f."DbColumnName", f."FieldType",
       f."Length", f."IsRequired", f."IsUnique"
FROM "MetadataFields" f
JOIN "MetadataObjects" o ON o."Id" = f."MetadataObjectId"
WHERE o."TableName" = 'catalog_service_types'
ORDER BY f."Order";

-- 2) привязка к модулю
SELECT m."Name" AS "Модуль", m."IsActive" AS "Модуль включён",
       i."ObjectType", o."Name" AS "Объект"
FROM "MetadataModuleItems" i
JOIN "MetadataModules" m ON m."Id" = i."ModuleId"
JOIN "MetadataObjects" o ON o."Id" = i."ObjectId"
WHERE o."TableName" = 'catalog_service_types';

-- 3) данные
SELECT "code", "service_type" FROM "catalog_service_types" ORDER BY "code";
```

Ожидаемый результат: 2 поля (`code` — Order 1, обязательное и уникальное; `service_type` —
Order 2, обязательное), одна строка привязки `Catalog → Абонентский отдел (включён)`,
три записи.

### Шаг 8. Проверка в программе

1. Запустите программу, войдите в базу.
2. В дереве навигации: раздел **«СПРАВОЧНИКИ»** → **«Справочник типов услуг»**;
   и в модуле **«АБОНЕНТСКИЙ ОТДЕЛ»** → группа **«Справочники»** → тот же справочник.
   Если модуля в дереве нет — проверьте, что у него включено «Доступен в инфобазе»,
   и перезапустите программу.
3. Откройте справочник: колонки **«Код»** и **«Тип услуги»**, три записи.
4. **«➕ Добавить»**: откроется карточка, «Код» подставится автоматически (4), введите
   «Тип услуги» → «Сохранить». Запись появится в списке.
5. **«✏️ Редактировать»** — проверьте, что значения читаются и сохраняются.

## 4. Путь B. Через код продукта (для разработчика)

Нужен, если справочник должен появляться в **новых** базах автоматически и догоняться
в существующих. Порядок действий:

1. **Описание полей** — `MetadataService.Fields.cs`, новый метод `GetServiceTypeFields`
   (по образцу `GetMaterialFields`, строка 350):

```csharp
private List<MetadataField> GetServiceTypeFields(Guid metadataObjectId)
{
    return new List<MetadataField>
    {
        new MetadataField { Id = Guid.NewGuid(), Name = "Код", DbColumnName = "code",
            FieldType = "String", Length = 50, IsRequired = true, IsUnique = true,
            Order = 1, MetadataObjectId = metadataObjectId },
        new MetadataField { Id = Guid.NewGuid(), Name = "Тип услуги", DbColumnName = "service_type",
            FieldType = "String", Length = 300, IsRequired = true,
            Order = 2, MetadataObjectId = metadataObjectId }
    };
}
```

2. **Создание справочника** — `MetadataService.Catalogs.cs`, метод
   `CreateServiceTypesCatalog(config)` по образцу `CreateMaterialTypesCatalog`
   (строка 138): `Name = "Справочник типов услуг"`, `TableName = "catalog_service_types"`,
   `ObjectType = "Catalog"`, `Icon = "🚿"`, `Fields = GetServiceTypeFields(...)`,
   затем `CreateTableForCatalogAsync` и заполнение `AddServiceTypesDataToTable` тремя записями.

3. **Вызов при инициализации** — `MetadataService.cs`, `InitializePredefinedCatalogsAsync`
   (строка ~1274, рядом с материалами):

```csharp
if (!existingCatalogs.Contains("Справочник типов услуг"))
    await CreateServiceTypesCatalog(config);
await EnsureServiceTypesCatalogStructureAsync();
```

4. **Догон существующих баз** — `EnsureServiceTypesCatalogStructureAsync` по образцу
   `EnsureMaterialCatalogStructureAsync` (`MetadataService.Catalogs.cs:204`): находит каталог,
   добавляет недостающие поля (`_context.MetadataFields.AddAsync` + `AddColumnToTableAsync`)
   и приводит описание существующих к шаблону.

5. **Модуль и привязка** — `ModuleMetadataService`:
   * добавить модуль в посев `EnsureDefaultModulesAsync` вызовом
     `EnsureModuleAsync(code: "abonent", name: "Абонентский отдел", description: ..., icon: "🚿",
     order: 90, closeOrder: 90, isActiveByDefault: true, participatesInPeriodClose: false)`
     (метод на строке 272; модуль станет системным, как остальные);
   * объявить `public static readonly string[] ServiceTypesCatalogNames = { "Справочник типов услуг" };`
   * в `SynchronizeDefaultAssignmentsAsync` (строка ~338) вызвать по образцу остальных:

```csharp
await AssignMissingByNameAsync(
    modules[ServiceTypesCode].Id, "Catalog",
    catalogs.Select(item => (item.Id, item.Name)), ServiceTypesCatalogNames);
```

   * **важно:** автосинхронизация выполняется только на «пустой» базе (метод выходит,
     если у системных модулей уже есть объекты). Для привязки в уже настроенных базах нужен
     отдельный ensure-метод, который при каждом старте проверяет наличие пары
     «модуль ↔ каталог» и добавляет её, если нет.

6. **Проверка:** новая база — каталог в модуле сразу; существующая — после запуска
   `Ensure…` появляются поля, записи и привязка к модулю.

## 5. Чек-лист приёмки

- [ ] В дереве навигации есть «Справочник типов услуг» (раздел «СПРАВОЧНИКИ»).
- [ ] Он же виден в модуле «АБОНЕНТСКИЙ ОТДЕЛ → Справочники».
- [ ] В списке колонки «Код» и «Тип услуги», есть три записи.
- [ ] «Добавить» создаёт запись, «Код» подставляется автоматически.
- [ ] «Редактировать» открывает значения и сохраняет изменения.
- [ ] После перезапуска программы всё на месте (ничего не «откатилось»).
- [ ] В конфигураторе («Справочники» в дереве) объект виден и его поля читаются.

## 6. Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| Справочника нет в дереве | программа не перезапущена, либо `ObjectType` не `Catalog`, либо `TableName` пуст | перезапустить; проверить `MetadataObjects` |
| В «СПРАВОЧНИКАХ» есть, в модуле нет | нет строки в `MetadataModuleItems` или модуль отключён (`IsActive = false`) — объект, привязанный только к отключённому модулю, скрывается | проверить привязку и флаг «Доступен в инфобазе» |
| Модуль не появился | модуль отключён или у него пустой код | включить «Доступен в инфобазе», задать код |
| При сохранении «столбец … не существует» | поле в `MetadataFields` есть, колонки в таблице нет | перезапустить программу: `MetadataSchemaRepairService` добавит колонку по метаданным; либо `ALTER TABLE ... ADD COLUMN` вручную |
| Поле есть в базе, но не видно в форме | нет строки в `MetadataFields` (колонка есть, описания нет) | добавить строку метаданных (шаг 4) |
| «Код» серый и не редактируется | штатное поведение автогенерации | ничего не делать, код подставляется сам |
| Две записи об одном справочнике | скрипт запускали без условия `NOT EXISTS` | удалить лишнюю строку `MetadataObjects` (и её поля), проверить навигацию |
| После «Загрузить конфигурацию» пропали данные | импорт конфигурации **удаляет все динамические таблицы** (`DROP TABLE … CASCADE`, [ConfigurationExchangeService.cs:272](<Services/ConfigurationExchangeService.cs>)) | импорт для этой задачи не использовать; восстановить из резервной копии |

## 7. Что нельзя делать

* **Выполнять скрипт в `bis_master`** — там нет таблиц метаданных справочников;
* **Загружать конфигурацию из JSON** вместо SQL — импорт стирает динамические таблицы
  со всеми данными;
* **Менять `IsSystem` на `true`** — объект станет системным и будет вести себя как служебный;
* **Привязывать каталог к двум модулям** — не даст уникальный индекс
  `(ObjectType, ObjectId)` в `MetadataModuleItems`.
