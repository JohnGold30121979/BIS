# `CatalogItemDialog`: мёртвый код — описание и рекомендации

> **Статус:** только анализ. Код по этому документу **не менялся** — правки делаются отдельной
> задачей. Все ссылки на строки даны по текущей версии файла
> `Views/CatalogItemDialog.xaml.cs` (2101 строка) и `Views/CatalogItemDialog.xaml` (72 строки)
> на 28.10.2026.

## 1. Что и как проверялось

1. Из файла выбраны все объявления членов (`private/public/internal/protected`: методы, поля,
   свойства) и для каждого посчитаны ссылки в самом файле и по всему репозиторию.
2. Для «подозрительных» веток (условия по именам полей) сверены **фактические метаданные**
   в локальных базах `bis_OsOO1_20260908_112439`, `bis_OsOO2_20261019_130122`,
   `bis_OsOO3_20261026_133202` — какие поля реально есть у справочников.
3. Сборка проверена на предупреждения: по `CatalogItemDialog` их **ноль** — компилятор такие
   члены не подсвечивает (в проекте нет `.editorconfig` и анализаторов неиспользуемого кода
   IDE0051/IDE0052), поэтому мёртвый код виден только при чтении файла.

Ограничения: анализировались члены класса (не локальные переменные и не лямбды); XAML проверен
на `x:Name`, на которые никто не ссылается.

## 4. Мёртвая ветка в рабочем коде

`ShouldStoreReferenceDisplayValue` (1516–1523) и тернарник в `ReadFieldValue` (1610–1615):

```csharp
return ShouldStoreReferenceDisplayValue(field)
    ? referencePicker.SelectedReferenceItem?.DisplayName ?? referencePicker.ComboBox.Text ?? string.Empty
    : referencePicker.SelectedReferenceItem?.Id.ToString() ?? string.Empty;
```

Метод возвращает `true` только для справочника «Организации» и полей `Банк`/`bank_name`/
`Расчетный счет`/`bank_account`. Проверка по трём базам:

| База | Поля «Банк»/«Расчетный счет» |
|---|---|
| `bis_OsOO1_…` | только у «Расчетные счета организаций»: `bank_id`, `account_number` |
| `bis_OsOO2_…` | то же |
| `bis_OsOO3_…` | то же |

У «Организаций» таких полей нет ни в одной базе (и комментарий в коде на строках 262–265 прямо
говорит, что банковские реквизиты из организаций удалены). Условие всегда `false` — ветка
недостижима.

**Важно перед удалением:** проверить клиентские базы (SQL в §7), потому что если в какой-то старой
базе поля `bank_name`/`bank_account` всё же есть, ветка станет нужной: тогда в колонку пойдёт
`Id` вместо названия банка.

## 7. План уборки (по этапам, каждый — отдельный коммит)

### Этап 1. Кластер «расшифровки ссылок» — безопасно, ≈ 161 строка

Удалить: поле `_referenceCache` (21) и его инициализацию в конструкторе (44), методы
`GetReferenceLookupKeys` (337–369), `NormalizeReferenceLookupKey` (371–381), `GetDisplayFieldName`
(386–416), `GetDisplayValueOLD` (421–446), `GetDisplayValue` (450–500), `NormalizeAccountTypeCode`
(648–654).

Проверка: сборка без новых предупреждений; открыть и сохранить карточки «Организации», «МОЛ»,
«План счетов», «Пары счетов», «Справочник материалов», «Ввод нового документа ТМЗ».

### Этап 2. Мёртвая ветка `ReadFieldValue`

Сначала SQL по всем базам (ожидается 0 строк):

```sql
SELECT o."Name", f."Name", f."DbColumnName"
FROM "MetadataFields" f
JOIN "MetadataObjects" o ON o."Id" = f."MetadataObjectId"
WHERE o."Name" = 'Организации'
  AND (f."Name" ILIKE '%банк%' OR f."Name" ILIKE '%расчетн%'
       OR f."DbColumnName" IN ('bank_name', 'bank_account'));
```

Если строк нет: удалить `ShouldStoreReferenceDisplayValue` (1516–1523) и заменить тернарник в
`ReadFieldValue` (1610–1615) на

```csharp
return referencePicker.SelectedReferenceItem?.Id.ToString() ?? string.Empty;
```

### Этап 3. Косметика XAML

Убрать `x:Name="SaveButton"`, `x:Name="CancelButton"`, `x:Name="ExtraBlockTitle"` — либо
использовать первые два для защиты от двойного нажатия «Сохранить».

### Этап 4. Профилактика

Добавить `.editorconfig` с `dotnet_diagnostic.IDE0051.severity = warning`
(неиспользуемые `private`-члены) и `IDE0052` (неиспользуемые закрытые поля) — тогда мёртвый код
виден в сборке, а не только при чтении файла.

## 8. Долг рядом (не мёртвый код, но обнаружился при разборе)

1. **Дублирование `IsAsciiDigits`** — своя копия в `CatalogItemDialog` (1110) и в
   `Views/AccountPickerControlFactory.cs`. Стоит вынести в один helper, чтобы правила ввода цифр
   не разъезжались.
2. **Дублирование нормализации модуля** — `NormalizeChartOfAccountsChoice`/`NormalizeClosingModuleChoice`
   (524, 1525) и `GetFoxClosingModuleChoices` (590) повторяют карту из
   `ChartOfAccountsSelectionMetadata.NormalizeModuleKey`. Лучше переиспользовать сервис: иначе новое
   значение модуля добавят в одном месте и забудут в другом.
3. **Устаревшее сравнение по имени** — `IsInventoryEntryCatalog` (1423) ищет имя «Вид операции ТМЗ»,
   хотя в базах каталог называется «Ввод нового документа ТМЗ»; работает только благодаря проверке
   `TableName`. Стоит оставить сравнение по таблице (или обновить константу имени).
4. **Несимметричный UX** — у «Ввода нового документа ТМЗ» есть выпадающие списки «Документ ТМЗ» и
   «Вид движения», а у «Ввода нового документа ОС» поля «Документ ОС»/«Вид движения» — обычный
   текст. Не мёртвый код, но тот же приём стоит перенести.
5. **Публичное `ItemData` без защиты** — диалог отдаёт «сырой» словарь; при удалении полей из
   метаданных ключи-сироты останутся. На будущее — отдавать снимок только по существующим полям.
