# Форматный макет: многоуровневая шапка, поворот текста, бланк СТ-1

Документ описывает разделение макетов на два вида и средства, добавленные
для печатных бланков. Разобран живой пример — **счёт-фактура по форме СТ-1**.

Выполнено в версии **1.1.298**.

---

## 1. Зачем разделять макеты

Отчёты бывают двух разных природ, и собирать их одним набором средств неудобно.

| Что это | Пример | Что нужно |
| --- | --- | --- |
**Список** | Журнал счет-фактур, реестр, ведомость | Одна строка шапки, ровные колонки |
**Бланк** | Счёт-фактура (СТ-1), накладная | Несколько уровней шапки, объединения, вертикальные подписи графов |

**Бланк нельзя собрать средствами списка:** в нём шапка двух- и трёхуровневая,
подписи графов стоят вертикально, а ячейки объединяются и по горизонтали,
и по вертикали.

## 2. Вид макета — во вкладке «Общие»

```
Способ макета:  [ClosedXML — визуальный Excel ▾]
Вид макета:     (•) Простой макет    ( ) Форматный макет
```

| Вид | Для чего | Что доступно |
| --- | --- | --- |
**Простой макет** | Журналы, реестры, ведомости | Одна строка шапки из заголовков колонок |
**Форматный макет** | Печатные бланки | Уровни шапки, объединения, поворот текста |

Выбор сохраняется в макете — в поле **`LayoutKind`** листа.
При «Форматном» в блоке «Таблица» появляется раздел **«Уровни шапки»**.

## 3. Что добавлено в модель

Файл `Models/ClosedXmlReportLayout.cs`.

### Вид макета

```csharp
public static class ClosedXmlLayoutKinds
{
    public const string Simple = "Simple";        // таблица с одной строкой шапки
    public const string Formatted = "Formatted";  // бланк с многоуровневой шапкой
}

// Поле листа:
public string LayoutKind { get; set; } = ClosedXmlLayoutKinds.Simple;
```

### Поворот и перенос текста

```csharp
// Ячейка текста (ClosedXmlTextCell):
public int TextRotation { get; set; }   // 0, 45, 90, 270
public bool WrapText { get; set; }

// Колонка таблицы (ClosedXmlColumn):
public int TextRotation { get; set; }   // поворот подписи колонки
```

### Уровни шапки

```csharp
public class ClosedXmlHeaderLevel
{
    public string Name { get; set; }
    public List<ClosedXmlHeaderCell> Cells { get; set; }
}

public class ClosedXmlHeaderCell
{
    public int Column { get; set; }         // с какой колонки
    public int MergeToColumn { get; set; }  // по какую включительно
    public int RowSpan { get; set; } = 1;   // сколько строк занимает
    public string Text { get; set; }        // пусто в нижнем уровне — из колонки
    public bool Bold { get; set; } = true;
    public string Align { get; set; } = "Center";
    public int TextRotation { get; set; }
    public string Fill { get; set; }
}
```

Секция таблицы:

```csharp
/// <summary>Уровни шапки сверху вниз. Пусто — шапка из одной строки.</summary>
public List<ClosedXmlHeaderLevel> HeaderLevels { get; set; } = new();

/// <summary>Высота строки шапки в пунктах.</summary>
public double HeaderRowHeight { get; set; }
```

## 4. Как рисуется шапка

### Общий расчёт размещения

Шапку рисует **один расчёт** — `BuildHeaderGrid` в `ClosedXmlReportRenderer`.
Им пользуются **и вывод в Excel, и вывод в PDF**, поэтому шапки совпадают.

Алгоритм:

| Шаг | Что делает |
| --- | --- |
Уровни | Идут по порядку: 0 — верхний |
Для каждой колонки | Хранится первая свободная строка |
Ячейка занимает | Самую верхнюю свободную строку своих колонок |
`RowSpan > 1` | Ячейка занимает столько строк вниз |
Пустая подпись в нижнем уровне | Заменяется заголовком колонки |
Лишние пустые строки | Убираются сдвигом нижних вверх |

### Excel

| Что | Как |
| --- | --- |
Объединение по колонкам | `worksheet.Range(row, from, row, to).Merge()` |
Объединение по строкам | `worksheet.Range(row, from, lastRow, to).Merge()` |
Поворот | `cell.Style.Alignment.TextRotation` |
Высота строки | `worksheet.Row(rowIndex).Height` |

### PDF

| Что | Как |
| --- | --- |
Объединение по колонкам | `cell.ColumnSpan(n)` |
Объединение по строкам | `cell.RowSpan(n)` |
**Поворот** | **Подпись рисуется средствами WPF в картинку** |

**Про поворот в PDF.** Векторного поворота текста в PDF нет, поэтому подпись
рисуется в картинку и вставляется в документ:

```csharp
context.PushTransform(new RotateTransform(angle, imageWidth / 2d, imageHeight / 2d));
context.DrawText(formatted, new Point(...));
context.Pop();
```

| Решение | Зачем |
| --- | --- |
**Кэш картинок** | Одинаковые подписи рисуются один раз |
**Ограничение высоты** | Высокая картинка иначе растянула бы строку шапки |
**Шрифт листа** | Подпись набрана тем же шрифтом, что и документ |
**Запасной путь** | Если картинку собрать не удалось — текст выводится как есть |

## 5. Бланк СТ-1

### Что создано

| Часть | Где |
| --- | --- |
**SQL-набор** | `finance.vat-invoice-st1` — 39 колонок |
**Отчёт** | `standard.finance.vat-invoice-st1` — «Счёт-фактура по форме СТ-1» |
**Макет** | `ClosedXmlLayoutTemplates.CreateVatInvoiceSt1` |

### Состав бланка

| Блок | Что в нём |
| --- | --- |
**Заголовок** | «СЧЕТ-ФАКТУРА», «по форме СТ-1 (рег. N 283 от 12.08.2026)» |
**Реквизиты** | Слева продавец, справа покупатель: наименование, ИНН, ОКПО, адрес, рег. N, расчётный счёт |
**Таблица** | 13 графов с многоуровневой шапкой |
**Подписи** | Руководитель, Главный бухгалтер |


**Все подписи графов повёрнуты на 90°** — читаются снизу вверх, как в бланке.

### Реквизиты сторон

SQL-набор отдаёт реквизиты в каждой строке — макет читает их из первой:

| Колонка набора | Что содержит |
| --- | --- |
`seller_name` | Наименование продавца |
`seller_inn_text` | «ИНН: … ОКПО: …» |
`seller_address_text` | «Адрес: …» |
`seller_reg_number` | Номер регистрационного удостоверения |
`seller_bank_text` | «Р/с: … в …» |
`buyer_name`, `buyer_inn_text`, `buyer_address_text` | Реквизиты покупателя |

**Покупатель в данных не хранится** — в счёте-фактуре есть только счёт
контрагента. Места под реквизиты покупателя подготовлены: их заполнит SQL,
когда появится источник данных контрагента.

### Порядок документов

Запрос выдаёт сначала документы **с заполненными реквизитами**: макет берёт их
из первой строки набора.

```sql
ORDER BY (CASE WHEN COALESCE(p.seller_name, '') = '' THEN 1 ELSE 0 END),
         p.doc_date DESC, p.doc_number DESC, p.line_number
```

## 7. Что не доделано

**Честно: позиционирование уровней шапки работает не идеально.**

| Что | Состояние |
| --- | --- |
**Пустая строка** между уровнями | Осталась: уровень «Ставка/Сумма» встаёт ниже, чем нужно |
**Номера графов** | Смешиваются с подписями среднего уровня в одной строке |
**Расчёт `BuildHeaderGrid`** | Даёт структурно верную, но не идеальную раскладку |

**Причина.** Алгоритм ищет для каждой ячейки первую свободную строку от начала
уровня. Когда верхний уровень перекрывает одни колонки и не перекрывает другие,
ячейки нижнего уровня встают в разные строки, и между ними появляется полоса.

**Что нужно.** Ограничить уровень его собственным диапазоном строк: уровень
занимает фиксированные строки, рассчитанные по числу уровней и их `RowSpan`.
Это отдельная задача — правка одного метода `BuildHeaderGrid`.

**Отчёт при этом работает:** шапка читается, графы подписаны, данные на месте.
Пустая полоса — оформление, а не потеря данных.

## 8. Важное замечание о правке исходников

**Файл `ClosedXmlLayoutTemplates.cs` дважды повреждался** при правке скриптами
PowerShell: `Get-Content` без `-Encoding UTF8` читает UTF-8 как ANSI,
и кириллица превращается в «РћС‚С‡РµС‚».

| Что | Как |
| --- | --- |
**Всего повреждено** | 9 строк из 839 |
**Восстановлено** | Побайтовым обратным преобразованием через Python |
**Проверка** | Скрипт `tools/show_bad.py` — ищет порчу в файле |

**Правило: исходники править только инструментом редактирования, не скриптами.**
Если правка скриптом необходима — читать и писать файл **в Python**,
а не в PowerShell.
