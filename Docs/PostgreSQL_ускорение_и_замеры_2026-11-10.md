# Удалённый PostgreSQL: открытие документов и замеры

## Что изменилось

### Карточка ТМЗ

[DynamicDocumentWorkView.xaml.cs](../Views/DynamicDocumentWorkView.xaml.cs) при просмотре и редактировании раньше читал весь журнал и искал выбранный документ в памяти.

```csharp
var rows = await metadata.GetCatalogDataAsync(_documentMetadata.Id);
var existing = rows.FirstOrDefault(row =>
    row.TryGetValue("Id", out var value) && value is Guid guid && guid == id);
```

Теперь [MetadataService.cs](../Services/MetadataService.cs) читает одну строку. Метод повторно использует преобразование колонок в имена полей и нормализацию номера документа.

```csharp
var existing = await StartupProfiler.MeasureAsync("ТМЗ: чтение карточки по Id",
    () => metadata.GetDocumentRecordAsync(_documentMetadata.Id, id));
if (existing == null)
{
    StatusText.Text = "Документ не найден. Обновите список.";
    return;
}
```

```csharp
var sql = $"SELECT * FROM {QuoteIdentifier(document.TableName)} WHERE \"Id\" = @recordId";
var rows = await ReadCatalogRowsAsync(documentId, document.TableName, document.Name,
    document.ObjectType, document.Fields, sql, recordId);
return rows.FirstOrDefault();
```

Имя таблицы берётся из метаданных и экранируется, идентификатор передаётся параметром. Удалённый другим пользователем документ больше не открывается как пустая карточка.

### Справочники карточки и журнала

Раньше получение списка справочников вызывало проверки и достройку служебных структур. Затем чтение каждого справочника снова запрашивало его метаданные по идентификатору.

```csharp
var catalogs = await metadata.GetCatalogsAsync();
var rows = await metadata.GetCatalogDataAsync(catalog.Id);
```

Для инициализации карточки и подстановки ссылок в журнале используется чтение без обслуживания структуры. При чтении строк повторно используются уже загруженные поля. Существующая сортировка справочников сохраняется.

```csharp
var catalogs = await StartupProfiler.MeasureAsync("ТМЗ: метаданные справочников",
    metadata.ReadCatalogMetadataAsync);
// После выбора справочника из catalogs
var rows = await StartupProfiler.MeasureAsync($"ТМЗ: справочник {catalog.Name}",
    () => _metadataService.ReadCatalogDataAsync(catalog));
```

Связанные файлы: [карточка ТМЗ](../Views/Dialogs/InventoryDocumentDialog.xaml.cs), [журнал документов](../Views/DynamicDocumentWorkView.xaml.cs), [чтение метаданных и строк](../Services/MetadataService.cs).

### Временные метки

Раньше общий таймер запускался при первом обращении к профилировщику около этапа миграций. Теперь он запускается после настройки системного лога. Для синхронной проверки соединения также записывается длительность.

```csharp
StartupProfiler.Mark("Вход в запуск приложения");
bool needSetup = !StartupProfiler.Measure("Проверка подключения к PostgreSQL", settings.TestConnection);
```

В журнале с категорией `Startup` появятся следующие строки:

- **До рабочего окна** — проверка PostgreSQL, показ выбора инфобазы, переключение базы и полное время окна входа. Последнее включает ручной ввод и ожидание пользователя.
- **Авторизация** — схема прав, поиск пользователя, проверка пароля и запись отметки о входе.
- **Рабочее окно** — ожидание существующей блокировки инициализации, построение дерева целиком, отдельная проверка кассовых отчётов после сообщения о пропуске посадки и отметка завершения инициализации.
- **Документы** — чтение журнала, метаданные справочников, чтение карточки ТМЗ по Id, инициализация карточки, каждый справочник ТМЗ и строки документа. Для счетов-фактур отдельно измеряются проверка проведения и чтение журнала.

[Профилировщик](../Services/StartupProfiler.cs) пишет длительность этапа и время от начала запуска. Этапы от 1000 мс выделяются предупреждением. Вложенные длительности входят в родительский этап. Запись длительности в `finally` появляется и при ошибке, поэтому об успешном завершении запуска говорит отдельная отметка.

## Как сравнить на удалённой базе

1. Запустить приложение, войти в ту же инфобазу и сравнить отметки от проверки подключения до завершения инициализации.
2. Открыть журнал ТМЗ, затем одну и ту же существующую карточку дважды. Сравнить чтение по Id, инициализацию целиком и самые долгие справочники.
3. Открыть журнал счетов-фактур и сравнить проверку проведения с чтением списка. Проверка проведения сохранена, поскольку её перенос меняет момент появления проводок.

Замеры удалённой базы до и после изменения нужно выполнить в приложении. Полные справочники карточки ТМЗ пока загружаются при открытии. По новым меткам можно определить, какой из них стоит переводить на отложенную загрузку первым.
