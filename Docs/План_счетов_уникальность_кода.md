# План счетов: запрет повторяющегося кода счёта

Документ по исправлению: в справочнике **«План счетов»** можно было добавить
второй счёт с уже существующим кодом (например, два счёта `14160000`).
Теперь код проверяется до записи — и в форме, и в сервисе сохранения.

Дата: 30.10.2026. Сборка: `1.1.809`.

---

## 1. Почему так было

У поля «Код» в метаданных стоит `IsUnique = true`, но это только **описание**
поля: `MetadataService` не проверял уникальность перед `INSERT`/`UPDATE`,
а в таблице `catalog_plan_schetov` нет уникального индекса по `code`
(он не создаётся для универсальных справочников).

В результате:

- `CatalogItemDialog` проверял только формат кода (1–8 цифр);
- `AddCatalogItemAsync` / `UpdateDynamicRecordAsync` вставляли запись без
  проверки повторов;
- в справочнике появлялись два счёта с одинаковым кодом, и проводки/отчёты
  ссылались на неоднозначный счёт.

---

## 2. Что сделано

### 2.1. Проверка в сервисе — `Services/MetadataService.cs`

Добавлен метод:

```csharp
/// <summary>
/// План счетов: код счёта должен быть уникальным. Проверяем до INSERT/UPDATE,
/// иначе в справочник попадают два счёта с одинаковым кодом, а проводки
/// и отчёты начинают ссылаться на неоднозначный счёт.
/// </summary>
private async Task EnsureChartOfAccountsCodeUniqueAsync(
    MetadataObject metadata,
    Dictionary<string, object> data,
    Guid? excludeRecordId = null)
{
    if (!string.Equals(metadata.Name, "План счетов", StringComparison.OrdinalIgnoreCase))
        return;

    var codeField = metadata.Fields.FirstOrDefault(field =>
        string.Equals(field.Name, "Код", StringComparison.OrdinalIgnoreCase) ||
        string.Equals(field.DbColumnName, "code", StringComparison.OrdinalIgnoreCase));
    if (codeField == null ||
        !TryGetFieldValue(data, codeField, out var value) ||
        value is null or DBNull)
    {
        return;
    }

    var code = value.ToString()?.Trim() ?? string.Empty;
    if (code.Length == 0)
        return;

    var sql = $@"
        SELECT ""Id""
        FROM {QuoteIdentifier(metadata.TableName)}
        WHERE LOWER(TRIM({QuoteIdentifier(codeField.DbColumnName)})) = LOWER(TRIM(@code))";
    if (excludeRecordId.HasValue)
        sql += " AND \"Id\" <> @excludeId";
    sql += " LIMIT 1;";

    {

            $"Счёт с кодом «{code}» уже существует. Укажите другой код счёта.");

```

Метод вызывается:

- в `AddCatalogItemCoreAsync` — перед вставкой новой записи справочника;
- в `CreateDynamicRecordAsync` — перед созданием записи;
- в `UpdateDynamicRecordAsync` — перед обновлением, с `recordId`,
  чтобы счёт не считался дубликатом самого себя.

Сравнение идёт по `LOWER(TRIM(code))`: регистр и случайные пробелы не создают
«новый» код.

### 2.2. Проверка в форме — `Views/CatalogItemDialog.xaml.cs`

Для нового счёта проверка выполняется **до закрытия формы**, чтобы пользователь
исправил код, а не получал ошибку после сохранения:

```csharp
private async Task<bool> ValidateChartOfAccountsCodeUniqueAsync()
{
    if (!IsChartOfAccountsCatalog() || !_isNewRecord)
        return true;

    var code = GetItemText("Код", "code").Trim();
    if (code.Length == 0)
        return true;

    var rows = await _metadataService.GetCatalogDataAsync(_catalog.Id);
    var exists = rows.Any(row =>
    {
        var value = row.GetValueOrDefault("Код") ?? row.GetValueOrDefault("code");
        return string.Equals(value?.ToString()?.Trim(), code, StringComparison.OrdinalIgnoreCase);
    });

    if (!exists)
        return true;

    MessageBox.Show(
        $"Счёт с кодом «{code}» уже существует. Укажите другой код счёта.",
        "План счетов", MessageBoxButton.OK, MessageBoxImage.Warning);

    if (_controls.TryGetValue("Код", out var control) && control is TextBox codeBox)
    {
        codeBox.Focus();
        codeBox.SelectAll();
    }

    return false;
}
```

Вызов в `OnSaveClick` после проверки формата:

```csharp
if (!ValidateChartOfAccountsCode())
    return;

if (!await ValidateChartOfAccountsCodeUniqueAsync())
    return;
```

Для редактирования форма не блокирует сохранение (у неё нет Id записи),
но сервис `UpdateDynamicRecordAsync` проверяет код с исключением текущей
записи — изменить счёт на уже существующий код нельзя.

---

## 3. Результат

- Новый счёт с существующим кодом не сохраняется: форма показывает
  «Счёт с кодом «…» уже существует» и оставляет ввод;
- при редактировании смена кода на чужой также отклоняется сервисом;
- изменение остальных реквизитов счёта без смены кода работает как раньше;
- проверка не зависит от того, откуда пришло сохранение — из карточки
  справочника, выбора счёта или другого диалога.

## 4. Проверка

- Сборка `1.1.809` — 0 ошибок.
- SQL проверки: `SELECT "Id" FROM "catalog_plan_schetov"
  WHERE LOWER(TRIM("code")) = LOWER(TRIM(@code)) LIMIT 1` — при наличии строки
  выбрасывается понятная ошибка; при обновлении добавляется `AND "Id" <> @excludeId`.
- В форме повторный код ловится до закрытия окна; в сервисе — как страховка
  для всех остальных путей сохранения.
