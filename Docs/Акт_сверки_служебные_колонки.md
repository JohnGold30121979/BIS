# «Акт сверки»: лишние колонки в сетке и их скрытие

Документ по замечанию: в «Бухгалтерская отчётность» → «Акт сверки» → «Сформировать»
в таблице после колонки **«Модуль»** видны лишние поля. Ниже — что это за поля,
зачем они нужны отчёту, почему показывались и что изменено.

Дата: 29.10.2026. Сборка: `1.1.797`.

---

## 1. Коротко

- Это **служебные колонки макета отчёта**, а не данные для пользователя.
- Они нужны для подстановки значений в печатную форму (FRX/ClosedXML):
  заголовок, период, суммы, реквизиты сторон и подписи.
- В `DataTable` они остаются — скрываются **только в экранной сетке**, поэтому
  печать и экспорт не меняются.
- Сетка скрывает колонки по списку `ServiceColumnNames`; в нём не хватало
  колонок сторон акта — поэтому они и были видны после «Модуля».
- Добавил недостающие колонки в список. Теперь в сетке остаются только
  отображаемые колонки, а всё после «Модуля» скрыто.

---

## 2. Из чего состоит таблица акта сверки

Таблицу строит `Services/ReconciliationActBuilder.cs`, метод `CreateTable()`.
Сначала идут **отображаемые** колонки, затем — **служебные** (алиасы макета):

```csharp
public static DataTable CreateTable()
{
    var table = new DataTable("Акт сверки");
    // Первыми идут дата и номер документа: так акт читается слева направо,
    // а описание операции и суммы — уже после них.
    table.Columns.Add("Дата", typeof(string));
    table.Columns.Add("N докум", typeof(string));
    table.Columns.Add("Наименование материала, вид операции", typeof(string));
    table.Columns.Add("Дебет", typeof(string));
    table.Columns.Add("Кредит", typeof(string));
    table.Columns.Add("Сумма Дт", typeof(decimal));
    table.Columns.Add("Сумма Кт", typeof(decimal));
    table.Columns.Add("Модуль", typeof(string));

    // Колонки под канонические имена макета: механизм подстановки ищет
    // значения именно в них, иначе в макете печатается текст выражения.
    AddAliasColumn(table, "operation_name", typeof(string));
    AddAliasColumn(table, "debit_account", typeof(string));
    AddAliasColumn(table, "credit_account", typeof(string));
    AddAliasColumn(table, "debit_amount", typeof(decimal));
    AddAliasColumn(table, "credit_amount", typeof(decimal));
    AddAliasColumn(table, "debit_begin", typeof(decimal));
    AddAliasColumn(table, "credit_begin", typeof(decimal));
    AddAliasColumn(table, "document_number", typeof(string));
    AddAliasColumn(table, "document_date", typeof(string));
    // Макет акта берёт дату из posting_date: значение заполняет вызывающая сторона.
    AddAliasColumn(table, "posting_date", typeof(string));
    AddAliasColumn(table, "module_code", typeof(string));
    AddAliasColumn(table, "module", typeof(string));
    AddAliasColumn(table, "report_title", typeof(string));
    AddAliasColumn(table, "report_summary", typeof(string));
    AddAliasColumn(table, "period_start", typeof(string));
    AddAliasColumn(table, "period_end", typeof(string));
    // Стороны акта: их читает блок подписей макета.
    AddAliasColumn(table, "our_organization", typeof(string));
    AddAliasColumn(table, "our_director", typeof(string));
    AddAliasColumn(table, "our_accountant", typeof(string));
    AddAliasColumn(table, "counterparty", typeof(string));
    AddAliasColumn(table, "counterparty_director", typeof(string));
    AddAliasColumn(table, "counterparty_accountant", typeof(string));
    return table;
}
```

Итого:

| Тип | Колонки |
|---|---|
| Отображаемые | Дата; N докум; Наименование материала, вид операции; Дебет; Кредит; Сумма Дт; Сумма Кт; Модуль |
| Служебные (алиасы макета) | `operation_name`, `debit_account`, `credit_account`, `debit_amount`, `credit_amount`, `debit_begin`, `credit_begin`, `document_number`, `document_date`, `posting_date`, `module_code`, `module`, `report_title`, `report_summary`, `period_start`, `period_end`, `our_organization`, `our_director`, `our_accountant`, `counterparty`, `counterparty_director`, `counterparty_accountant` |

## 3. Зачем эти колонки отчёту

### 3.1. Шапка и итог — `ApplyHeaderFields`

```csharp
/// <summary>Проставляет поля шапки макета во всех строках: их читает полоса Title.</summary>
internal static void ApplyHeaderFields(DataTable table, DateTime start, DateTime end, string summary)
{
    var periodStart = start.ToString("dd/MM/yyyy");
    var periodEnd = end.ToString("dd/MM/yyyy");

    foreach (DataRow row in table.Rows)
    {
        SetServiceValue(row, "report_title", text: "АКТ СВЕРКИ");
        SetServiceValue(row, "report_summary", text: summary);
        SetServiceValue(row, "period_start", text: periodStart);
        SetServiceValue(row, "period_end", text: periodEnd);
    }
}
```

### 3.2. Стороны и подписи — `ApplyPartyFields`

```csharp
/// <summary>
/// Проставляет стороны акта во все строки: их читает блок подписей макета.
/// </summary>
internal static void ApplyPartyFields(DataTable table, ReconciliationActParties? parties)
{
    if (parties == null)
        return;

    foreach (DataRow row in table.Rows)
    {
        SetServiceValue(row, "our_organization", text: parties.OurName);
        SetServiceValue(row, "our_director", text: parties.OurDirector);
        SetServiceValue(row, "our_accountant", text: parties.OurAccountant);
        SetServiceValue(row, "counterparty", text: parties.CounterpartyName);
        SetServiceValue(row, "counterparty_director", text: parties.CounterpartyDirector);
        SetServiceValue(row, "counterparty_accountant", text: parties.CounterpartyAccountant);
    }
}
```

### 3.3. Строки данных

`AddRow` / `AddSection` заполняют и отображаемые колонки, и алиасы
(`operation_name`, `debit_account`, `credit_account`, `debit_amount`,
`credit_amount`, `debit_begin`, `credit_begin`, `document_number`,
`document_date`, `module_code`, `module` и т. д.). По этим именам макет
подставляет значения в ячейки печатной формы; если колонки нет, в макете
печатается текст выражения вместо значения.

**Вывод:** колонки нужны именно печатному макету. Экранной сетке они не нужны.

## 4. Почему они показывались

Экранная сетка `ReportGrid` в `Views/AccountingReportsView.xaml` строит колонки
автоматически:

```xml
<DataGrid x:Name="ReportGrid" Grid.Row="2" AutoGenerateColumns="True" IsReadOnly="True"
          MouseDoubleClick="OnReportGridDoubleClick"
          AutoGeneratingColumn="OnReportGridAutoGeneratingColumn"/>
```

Лишние колонки отменяются в обработчике:

```csharp
private void OnReportGridAutoGeneratingColumn(object? sender, DataGridAutoGeneratingColumnEventArgs e)
{
    if (e.PropertyName != null && ServiceColumnNames.Contains(e.PropertyName))
        e.Cancel = true;
}
```

Список `ServiceColumnNames` в `Views/AccountingReportsView.xaml.cs` объединяет
служебные имена акта сверки, оборотно-сальдовой ведомости и оборотной
ведомости по счёту. В нём были перечислены почти все алиасы акта, **кроме
колонок сторон**:

```csharp
// Акт сверки.
"operation_name", "debit_account", "credit_account",
"debit_amount", "credit_amount", "debit_begin", "credit_begin",
"document_number", "document_date", "module",
"report_title", "report_summary", "period_start", "period_end",
```

Поэтому после «Модуля» оставались `our_organization`, `our_director`,
`our_accountant`, `counterparty`, `counterparty_director`,
`counterparty_accountant` — их и видел пользователь.

## 6. Что теперь в сетке

Только отображаемые колонки, **операция — первой**:

**Наименование материала, вид операции | Дата | N докум | Дебет | Кредит | Сумма Дт | Сумма Кт | Модуль**

Всё, что после «Модуля», скрыто.

### 6.1. Порядок колонок: операция первой

Сначала отображаемые колонки шли так:

```
Наименование материала, вид операции | Дебет | Кредит | Сумма Дт | Сумма Кт | N докум | Дата | Модуль
```

Затем был промежуточный вариант с датой и номером первыми:

```
Дата | N докум | Наименование материала, вид операции | Дебет | Кредит | Сумма Дт | Сумма Кт | Модуль
```

Теперь — так:

```
Наименование материала, вид операции | Дата | N докум | Дебет | Кредит | Сумма Дт | Сумма Кт | Модуль
```

Изменился только порядок добавления отображаемых колонок в `CreateTable()`:

```csharp
var table = new DataTable("Акт сверки");
// Первой идёт операция, затем дата и номер документа, потом суммы.
table.Columns.Add("Наименование материала, вид операции", typeof(string));
table.Columns.Add("Дата", typeof(string));
table.Columns.Add("N докум", typeof(string));
table.Columns.Add("Дебет", typeof(string));
table.Columns.Add("Кредит", typeof(string));
table.Columns.Add("Сумма Дт", typeof(decimal));
table.Columns.Add("Сумма Кт", typeof(decimal));
table.Columns.Add("Модуль", typeof(string));
```

Заполнение строк не менялось: `AddRow` пишет значения по **именам** колонок
(`row["Дата"]`, `row["N докум"]`, …), поэтому смена порядка на данные не влияет.

### 6.2. Печатный макет ClosedXML: порядок в Excel и PDF

`ClosedXmlReportRenderer` ищет значения по имени поля, но **порядок колонок
в Excel/PDF задаёт сам макет** (`ClosedXmlTableSection.Columns`), а не порядок
колонок `DataTable`. Поэтому для печати изменены `ActHeaders` и определения
колонок в `Services/ClosedXmlLayoutTemplates.cs`:

```csharp

```

**Важно: макет хранится в базе.** `EnsureStandardReportsAsync` записывает
`Reports."ClosedXmlLayout"` один раз, и на существующих базах остаётся старый
JSON — поэтому одного изменения шаблона недостаточно. Добавлены разовые шаги
`2026.10.30.01` и `2026.10.30.02` в `Services/SchemaMigrationService.cs`: они
проверяют, что порядок колонок в сохранённом макете совпадает с одним из старых
стандартных (исходный или промежуточный «дата и номер первыми»), и пересоздают
макет из нового шаблона. Пользовательскую разметку шаг не трогает.

```csharp
private static readonly string[] LegacyReconciliationActColumns =
{
    ClosedXmlLayoutTemplates.ActLabelField, "Дебет", "Кредит", "Сумма Дт",
    "Сумма Кт", "N докум", "Дата", "Модуль"
};

private static readonly string[] DateFirstReconciliationActColumns =
{
    "Дата", "N докум", ClosedXmlLayoutTemplates.ActLabelField, "Дебет",
    "Кредит", "Сумма Дт", "Сумма Кт", "Модуль"
};

private static async Task EnsureReconciliationActColumnOrderAsync(AppDbContext ctx)
{
    var report = await ctx.Reports
        .FirstOrDefaultAsync(item => item.Code == "standard.finance.reconciliation-act-closedxml");
    if (report == null || string.IsNullOrWhiteSpace(report.ClosedXmlLayout))
        return;

    var layout = ClosedXmlReportRenderer.ParseLayout(report.ClosedXmlLayout, out _);
    if (layout == null)
        return;

    var section = layout.Sheets
        .SelectMany(sheet => sheet.Blocks)
        .Where(block => string.Equals(block.Type, "TabularSection", StringComparison.OrdinalIgnoreCase))
        .Select(block => block.Table)
        .FirstOrDefault(table => table != null);
    if (section == null)
        return;

    var fields = section.Columns.Select(column => column.Field).ToArray();
    var isLegacy = fields.Length == LegacyReconciliationActColumns.Length &&
                   fields.SequenceEqual(LegacyReconciliationActColumns, StringComparer.OrdinalIgnoreCase);
    var isDateFirst = fields.Length == DateFirstReconciliationActColumns.Length &&
                      fields.SequenceEqual(DateFirstReconciliationActColumns, StringComparer.OrdinalIgnoreCase);
    if (!isLegacy && !isDateFirst)
        return;

    var updated = ClosedXmlLayoutTemplates.CreateReconciliationAct(report.Name);
    report.ClosedXmlLayout = ClosedXmlReportRenderer.SerializeLayout(updated);
    report.TemplateVersion = Math.Max(report.TemplateVersion, 2);
    report.UpdatedAt = DateTime.UtcNow;
    await ctx.SaveChangesAsync();
}
```

Новые базы сразу получают новый макет из шаблона; существующие обновляются
при первом открытии базы с этой сборкой.

Тот же порядок задан и в программном Excel/PDF (`PrintFormService.BuildReconciliationActExcel`
и `AddReconciliationPdfRow`): массив `headers`, порядок ячеек и ширины колонок
(1 — операция, 2 — дата, 3 — номер, 4–8 — остальные).

```csharp

```

```csharp

```

При этом:

- `DataTable` по-прежнему содержит все служебные колонки;
- Excel/PDF получают те же значения (`report_title`, `period_start`,
  `period_end`, `our_*`, `counterparty*`, суммы и т. д.), но в новом порядке;
- экранная сетка скрывает служебные колонки, а печатный макет — нет.

## 7. Проверка

- Сборка `1.1.797` — 0 ошибок.
- Проверка по коду: все колонки, добавляемые `CreateTable()` после
  отображаемых, входят в `ServiceColumnNames` — обработчик
  `OnReportGridAutoGeneratingColumn` их отменяет.
- Проверка макета: в локальной базе сохранённый `ClosedXmlLayout` акта имел
  старый порядок (`Наименование материала, вид операции`, `Дебет`, …, `Дата`,
  `Модуль`) — шаги миграции `2026.10.30.01`/`2026.10.30.02` пересоздают его
  с порядком «операция, дата, номер документа, затем остальные».
- Визуально: «Бухгалтерская отчётность» → «Акт сверки» → «Сформировать» —
  первой идёт «Наименование материала, вид операции», затем «Дата» и «N докум»;
  экспорт в Excel и PDF повторяет этот порядок; подписи сторон и итоги на месте.
