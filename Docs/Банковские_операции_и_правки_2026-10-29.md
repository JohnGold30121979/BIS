# «Банковские операции» и правки 29.10.2026: что изменено и полный код

Документ фиксирует пять независимых наборов изменений в рабочем дереве:

1. **Переименование разделов** «Платежное поручение» и «Расходный/Приходный КО»
   в «Банковские операции» — только дерево навигации и заголовки окон.
2. **Правки по логу партнёра за 29.10.2026** — колонки `bank_name` у организаций,
   надёжное сохранение счетов в парах, две ошибки формы ТМЗ.
3. **Числовые поля** — в «Табельный номер» и другие числовые реквизиты больше
   нельзя ввести текст (только цифры), с проверкой на сохранении.
4. **Авансовый отчёт** — панель «Организация» появляется и по счёту затрат
   со связью с организациями, а не только по флагу пары счетов.
5. **Курсы валют** — кнопка «?» в авансовых платежах открывает окно истории
   курсов; история больше не прячется фильтром `is_active`, в справочнике
   последняя строка сверху и подсвечена.

Дата: 29.10.2026. Сборка: `1.1.784`.

Связанные документы:

- `Docs/Разбор_лога_партнёра_2026-10-29.md` — разбор лога и этих правок;
- `Docs/Пары_счетов_uuid_миграция.md` — миграция ссылок и контракт значения счёта;
- `Docs/Конкуренция_и_контексты_окон.md` — изоляция окон по подключениям;
- `Docs/Задержки_запуска_и_оптимизация.md` — старт и миграции.

### 2.4. Что не менялось

| Не менялось | Почему |
|---|---|
| Метаданные «Платежное поручение», «Расходный/Приходный КО» | это имена документов, на них завязаны проводки, печать, импорт/экспорт |
| Таблицы `doc_payment_orders`, `doc_cash_orders` | внутренняя логика и данные |
| Титулы диалогов | «Платежное поручение», «Приходный/Расходный кассовый ордер» — это формы конкретных документов |
| Заголовки печатных форм, сообщений | относятся к документу, а не к разделу |
| Обработчики, SQL, права | не затрагивались |

### 2.5. Нюансы

1. **Два раздела с одинаковым названием.** Если в базе есть и платёжные поручения,
   и кассовые ордера, в дереве будет два узла «Банковские операции» с разными
   `Id`/`Type`. Если так не задумано — варианты: объединить в один раздел или
   назвать кассовые ордера «Кассовые операции».
2. **Поиск по старому названию.** Поиск в дереве смотрит `item.Name`, `Id`, `Type`
   и — если в `Tag` лежит `MetadataObject` — имя/таблицу/описание документа.
   Для платёжного поручения поиск «Платежное» по-прежнему работает; для кассовых
   ордеров в `Tag` массив документов, поэтому «КО» раздел уже не находит.
   При необходимости добавим старые имена как алиасы поиска.
3. **Заголовок вкладки** MDI берётся из `item.Name` при `NavigateTo`, поэтому
   вкладка тоже «Банковские операции»; ключ вкладки — `document:{item.Id}`, он не менялся.

```csharp
/// <summary>
/// Легаси-колонки «Банк»/«Расчётный счёт»/«БИК» в справочнике организаций.
///
/// Из метаданных эти реквизиты удалены (банки и расчётные счета ведутся
/// отдельными справочниками), но физические колонки читают печатные формы
/// и SQL-наборы отчётов. В базах, созданных после удаления полей, колонки
/// никто не создавал — отчёты падали:
/// «42703: столбец o.bank_name не существует». Держим колонки на месте.
/// </summary>
private async Task EnsureLegacyOrganizationBankColumnsAsync(MetadataObject catalog)
{
    if (string.IsNullOrWhiteSpace(catalog.TableName))
        return;

    var table = QuoteIdentifier(catalog.TableName);
    await _context.Database.ExecuteSqlRawAsync($@"
        ALTER TABLE {table} ADD COLUMN IF NOT EXISTS ""bank_name"" varchar(250);
        ALTER TABLE {table} ADD COLUMN IF NOT EXISTS ""bank_account"" varchar(100);
        ALTER TABLE {table} ADD COLUMN IF NOT EXISTS ""bic"" varchar(50);");
}
```

Почему так: SQL отчёта (`Services/ReportDataSetService.cs`) читает
`o."bank_name"`, `o."bank_account"`, `o."bic"` и для продавца, и для покупателя.
В базе, созданной после удаления этих полей из метаданных, колонок нет —
отчёт падает с `42703`. Шаг идемпотентный, выполняется при каждом открытии базы.

### 3.2. Нормализация счёта не зависит от `FieldType`

`Services/MetadataService.cs`:

```csharp
/// <summary>
/// Поле — ссылка на план счетов. Тип поля в метаданных здесь не решает:
/// в старых базах «Дебет»/«Кредит» могли остаться строковыми, а колонка
/// уже uuid. Что делать со значением, решает фактический тип колонки
/// (проверяется в NormalizeAccountReferenceValuesAsync), а этот метод
/// отвечает только на вопрос «относится ли поле к счёту».
/// </summary>
private static bool IsAccountReferenceField(MetadataField field)
{
    if (string.IsNullOrWhiteSpace(field.DbColumnName))
        return false;

    return field.ReferenceCatalog?.StartsWith("План счетов", StringComparison.OrdinalIgnoreCase) == true ||
           AccountAnalyticsRules.IsAccountSelectorField(field);
}
```

Было (до правки) — дополнительно требовался `FieldType = "Reference"`:

```csharp
if (!string.Equals(field.FieldType, "Reference", StringComparison.OrdinalIgnoreCase))
    return false;
```

Полный метод, в котором это используется, — чтобы видно было, как принимается решение:

```csharp
private async Task NormalizeAccountReferenceValuesAsync(
    MetadataObject metadata,
    Dictionary<string, object> data,
    IReadOnlyDictionary<string, string>? columnTypes = null)
{
    if (data == null || string.IsNullOrWhiteSpace(metadata.TableName))
        return;

    var accountFields = metadata.Fields
        .Where(IsAccountReferenceField)
        .ToList();
    if (accountFields.Count == 0)
        return;

    columnTypes ??= await LoadColumnTypesAsync(metadata.TableName);
    if (columnTypes.Count == 0)
        return;

    var pending = new List<(MetadataField Field, string Code)>();
    var codes = new List<string>();

    foreach (var field in accountFields)
    {
        if (!columnTypes.TryGetValue(field.DbColumnName, out var columnType) ||
            !string.Equals(columnType, "uuid", StringComparison.OrdinalIgnoreCase))
        {
            continue;
        }

        if (!TryGetFieldValue(data, field, out var rawValue) || rawValue is null or DBNull)
            continue;

        if (rawValue is Guid)
        {
            // Уже Id ссылки — приводить нечего.
            continue;
        }

        var text = rawValue.ToString()?.Trim() ?? string.Empty;
        if (text.Length == 0 || Guid.TryParse(text, out _))
            continue;

        var code = NormalizeAccountCodeText(text);
        if (code.Length == 0)
            continue;

        pending.Add((field, code));
        if (!codes.Contains(code, StringComparer.OrdinalIgnoreCase))
            codes.Add(code);
    }

    if (pending.Count == 0)
        return;

    var idsByCode = await LoadChartOfAccountIdsByCodeAsync(codes);

    foreach (var (field, code) in pending)
    {
        if (!idsByCode.TryGetValue(code, out var accountId))
        {
            throw new InvalidOperationException(
                $"Счет «{code}» не найден в плане счетов (поле «{field.Name}»). " +
                "Выберите счёт из плана счетов и сохраните запись повторно.");
        }

        data[field.Name] = accountId;
    }
}
```

private object? ResolveReference(string column, string text)
{
    if (!_rowsByColumn.TryGetValue(column, out var rows))

    var code = text.Split(" - ")[0].Trim();

/// <summary>
/// «Табельный номер» — целое число: только цифры, без пробелов и букв.
/// В метаданных поле помечено как String (исторически), поэтому
/// ограничение ставится в самой форме; на сохранении есть ещё проверка.
/// </summary>
private void ConfigurePersonnelNumberInput()
{
    txtPersonnelNumber.MaxLength = 10; // int — до 10 цифр
    txtPersonnelNumber.ToolTip = "Только цифры, целое число";

    txtPersonnelNumber.PreviewTextInput += (_, args) => args.Handled = !IsAsciiDigits(args.Text);
    txtPersonnelNumber.PreviewKeyDown += (_, args) =>
    {
        if (args.Key == Key.Space)
            args.Handled = true;
    };

    DataObject.AddPastingHandler(txtPersonnelNumber, (_, args) =>
    {
        if (!args.SourceDataObject.GetDataPresent(DataFormats.UnicodeText, true))
        {
            args.CancelCommand();
            return;
        }

        var text = args.SourceDataObject.GetData(DataFormats.UnicodeText) as string ?? string.Empty;
        if (!IsAsciiDigits(text))
            args.CancelCommand();
    });
}

private static bool IsAsciiDigits(string? text)
{
    if (string.IsNullOrEmpty(text))
        return true;

    foreach (var character in text)
    {
        if (character is < '0' or > '9')
            return false;
    }

    return true;
}

### 4.4. Почему тип в метаданных оставлен `String`

В существующих базах колонка `personnel_number` — `varchar`, и там могут быть
пустые строки и ранее введённый текст. Если объявить поле `Int`, экран справочника
(`CatalogDataView` строит `DataTable` с типом колонки по метаданным) споткнётся
на пустых/текстовых значениях. Поэтому:

- ограничение и проверка сделаны на уровне формы — для старых и новых баз одинаково;
- при необходимости числовой колонки в БД нужна отдельная миграция: сначала
  почистить/заполнить значения, затем `ALTER COLUMN … TYPE integer USING …`.
