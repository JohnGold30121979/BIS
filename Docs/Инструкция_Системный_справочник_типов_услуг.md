# Инструкция: системный справочник «Справочник типов услуг» (модуль «Абонентский отдел»)

Документ описывает **системный** справочник — тот, который описан в коде и **сам разворачивается
в базе** при старте: объект метаданных, таблица, поля и стартовые записи. Пользовательские
справочники (созданные в конфигураторе) — другая история, см.
[Инструкция_Справочник_типов_услуг.md](<Docs/Инструкция_Справочник_типов_услуг.md>).

Для кого: разработчик продукта. Итог — изменения в 5 файлах, без ручных SQL-скриптов на клиентских
базах.

---

## 1. Что должно получиться

| Что | Значение |
|---|---|
| Объект метаданных | `Справочник типов услуг`, `ObjectType = Catalog`, `IsSystem = true` |
| Таблица | `catalog_service_types` |
| Поле 1 | `Код` → `code`, String(20), обязательное, уникальное, `Order = 1` |
| Поле 2 | `Тип услуги` → `service_type`, String(200), обязательное, `Order = 2` |
| Стартовые записи | `1` — Холодное водоснабжение, `2` — Канализация, `3` — Отопление |
| Модуль | «Абонентский отдел», код `abonent`, порядок 90, включён |
| Навигация | «СПРАВОЧНИКИ» → «Справочник типов услуг» и «АБОНЕНТСКИЙ ОТДЕЛ» → «Справочники» |
| Порядок каталога (`Order`) | 41 (в типовой базе максимум 40 — «Настройки XML ЭСФ») |

## 2. Как это разворачивается само (механизм)

```
старт приложения / открытие информационной базы
        │
        ├── RuntimeSchemaFixService.EnsureAsync()            ← достраивает колонки по метаданным
        │
        ├── MetadataService.InitializePredefinedCatalogsAsync(infoBaseId)
        │       ├── existingCatalogs = SELECT Name FROM MetadataObjects WHERE ObjectType='Catalog'
        │       ├── if (!existingCatalogs.Contains("Справочник типов услуг"))
        │       │        CreateServiceTypesCatalog(config)
        │       │            ├── INSERT MetadataObjects          (объект + поля в _context)
        │       │            ├── SaveChangesAsync                (строки метаданных в БД)
        │       │            ├── CreateTableForCatalogAsync      (CREATE TABLE из полей)
        │       │            └── AddServiceTypesDataToTable      (3 стартовые записи)
        │       ├── EnsureServiceTypesCatalogStructureAsync()    ← догон полей в существующих базах
        │       └── EnsureAbonentModuleCatalogsAsync()    ← модуль (если нет) + привязка, на каждом старте
        │
        ├── ModuleMetadataService.EnsureDefaultModulesAsync()   (на новой базе / из конфигуратора)
        │       ├── EnsureModuleAsync("abonent", "Абонентский отдел", …)
        │       ├── SynchronizeDefaultAssignmentsAsync()         ← привязка состава (только «пустая» база)
        │       └── EnsureAbonentModuleCatalogsAsync()    ← та же привязка, идемпотентно
        │
        └── MainWorkWindow.BuildNavigationTree()                 ← дерево строится из этих метаданных
```

Почему так:

* **`existingCatalogs` — имя, а не Id.** Поэтому новый системный справочник получат и новые,
  и уже существующие базы: у них этого имени в списке нет — сработает создание.
* **`CreateTableForCatalogAsync`** строит `CREATE TABLE` из `catalog.Fields`:
  `String → varchar(Length)`, `Decimal → numeric(Precision,Scale)`, `Reference → uuid`,
  плюс `"Id" uuid`, `"CreatedAt"`, `"UpdatedAt"`.
* **`Ensure…`** нужен на будущее: когда вы добавите поле к уже существующему справочнику,
  он добавит и `MetadataField`, и колонку (`AddColumnToTableAsync`).
* **Схема самовосстанавливается:** при старте `MetadataSchemaRepairService` добавит колонку,
  если поле описано в метаданных, а колонки нет (только добавление, ничего не удаляет).
* **Дерево навигации и окно карточки универсальны:** как только справочник есть в
  `MetadataObjects`, он появляется в разделе «СПРАВОЧНИКИ», а «Добавить/Редактировать»
  открывает универсальный `CatalogItemDialog` — отдельный код под справочник не нужен.

## 3. Где менять (карта правок)

| Файл | Что добавить | Зачем |
|---|---|---|
| `Services/InitialDataProvider.cs` | `SeedServiceType` + `GetServiceTypes()` | стартовые данные отдельно от логики |
| `Services/MetadataService.Fields.cs` | `GetServiceTypeFields(...)` | описание полей |
| `Services/MetadataService.Catalogs.cs` | `CreateServiceTypesCatalog(config)`, `EnsureServiceTypesCatalogStructureAsync()` | создание и догон |
| `Services/MetadataService.DataSeed.cs` | `AddServiceTypesDataToTable(catalog)` | запись стартовых строк |
| `Services/MetadataService.cs` | 2 строки в `InitializePredefinedCatalogsAsync` | точка развёртывания |
| `Services/ModuleMetadataService.cs` | константа кода, `EnsureModuleAsync`, массив имён, `EnsureAbonentModuleCatalogsAsync` | модуль и привязка |

Все методы — в том же `partial class MetadataService` / `ModuleMetadataService`, поэтому
`CreateTableForCatalogAsync`, `AddColumnToTableAsync`, `AssignMissingByNameAsync` доступны.

### Шаг 3. Создание справочника — `Services/MetadataService.Catalogs.cs`

Рядом с `CreateMaterialTypesCatalog` (строка 138):

```csharp
        /// <summary>
        /// Системный справочник «Справочник типов услуг» (модуль «Абонентский отдел»).
        /// Создаётся один раз на базу: объект метаданных → таблица → стартовые записи.
        /// </summary>
        private async Task CreateServiceTypesCatalog(MetadataConfiguration config)
        {
            try
            {
                var catalog = new MetadataObject
                {
                    Id = Guid.NewGuid(),
                    Name = "Справочник типов услуг",
                    TableName = "catalog_service_types",
                    ObjectType = "Catalog",
                    Description = "Типы услуг абонентского отдела: водоснабжение, канализация, отопление",
                    Icon = "🚿",
                    Order = 41,                       // после «Настроек XML ЭСФ» (40)
                    IsSystem = true,                  // системный: из конфигуратора не удаляется
                    MetadataConfigId = config.Id,
                    Fields = GetServiceTypeFields(Guid.NewGuid())
                };

                await _context.MetadataObjects.AddAsync(catalog);
                // Метаданные сохраняем ДО создания таблицы: поля должны уже иметь Id и FK.
                await _context.SaveChangesAsync();
                await CreateTableForCatalogAsync(catalog);
                await AddServiceTypesDataToTable(catalog);

                System.Diagnostics.Debug.WriteLine("Справочник 'Типы услуг' создан");
            }
            catch (Exception ex)
            {
                // В этом месте ошибка не пробрасывается: при отладке смотрите Debug/журнал.
                System.Diagnostics.Debug.WriteLine($"Ошибка создания справочника 'Типы услуг': {ex.Message}");
                throw;
            }
        }
```

> `throw;` внутри `catch` — намеренное отличие от старых методов: развёртывание нового
> справочника не должно «тихо» пропадать. Если хотите вести себя как весь остальной код —
> уберите `throw;` (тогда ошибка останется только в Debug-выводе).

> `Fields = GetServiceTypeFields(Guid.NewGuid())` — так во всех соседних методах: EF при
> добавлении объекта сам проставит `MetadataObjectId` полям из навигации.

### Шаг 4. Стартовые записи — `Services/MetadataService.DataSeed.cs`

Рядом с `AddMaterialTypesDataToTable` (строка 457):

```csharp
        /// <summary>
        /// Стартовые записи «Справочника типов услуг». Вызывается сразу после создания
        /// таблицы, поэтому таблица гарантированно пустая — повторных вставок не будет.
        /// </summary>
        private async Task AddServiceTypesDataToTable(MetadataObject catalog)
        {
            var serviceTypes = InitialDataProvider.GetServiceTypes();

            foreach (var serviceType in serviceTypes)
            {
                var sql = $@"
            INSERT INTO ""{catalog.TableName}""
            (""Id"", ""code"", ""service_type"", ""CreatedAt"", ""UpdatedAt"")
            VALUES (
                '{Guid.NewGuid()}',
                '{serviceType.Code}',
                '{serviceType.Name.Replace("'", "''")}',
                NOW(),
                NOW()
            )";
                await _context.Database.ExecuteSqlRawAsync(sql);
            }

            System.Diagnostics.Debug.WriteLine($"Добавлено типов услуг: {serviceTypes.Count}");
        }
```

### Шаг 6. Догон структуры — `Services/MetadataService.Catalogs.cs`

Сразу после `CreateServiceTypesCatalog`:

```csharp
        /// <summary>
        /// Догоняет структуру «Справочника типов услуг» в уже созданных базах:
        /// недостающие поля добавляет и в метаданные, и в таблицу, а описание
        /// существующих приводит к шаблону. Нужен, когда состав полей меняется
        /// после того, как справочник уже развернулся.
        /// </summary>
        private async Task EnsureServiceTypesCatalogStructureAsync()
        {
            var catalog = await _context.MetadataObjects
                .Include(metadata => metadata.Fields)
                .FirstOrDefaultAsync(metadata =>
                    metadata.ObjectType == "Catalog" &&
                    (metadata.Name == "Справочник типов услуг" ||
                     metadata.TableName == "catalog_service_types"));

            if (catalog == null)
                return;

            // Лечим случай, когда в прошлый раз метаданные сохранились, а CREATE TABLE упал:
            // CREATE TABLE IF NOT EXISTS ничего не сломает, если таблица уже есть.
            await CreateTableForCatalogAsync(catalog);

            var existingByColumn = catalog.Fields
                .Where(field => !string.IsNullOrWhiteSpace(field.DbColumnName))
                .GroupBy(field => field.DbColumnName, StringComparer.OrdinalIgnoreCase)
                .ToDictionary(group => group.Key, group => group.First(), StringComparer.OrdinalIgnoreCase);

            foreach (var desired in GetServiceTypeFields(catalog.Id))
            {
                if (!existingByColumn.TryGetValue(desired.DbColumnName, out var existing))
                {
                    desired.Id = Guid.NewGuid();
                    desired.MetadataObjectId = catalog.Id;
                    await _context.MetadataFields.AddAsync(desired);
                    await AddColumnToTableAsync(catalog.TableName, desired);
                    catalog.Fields.Add(desired);
                    continue;
                }

                existing.Name = desired.Name;
                existing.FieldType = desired.FieldType;
                existing.Length = desired.Length;
                existing.IsRequired = desired.IsRequired;
                existing.IsUnique = desired.IsUnique;
                existing.Order = desired.Order;
            }

            await _context.SaveChangesAsync();
        }
```

**7.4. Развёртывание модуля и привязки в уже настроенных базах.** `SynchronizeDefaultAssignmentsAsync`
выполняется **только один раз** — на базе, где у системных модулей ещё нет объектов (см. комментарий
в коде). Кроме того, сама посадка документации/отчётов, которая дергает
`EnsureDefaultModulesAsync`, на уже настроенной базе может быть пропущена (seed-гейт).

Практика показала: на рабочей базе модуля «Абонентский отдел» может не быть вовсе, поэтому
метод должен **сам создавать модуль**, если его нет, и только потом привязывать каталог.
Иначе справочник появится в «СПРАВОЧНИКАХ», но не в модуле. Метод — идемпотентный и
**публичный**, чтобы вызывать его из `InitializePredefinedCatalogsAsync`:

```csharp
        /// <summary>
        /// Развёртывание модуля «Абонентский отдел» и привязка к нему его справочников
        /// (AbonentCatalogNames): «Справочник типов услуг» и «Справочник производственных
        /// участков». Автосинхронизация состава (SynchronizeDefaultAssignmentsAsync)
        /// выполняется только на «пустой» базе, а посадка документации/отчётов на настроенной
        /// базе пропускается по seed-гейту — поэтому модуль и связи досоздаются здесь,
        /// идемпотентно. Вызывается из MetadataService.InitializePredefinedCatalogsAsync
        /// при каждом старте, то есть до построения дерева навигации.
        /// </summary>
        public async Task EnsureAbonentModuleCatalogsAsync()
        {
            // На совсем новой базе таблиц модулей ещё может не быть.
            await EnsureSchemaAsync();

            var module = await _context.MetadataModules
                .FirstOrDefaultAsync(item => item.Code == AbonentModuleCode);

            if (module == null)
            {
                // Модуля ещё нет (настроенная база: EnsureDefaultModulesAsync мог не выполниться).
                await EnsureModuleAsync(
                    AbonentModuleCode, "Абонентский отдел", "Абоненты, типы услуг и производственные участки",
                    "🚿", 90, 90,
                    participatesInPeriodClose: false,
                    isActiveByDefault: true);

                module = await _context.MetadataModules
                    .FirstOrDefaultAsync(item => item.Code == AbonentModuleCode);
                if (module == null)
                    return;
            }

            var names = AbonentCatalogNames.ToHashSet(StringComparer.OrdinalIgnoreCase);
            var catalogs = (await _context.MetadataObjects.AsNoTracking()
                    .Where(item => item.ObjectType == "Catalog")
                    .ToListAsync())
                .Where(item => names.Contains(item.Name))
                .ToList();
            if (catalogs.Count == 0)
                return;

            // Индекс (ObjectType, ObjectId) уникальный: каталог может быть только в одном модуле.
            var assigned = (await _context.MetadataModuleItems.AsNoTracking()
                    .Where(item => item.ObjectType == "Catalog")
                    .ToListAsync())
                .Select(item => item.ObjectId)
                .ToHashSet();

            var order = await _context.MetadataModuleItems
                .Where(item => item.ModuleId == module.Id)
                .MaxAsync(item => (int?)item.Order) ?? 0;

            var added = 0;
            foreach (var catalog in catalogs.Where(item => !assigned.Contains(item.Id)))
            {
                await _context.MetadataModuleItems.AddAsync(new MetadataModuleItem
                {
                    ModuleId = module.Id,
                    ObjectId = catalog.Id,
                    ObjectType = "Catalog",
                    Order = ++order
                });
                added++;
            }

            if (added == 0)
                return;

            await _context.SaveChangesAsync();
            SystemLogService.Info(
                $"Модуль «{module.Name}»: привязано справочников — {added}.", nameof(ModuleMetadataService));
        }
```

**7.5. Два места вызова — обязательно оба.**

1. В `EnsureDefaultModulesCoreAsync` сразу после синхронизации состава (сработает на новой
   базе и при открытии редактора модулей):

```csharp
            await SynchronizeDefaultAssignmentsAsync();
            await EnsureAbonentModuleCatalogsAsync();
```

2. В `InitializePredefinedCatalogsAsync` — сразу после `EnsureServiceTypesCatalogStructureAsync()`
   (сработает на **каждом** старте уже настроенной базы, до построения дерева навигации):

```csharp
                if (!existingCatalogs.Contains("Справочник типов услуг"))
                    await CreateServiceTypesCatalog(config);
                await EnsureServiceTypesCatalogStructureAsync();
                await new ModuleMetadataService(_context).EnsureAbonentModuleCatalogsAsync();
```

Почему так:

| Что происходит при старте | Свежая база | Настроенная база |
|---|---|---|
| `InitializePredefinedCatalogsAsync` | создаёт каталог; модуля нет → метод **создаёт модуль** и привязку | создаёт каталог; модуль обычно уже есть → **создаётся привязка** |
| `DocumentationMetadataSeedService` / `InvoiceMetadataSeedService` | посадка идёт → `EnsureDefaultModulesAsync` → всё уже создано, повторно не дублируется | seed уже отмечен → шаг может быть пропущен |
| `BuildNavigationTree` | видит привязку | видит привязку (создана на шаге 1) |

> `EnsureDefaultModulesAsync` вызывается также при открытии редактора модулей
> (`ModuleManagementView`) и при создании базы — но полагаться на него нельзя:
> на настроенной базе он может не выполниться. Поэтому модуль создаёт именно
> `EnsureAbonentModuleCatalogsAsync`.

### 5.3. Существующая база (догон)

1. Запустите программу на рабочей базе и перезапустите ещё раз (проверка идемпотентности).
2. SQL-проверки (в базе информационной базы):

```sql
-- объект и поля (ожидается 2 строки)
SELECT f."Order", f."Name", f."DbColumnName", f."FieldType", f."Length",
       f."IsRequired", f."IsUnique"
FROM "MetadataFields" f
JOIN "MetadataObjects" o ON o."Id" = f."MetadataObjectId"
WHERE o."TableName" = 'catalog_service_types'
ORDER BY f."Order";

-- привязка к модулю (ожидается 1 строка, модуль включён)
SELECT m."Name", m."IsActive", i."ObjectType", i."Order"
FROM "MetadataModuleItems" i
JOIN "MetadataModules" m ON m."Id" = i."ModuleId"
JOIN "MetadataObjects" o ON o."Id" = i."ObjectId"
WHERE o."TableName" = 'catalog_service_types';

-- данные (ожидается 3 строки)
SELECT "code", "service_type" FROM "catalog_service_types" ORDER BY "code";

-- колонки таблицы (обе varchar, "Id"/"CreatedAt"/"UpdatedAt")
SELECT column_name, data_type, character_maximum_length
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'catalog_service_types'
ORDER BY ordinal_position;
```

3. Повторный запуск не должен добавлять ни полей, ни записей, ни второго модуля/привязки.

## 6. Откат

1. Откатить код: `git revert <коммит>` (или удалить добавленные методы и строки вызова).
2. Развёрнутые данные в базе кодом не удаляются (удаление системных сущностей не
   автоматизировано). Если нужно убрать и их — выполнить в базе информационной базы:

```sql
BEGIN;

DELETE FROM "MetadataModuleItems"
 WHERE "ObjectType" = 'Catalog'
   AND "ObjectId" IN (SELECT "Id" FROM "MetadataObjects" WHERE "TableName" = 'catalog_service_types');

DELETE FROM "MetadataFields"
 WHERE "MetadataObjectId" IN (SELECT "Id" FROM "MetadataObjects" WHERE "TableName" = 'catalog_service_types');

DELETE FROM "MetadataObjects" WHERE "TableName" = 'catalog_service_types';
DROP TABLE IF EXISTS "catalog_service_types";

-- модуль — только если он не нужен другим справочникам
DELETE FROM "MetadataModuleItems"
 WHERE "ModuleId" IN (SELECT "Id" FROM "MetadataModules" WHERE "Code" = 'abonent');
DELETE FROM "MetadataModules" WHERE "Code" = 'abonent' AND "IsSystem" = false;

COMMIT;
```

## 8. Грабли

| Ситуация | Причина | Что делать |
|---|---|---|
| Справочник не появился | в `catch` метода создания ошибка, а она только в Debug-выводе | смотреть вывод отладки/журнал; в этой инструкции стоит `throw;` — не убирайте его до первой успешной проверки |
| Справочник не появился после добавления кода | не совпало имя в `existingCatalogs.Contains(...)` и `Name` (в т. ч. «ё», регистр) | имена должны совпадать посимвольно |
| Таблица создалась, но без колонки | поле добавили позже, `Ensure` не вызван | вызвать `EnsureServiceTypesCatalogStructureAsync()` или перезапустить приложение — `MetadataSchemaRepairService` добавит колонку по метаданным |
| Метаданные есть, таблицы нет | `SaveChangesAsync` прошёл, `CREATE TABLE` упал, ошибка проглочена | перезапустить: `Ensure` вызывает `CreateTableForCatalogAsync` (`IF NOT EXISTS`) и создаст таблицу; либо удалить строки `MetadataObjects`/`MetadataFields` и дать коду создать справочник заново |
| В модуле справочника нет | автосинхронизация выполняется только на «пустой» базе | оставить `EnsureAbonentModuleCatalogsAsync` и её вызов из `InitializePredefinedCatalogsAsync` (шаги 7.4–7.5) |
| Модуля «Абонентский отдел» нет в дереве вовсе | на настроенной базе `EnsureDefaultModulesAsync` может не выполниться (seed-гейт) | метод должен сам создавать модуль через `EnsureModuleAsync` (шаг 7.4), а не только привязывать каталог |
| Модуль создан, но пустой (каталога в нём нет) | каталог создан позже модуля, а привязка не выполнялась | тот же `EnsureAbonentModuleCatalogsAsync` — он идемпотентно проверяет связь каждую загрузку |
| Модуль не виден в дереве | `isActiveByDefault: false` или модуль выключили в конфигураторе | включить «Доступен в инфобазе» |
| Две записи «Абонентский отдел» | модуль уже создали руками с другим кодом | привести код к `abonent` или переименовать ручной модуль; `EnsureModuleAsync` ищет по коду |
| Справочник нельзя удалить в конфигураторе | `IsSystem = true` | так и задумано для системного |
| Записи задвоились | `AddServiceTypesDataToTable` вызван повторно (например, из `Ensure`) | сид держать только в `Create…`, либо проверять пустоту таблицы перед вставкой |
| «Код» пользователь изменить не может | автогенерация для поля с именем «Код» | штатное поведение; если нужен ручной код — назовите поле иначе (например «Шифр») |
| Порядок каталога «прыгает» | `Order` совпал с другим каталогом | свободные значения начинаются с 41 |
