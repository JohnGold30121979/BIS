# Список отчётов в «Бухгалтерской отчётности»: отметка администратора

Документ описывает, как формируется список отчётов в окне **Бухгалтерская отчётность**,
зачем введено поле **«Показывать в бухгалтерской отчетности»** и как администратор
управляет списком без разработчика.

Выполнено в версии **1.1.388**.

---

## 1. Задача

**Было:** список отчётов в окне **жёстко зашит в разметке** — 11 пунктов в XAML.

```xml
<ComboBox x:Name="ReportTypeCombo">
    <ComboBoxItem Tag="TrialBalance">Оборотно-сальдовая ведомость</ComboBoxItem>
    <ComboBoxItem Tag="GeneralLedger">Главная книга</ComboBoxItem>
    ...
</ComboBox>
```

| Проблема | Следствие |
|---|---|
**Список в коде** | Подключить отчёт = правка XAML и `switch`, пересборка |
**8 из 11 пунктов не работали** | Пользователь видел отчёты, которых нет |
**Админ бессилен** | В конструкторе отчётов нет управления этим списком |

**Требовалось:** список должен строиться **из базы**, а администратор — сам решать,
какие отчёты в нём показывать.

**Препятствие:** в базе **не было пометки**, по которой отбирать отчёты для этого окна.
В таблице `Reports` **90 записей** — журналы склада, ведомости ОС, кассовые ордера,
платёжки. Показывать их в бухгалтерской отчётности нельзя.

**Решение:** ввести новое поле-отметку и вывести его в настройку администратора.

## 2. Что введено

### Поле в модели

**Файл:** `Models/Report.cs`

```csharp
/// <summary>
/// Показывать отчёт в списке окна «Бухгалтерская отчётность».
///
/// Отчёт попадает в список, если он активен и эта отметка стоит.
/// Администратор включает её в конструкторе отчётов.
/// </summary>
public bool ShowInAccountingReports { get; set; }
```

**По умолчанию `false`** — отчёт не появляется в окне, пока админ не отметит.

### Колонка в базе

**Файл:** `Services/RuntimeSchemaFixService.cs`

```sql
ALTER TABLE "Reports"
    ADD COLUMN IF NOT EXISTS "ShowInAccountingReports"
    boolean NOT NULL DEFAULT false;
```

**Схема правится при запуске приложения** — отдельная миграция не нужна.
Существующие базы получают колонку автоматически.

### Отметка у отчётов по умолчанию

**Файл:** `Services/MetadataService.Reports.cs`

В определение отчёта добавлен параметр:

```csharp
private sealed record StandardReportDefinition(
    ...
    bool SeedClosedXmlLayout = false,

    /// <summary>
    /// Отметить отчёт для списка окна «Бухгалтерская отчётность».
    /// Администратор может снять или поставить отметку в конструкторе.
    /// </summary>
    bool ShowInAccountingReports = false);
```

**Отмечены 4 рабочих отчёта** — у них готовый визуальный макет ClosedXML:

```csharp
SeedClosedXmlLayout: true, ShowInAccountingReports: true
```

| Код отчёта | Название | Тип |
|---|---|---|
`standard.finance.trial-balance-closedxml` | Оборотная ведомость (ClosedXML) | `TurnoverByAccount` |
`standard.finance.reconciliation-act-closedxml` | Акт сверки (ClosedXML) | `ReconciliationAct` |
`standard.finance.invoice-journal` | Журнал счет-фактур | `InvoiceJournal` |
`standard.finance.vat-invoice-st1` | Счёт-фактура по форме СТ-1 | `VatInvoiceSt1` |

**Применение при посеве:**

```csharp
if (isNewReport)
{
    report.IsActive = definition.SeedClosedXmlLayout;
    ...
    // Отметка для окна «Бухгалтерская отчётность» ставится один раз:
    // дальше администратор управляет ею в конструкторе.
    report.ShowInAccountingReports = definition.ShowInAccountingReports;
}
```

### Разовая отметка для существующих баз

**Файл:** `Services/RuntimeSchemaFixService.cs`

Посев срабатывает только для **новых** отчётов. Поэтому для уже работающих баз
добавлена разовая операция:

```csharp
private static readonly string[] DefaultAccountingReportCodes =
{
    "standard.finance.trial-balance-closedxml",
    "standard.finance.reconciliation-act-closedxml",
    "standard.finance.invoice-journal",
    "standard.finance.vat-invoice-st1"
};

private async Task MarkAccountingReportsOnceAsync()
{
    // Выполняется только тогда, когда ни один отчёт ещё не отмечен.
    var anyMarked = await _context.Reports
        .AsNoTracking()
        .AnyAsync(report => report.ShowInAccountingReports);

    if (anyMarked)
        return;

    await _context.Reports
        .Where(report => DefaultAccountingReportCodes.Contains(report.Code))
        .ExecuteUpdateAsync(setters => setters
            .SetProperty(report => report.ShowInAccountingReports, true)
            .SetProperty(report => report.IsActive, true));
}
```

**Ключевое свойство: операция идемпотентна.** Она срабатывает **один раз** — пока
ни один отчёт не отмечен. Как только администратор что-то изменил, повторный запуск
приложения **его выбор не перетирает**.

## 3. Настройка для администратора

### Где

**Конструктор отчётов** → вкладка **📋 Общие** → блок флагов отчёта.

```
☑ Отчет доступен
☑ Показывать в бухгалтерской отчетности      ← НОВЫЙ ФЛАГ
☐ Печатная форма документа
☐ По умолчанию
```

### Подсказка при наведении

> Отчет появится в списке окна «Бухгалтерская отчетность».
> Нужен сохраненный ClosedXML-макет.

### Код конструктора

**Файл:** `Views/ReportDesignerWindow.xaml`

```xml
<CheckBox x:Name="ShowInAccountingReportsCheck"
          Content="Показывать в бухгалтерской отчетности"
          ToolTip="Отчет появится в списке окна «Бухгалтерская отчетность».
                   Нужен сохраненный ClosedXML-макет."/>
```

**Чтение при открытии отчёта:**

```csharp
ShowInAccountingReportsCheck.IsChecked = report.ShowInAccountingReports;
```

**Запись при сохранении — в двух местах:**

```csharp
// Сохранение отчёта
ShowInAccountingReports = ShowInAccountingReportsCheck.IsChecked ?? false,

// Правка текущего отчёта
_currentReport.ShowInAccountingReports = ShowInAccountingReportsCheck.IsChecked ?? false;
```

## 4. Как строится список

### Разметка — пустой список

**Файл:** `Views/AccountingReportsView.xaml`

```xml
<!-- Список отчётов берётся из базы: Reports, где ShowInAccountingReports.
     Отметка ставится в конструкторе отчётов. -->
<ComboBox x:Name="ReportTypeCombo" Width="280" Height="32"
          DisplayMemberPath="DisplayName"
          SelectionChanged="OnReportTypeSelectionChanged"
          ToolTip="Показываются отчёты, отмеченные в конструкторе как
                   «Показывать в бухгалтерской отчетности»."/>
```

**Ни одного пункта в разметке. Хардкод-список удалён.**

### Загрузка из базы

**Файл:** `Views/AccountingReportsView.xaml.cs`

```csharp
var reports = await _context.Reports.AsNoTracking()
    .Where(report => report.IsActive && report.ShowInAccountingReports)
    .OrderBy(report => report.Order)
    .ThenBy(report => report.Name)
    .Select(report => new { report.Id, report.Code, report.Name, report.ReportType })
    .ToListAsync();

ReportTypeCombo.ItemsSource = items;
ReportTypeCombo.SelectedIndex = items.Count > 0 ? 0 : -1;
```

**Отбор — два условия:**

| Условие | Поле |
|---|---|
Отчёт включён | `IsActive` |
Отмечен для окна | `ShowInAccountingReports` |

**Порядок — по `Order`, затем по названию.**

**Если ничего не отмечено**, в строке состояния появляется подсказка:

> В конструкторе отчётов не отмечен ни один отчёт для этого окна

### Полный поток

```
Reports.ShowInAccountingReports = true   (конструктор, вкладка «Общие»)
        ↓
LoadAccountingReportsAsync()             (при открытии окна)
        ↓
ReportTypeCombo.ItemsSource = отчёты из базы
        ↓
Пользователь выбирает отчёт
        ↓
BuildSelectedAccountingReportAsync()     (маршрут по ReportType)
        ↓
набор данных + ClosedXmlLayout из базы
        ↓
таблица → грид / Excel / PDF
```

## 5. Маршрутизация по типу отчёта

**Ключ маршрута — поле `ReportType` отчёта из базы**, а не пункт списка.

```csharp
private async Task<(DataTable, Report)> BuildSelectedAccountingReportAsync(
    AccountingReportItem selected, DateTime start, DateTime end)
{
    if (IsReconciliationType(selected.ReportType))
        return await BuildOrganizationReconciliationAsync(start, end, closedXml: true);

    if (IsTurnoverType(selected.ReportType))
        return await BuildTurnoverStatementAsync(start, end);

    return await BuildClosedXmlReportByCodeAsync(selected.Code, start, end);
}
```

### Набор данных подбирается по типу

```csharp
private static string ResolveDataSetCodeForReport(string? reportType)
{
    if (string.Equals(reportType, "InvoiceJournal", ...))
        return ReportDataSetService.InvoiceJournalDataSetCode;

    if (string.Equals(reportType, "VatInvoiceSt1", ...))
        return ReportDataSetService.VatInvoiceSt1DataSetCode;

    if (IsReconciliationType(reportType))
        return SystemReportCalculators.ReconciliationActCode;

    // Ведомость по счёту и прочие табличные отчёты — движения по проводкам.
    return SystemReportCalculators.MovementsCode;
}
```

| Тип отчёта | Набор данных | Что даёт |
|---|---|---|
`ReconciliationAct` | `system.reconciliation-act` | Акт сверки |
`TurnoverByAccount` | `system.movements` | Проводки по счёту |
`InvoiceJournal` | `finance.invoice-journal` | Счёт-фактуры |
`VatInvoiceSt1` | `finance.vat-invoice-st1` | Позиции бланка СТ-1 |

### Показ панелей по типу

```csharp
var isReconciliation = selected != null && IsReconciliationType(selected.ReportType);
var isTurnover = selected != null && IsTurnoverType(selected.ReportType);

// Панель акта сверки
ClosedXmlReconciliationPanel.Visibility = isReconciliation ? Visible : Collapsed;

// Панель ведомости и фильтр по счёту
TrialBalanceClosedXmlPanel.Visibility = isTurnover ? Visible : Collapsed;
TrialBalanceFilterPanel.Visibility = isTurnover ? Visible : Collapsed;
```

**Фильтр «Счет» показывается только у ведомости** — акту сверки он не нужен.

## 6. **Важно: колонка — это контракт**

**Главное правило при подключении отчёта.**

Макет обращается к данным **по именам колонок**. Если набор отдаёт колонку
под другим именем, **колонка молча исчезает** — без ошибки, без предупреждения.

**Так была сломана «Оборотная ведомость (ClosedXML)»:**

| Макет ждал | Код давал | Совпало |
|---|---|---|
`posting_date` | `Счет` | ❌ |
`doc_number` | `Наименование` | ❌ |
`counter_account_code` | `Сальдо на начало Дт` | ❌ |
`debit_amount` | `Оборот Дт` | ❌ |
`credit_amount` | `Оборот Кт` | ❌ |
... | ... | **0 из 10** |

**Причина:** отчёт строил таблицу **сальдо**, а макет ждал **движения**.
Результат — пустой отчёт.

**Исправление:** данные берутся из `system.movements` — того самого набора,
чьи колонки ждёт макет.

**Проверка перед подключением отчёта:**

```csharp
foreach (var column in layout.Sheets[0].Blocks
             .First(b => b.Table != null).Table!.Columns)
{
    if (!table.Columns.Contains(column.Field))
        // колонка не появится в отчёте
}
```

## 8. Порядок для администратора

**Подключить отчёт в окно «Бухгалтерская отчётность»:**

| Шаг | Действие |
|---|---|
**1** | Открыть **Конструктор отчётов** |
**2** | Выбрать отчёт или создать новый |
**3** | Вкладка **📋 Общие** → поставить галку **«Показывать в бухгалтерской отчетности»** |
**4** | Собрать макет на вкладке **📊 ClosedXML макет** |
**5** | Убедиться, что **имена колонок макета совпадают** с колонками набора данных |
**6** | **Сохранить** |
**7** | Открыть **Бухгалтерская отчётность** — отчёт в списке |

**Убрать отчёт из списка:** снять галку и сохранить.

**Пересборка не нужна.**

## 9. Что осталось

| Вопрос | Состояние |
|---|---|
**Проверка из окна** | Список и колонки проверены на данных. **Нажатия кнопок в окне не проверял** |
**Разовая отметка** | Срабатывает один раз. Дальше отметками управляет только администратор |
**Дубли отчётов в базе** | Три «Ведомость основных средств» с одним кодом `standard.metadata.fixed.assets.statement`. На этот список не влияют — отмечены другие |
**Отбор по модулю** | Список не фильтруется по модулю. Все отмеченные отчёты видны в одном окне |
**Права доступа** | Отдельных прав на отметку нет: кто открыл конструктор, тот и меняет |
