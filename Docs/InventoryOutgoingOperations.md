# Выбытие ТМЗ. Что меняется при выборе вида операции

В BIS.ERP **вид операции сейчас влияет на цену, расчёт себестоимости и проводки, но почти не меняет шапку формы**. «Расход в производство» и «Списание по акту» используют одинаковую форму и одинаковую схему проводок. В FoxPro реализация и расход в производство открывают разные формы с разными реквизитами.

| Вид операции | FoxPro | BIS.ERP сейчас |
| --- | --- | --- |
| **Реализация ТМЗ** | `fma1_21_09.scx` — реализация с реквизитами счёта-фактуры и налогами. Более ранний вариант — `fma1_21.scx` | В строке доступна **«Цена продажи»**. Выручка и себестоимость проводятся отдельно. В шапке остаётся общий заголовок «Поставщик» |
| **Расход в производство** | `fma1_22.scx` — расход с подбором по наличию, счётом хранения из остатка и выбором объекта основных средств для затрат на ремонт | Цена становится расчётной. Проводка использует дебет из шапки, кредит из строки и рассчитанную себестоимость. Шапка «Поставщик» и налоговый блок остаются видны. Налоги при проведении обнуляются |
| **Списание по акту** | Самостоятельную зарегистрированную форму с таким названием в проверенных исходниках не нашёл. Файл `fma1_22akt.scx` имеет заголовок «Расход в производство». ## BIS.ERP. Почему шапка не меняется

Все три операции относятся к одному типу документа `Outgoing` и одной таблице `doc_inventory_outgoing`. Виды операции различаются сохранённым `operation_kind`. [Определения видов операции](<D:/C#/BIS.ERP/BIS.ERP/Services/InventoryDocumentModel.cs:144>)

```csharp
new KindDefinition(SaleOperation, "Реализация ТМЗ", OutgoingName, "Outgoing", 4,
    "Продажа ТМЗ на сторону"),
new KindDefinition("OUTGOING_PRODUCTION", "Расход в производство", OutgoingName, "Outgoing", 5,
    "Списание ТМЗ в производство"),
new KindDefinition("OUTGOING_WRITEOFF", "Списание по акту", OutgoingName, "Outgoing", 6,
    "Списание по акту (недостача, порча)"),
```

Инициализация выбытия идёт через общие `BuildSupplierCard` и `BuildTaxCard`. Обработчик смены вида операции для выбытия меняет заголовок и доступность колонки цены. Обработчик смены шапки, который есть у поступления, на выбытие не вызывается. [Инициализация карточки](<D:/C#/BIS.ERP/BIS.ERP/Views/Dialogs/InventoryDocumentDialog.xaml.cs:162>) · [Переключение цены](<D:/C#/BIS.ERP/BIS.ERP/Views/Dialogs/InventoryDocumentDialog.xaml.cs:383>)

```csharp
private void UpdateValuationPriceColumn()
{
    var isSale = string.Equals(SelectedOperation, InventoryDocumentModel.SaleOperation, StringComparison.OrdinalIgnoreCase);
    PriceColumn.IsReadOnly = !isSale;
    PriceColumn.Header = isSale ? "Цена продажи" : "Учётная цена";
```

При реализации формируются две проводки. У остальных видов выбытия один дебет из шапки, кредит из строки и себестоимость вместо суммы продажи. [Сервис проведения](<D:/C#/BIS.ERP/BIS.ERP/Services/MetadataService.cs:2796>)

```csharp

// Сумма проводки берётся из line.InventoryCost.
```

Ещё одно расхождение касается журнала закупок и продаж. Сейчас `BalanceService` относит выбытие к продажам по имени документа. Вид операции при таком отборе не проверяется, поэтому расход и списание могут попадать в продажи. [Условие отбора](<D:/C#/BIS.ERP/BIS.ERP/Services/BalanceService.cs:303>)

## Что требуется для отдельного поведения формы

- **Реализация.** Показать покупателя, счёт расчётов, реквизиты счёта-фактуры и налогов. Сохранить редактируемую цену продажи и отдельную проводку себестоимости.
- **Расход в производство.** Показать источник списания, счёт затрат и применимую производственную аналитику. Скрыть реквизиты продажи. Выбор основного средства для ремонта подтверждён кодом FoxPro. Правила остальных объектов зависят от используемого варианта формы.
- **Списание по акту.** Добавить основание акта и счёт списания, скрыть реквизиты продажи. Отдельно определить, нужен ли выбор документа инвентаризации. Это правило BIS.ERP, поскольку точный аналог операции в проверенных исходниках FoxPro не подтверждён.
- **Журнал продаж.** Отбирать из выбытия только операцию «Реализация ТМЗ».

## Как воспроизвести текущее поведение

В журнале «Выбытие ТМЗ» откройте добавление документа и переключите по очереди все три вида операции. У реализации колонка должна называться «Цена продажи» и редактироваться. У двух остальных видов она называется «Учётная цена» и доступна для чтения. Блоки «Поставщик» и «Налоги и оплата» остаются на месте во всех трёх случаях. Это проверка, выведенная из кода. Через запущенное окно сценарий не выполнялся. Исходники приложения и база в рамках этого сравнения не менялись.
