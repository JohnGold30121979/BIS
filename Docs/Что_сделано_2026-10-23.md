## 2. Механизм миграций схемы

**Задача.** Клиентские базы отстают от кода: в них нет колонок, которые ожидает модель
(`Reports.ClosedXmlLayout`, `catalog_organizations.bank_name` и подобные). Ошибка
`42703` валила загрузку окна, дерево не строилось.

**Сделано.** `Services/SchemaMigrationService.cs` — единый механизм с журналом:

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version     text PRIMARY KEY,
    description text NOT NULL DEFAULT '',
    applied_at  timestamp with time zone NOT NULL DEFAULT now(),
    runs        integer NOT NULL DEFAULT 1
);
```

## 3. Достройка схемы и работа с подключениями

### 3.1. Снимок схемы одним запросом

`Services/DatabaseSchemaCache.cs` — читает `information_schema.columns` **один раз**
на отдельном соединении (`new NpgsqlConnection`), хранит тип, `is_nullable`
и `column_default`.

Зачем: раньше каждый сервис спрашивал схему по одной таблице, а на общем соединении EF
это ещё и падало:

```
Npgsql.NpgsqlOperationInProgressException
A command is already in progress: SELECT data_type FROM information_schema.columns …
```

Теперь команды на соединении EF не выполняются вообще — гонка невозможна по построению.

### 3.2. Достройка колонок

- `SchemaRepairService` — колонки по EF-модели (закрывает `Reports.ClosedXmlLayout`);
- `MetadataSchemaRepairService` — колонки справочников и документов по метаданным
  (закрывает `bank_name` и подобные).

Оба аддитивные: только `ADD COLUMN IF NOT EXISTS`, значения по умолчанию по типу
(`''`, `0`, `false`, `now()`); ссылочные поля — без `NOT NULL`, чтобы не подставить
фиктивный uuid и не сломать FK.

### 3.3. Правило работы с подключениями

С 23.10.2026 в проекте действует: **параллельных запросов нет, одна единица работы —
один контекст — один `await using`**. Деревья читаются последовательно, каждый набор
на своём подключении через `LoadWithIndependentConnectionAsync`.

Цена отказа от параллельности по замерам: дерево ~0,8 с вместо ~0,24 с (по VPN).

### 4.3. Что дало ускорение

| Причина | Исправление |
|---|---|
| 2–3 команды на каждое поле даже без изменений | ранний выход по `is_nullable` из снимка схемы |
| `ALTER ADD COLUMN` в цикле | один пакетный `ALTER` на таблицу |
| До 3 запросов на каждое определение отчёта | предзагрузка в память (2 запроса на этап) |
| Посадки выполнялись при каждом запуске | отметки `SeedStateService` в `schema_migrations` |
| Запрос порядка групп на каждый модуль | `GetAllNavigationGroupOrdersAsync` — один запрос |

### 4.4. Отметки посадок

`Services/SeedStateService.cs`, ключи:

```

seed.invoices.2026.10.22.1
seed.standard-reports.2026.10.22.1
```

При наличии отметки этап пропускается с записью `Посадка документации уже выполнена — пропуск.`
Отметка ставится только после успешного завершения; при изменении состава посадки
версию в константе нужно поднять.

Ожидаемое поведение: первый запуск после обновления ~15 с (посадки идут и ставят отметки),
последующие ~4–5 с.

## 5. Исправленные ошибки

| Ошибка | Причина | Исправление |
|---|---|---|
| `42703: столбец r.ClosedXmlLayout не существует` | старая таблица `Reports` | шаг 01 — достройка колонок по EF-модели |
| `42703: столбец o.bank_name не существует` | нет колонки в `catalog_organizations` | шаг 02 — достройка по метаданным |
| `42703: столбец "level" … не существует` | сид плана счетов вставлял колонку, которой нет | INSERT строится по фактическим колонкам |
| `42710: ограничение fk_…_header уже существует` | проверка искала имя без префикса `fk_` | проверка по `conname` + `conrelid` |
| `22P02: неверный синтаксис для типа integer: ""` | `SET DEFAULT ''` для числовых/логических колонок | значения по умолчанию по фактическому типу |
| `42883: оператор не существует: text = uuid` | сравнение текста с uuid в SQL набора счет-фактур | сравнение `text` с `text` |
| `NpgsqlOperationInProgressException` | команда на соединении EF | снимок схемы на отдельном соединении |

## 9. Как проверить

1. Открыть удалённую базу по VPN, посмотреть в `logs/system_<дата>.log` строки `⏱`:
   суммарное время должно быть ~4–5 с на повторном запуске.
2. Убедиться, что в логе нет `A command is already in progress`,
   `A second operation was started`, `42703`, `42710`, `22P02`.
3. Открыть журнал проводок → `📄 Предпросмотр ПДФ` и `📊 Эксель`;
   включить `☑ Выбрать форму` — должен открыться список из четырёх форм.
