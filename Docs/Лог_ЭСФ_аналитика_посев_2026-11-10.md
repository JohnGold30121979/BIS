# Ошибки из лога 10.11.2026: гонка в выгрузке ЭСФ, `line_analytics`, двойная посадка

**Дата:** 10.11.2026
**Версия сборки:** 1.1.908 (Build 908)
**Задача (как сформулировал пользователь):** «Ещё пару ошибок из лога…» — `A command is already in progress` в выгрузке ЭСФ, повтор `42703: столбец "line_analytics" не существует` и двойная строка «Посадка счетов-фактур уже выполнена — пропуск». Отдельным указанием: «Убери гонку. Создай отдельные подключения как в системе».
**Итог:** все три пункта закрыты. Схема базы **не меняется** — ни одного `ALTER`/`CREATE`: приложение спрашивает `information_schema` и подстраивает SQL.

| Что в логе | Причина | Как исправлено |
|---|---|---|
| `A command is already in progress: SELECT … MetadataObjects …` | Окно ЭСФ работало на общем `AppDbContext`; загрузка запускалась из двух мест одновременно | Отдельное подключение на каждую операцию (`CreateIsolatedContext`), как в остальной системе |
| `42703: столбец "line_analytics" не существует POSITION: 354` | SQL счетов-фактур и авансовых платежей жёстко упоминал колонку, которой в базе нет | `TableColumnProbe.HasColumnAsync` + два варианта SQL (с колонкой / без) |
| `Посадка счетов-фактур уже выполнена — пропуск.` ×2 | Пропуск логировался на каждый вызов, окна рабочего режима и конфигуратора зовут посадку обе | `SemaphoreSlim` на процесс + лог только при реальной посадке |

## 1. Гонка: «A command is already in progress» в выгрузке ЭСФ

### 1.1. Причина

[Views/EsfExportWorkView.xaml.cs](Views/EsfExportWorkView.xaml.cs) держал один `AppDbContext` и использовал его во всех запросах. Загрузку списка запускают сразу несколько событий:

```csharp
            Loaded += async (_, _) => await LoadRowsAsync();          // при открытии вкладки
            …
            private async void OnSourceChanged(object sender, RoutedEventArgs e)
            {
                if (IsLoaded)
                    await LoadRowsAsync();                             // Checked/Unchecked чекбоксов
            }
            …
            private async void OnRefreshClick(…) => await LoadRowsAsync();   // кнопка «Обновить»
```

У чекбоксов в XAML стоит `IsChecked="True"`, поэтому `Checked` срабатывает ещё при инициализации разметки. Два обработчика стартуют `LoadRowsAsync` почти одновременно, оба идут в один `AppDbContext` → одна физическая сессия Npgsql → второй запрос падает с `NpgsqlOperationInProgressException`, а EF показывает его как «A command is already in progress: SELECT … MetadataObjects …».

### 1.2. Решение — отдельное подключение на операцию

Тот же приём уже используется в системе: `SchemaMigrationService` (`new AppDbContext(connectionString)`), `MainWorkWindow.LoadWithIndependentConnectionAsync`, `InventoryDocumentLineService.OpenConnectionAsync` (своё `NpgsqlConnection`). Повторяем его в окне ЭСФ:

```csharp
        private readonly AppDbContext _context;
        private MetadataObject? _salesInvoiceDocument;
        private bool _isBulkSelectionUpdating;

        /// <summary>
        /// Отдельное подключение на операцию — как в остальной системе
        /// (SchemaMigrationService, MainWorkWindow.LoadWithIndependentConnectionAsync,
        /// InventoryDocumentLineService). Общий DbContext окна для запросов не используется:
        /// загрузка запускается сразу из двух мест (Loaded и Checked чекбоксов при
        /// инициализации XAML), а две команды на одном соединении дают
        /// NpgsqlOperationInProgressException — «A command is already in progress».
        /// </summary>
        private AppDbContext CreateIsolatedContext()
        {
            var connectionString = _context.Database.GetConnectionString();
            if (string.IsNullOrWhiteSpace(connectionString))
                throw new InvalidOperationException("Не удалось определить строку подключения инфобазы.");

            return new AppDbContext(connectionString);
        }
```

Загрузка целиком переехала на этот контекст (было — `_context`, `_metadataService`, `_salesInvoiceService`, `_exchangeService` с общим соединением):

```csharp

                // больше не делят одно соединение.

                var metadataService = new MetadataService(context);

                {
                    var document = await FindSalesInvoiceDocumentAsync(context, metadataService);
                    _salesInvoiceDocument = document;
                    if (document == null)
                    {
                        SummaryText.Text = "Документ выписки счет-фактур не найден в метаданных.";
                        StatusText.Text = "Нет документа для выгрузки ЭСФ";
                    }
                    else
                    {
                        var salesInvoiceService = new InvoiceService(context);
                        salesInvoiceService.Configure(document);
                        var invoiceModuleName = await ResolveDocumentModuleNameAsync(metadataService, document);

                        var invoices = await salesInvoiceService.GetInvoicesAsync();
                        …
                    }
                }

                if (PostingsSourceCheckBox.IsChecked == true)
                {
                    var postingService = new PostingService(context);   // тоже своё подключение
                    …
                }
```

Сигнатуры вспомогательных методов стали принимать контекст, чтобы не тянуть общий:

```csharp
        private static async Task<MetadataObject?> FindSalesInvoiceDocumentAsync(
            AppDbContext context,
            MetadataService metadataService)
        {
            var document = await context.MetadataObjects
                .AsNoTracking()
                .FirstOrDefaultAsync(item => item.ObjectType == "Document" && …);
            …
        }

        private static async Task<string> ResolveDocumentModuleNameAsync(
            MetadataService metadataService,
            MetadataObject document)
        {
            var assignedModuleName = await metadataService.GetAssignedModuleNameAsync(document.Id, document.ObjectType);
            return string.IsNullOrWhiteSpace(assignedModuleName) ? "Финансы" : assignedModuleName.Trim();

```

Выгрузка тоже получила своё подключение (раньше жила на сервисах, созданных при загрузке, — то есть на общем соединении):

```csharp
                StatusText.Text = "Формирование XML ЭСФ...";
                var invoiceIds = selectedRows.Select(row => row.InvoiceId!.Value).ToArray();

                // Отдельное подключение и на выгрузку: не делим соединение
                // с фоновой загрузкой списка (общая причина ошибки
                // «A command is already in progress»).
                await using (var context = CreateIsolatedContext())
                {
                    var salesInvoiceService = new InvoiceService(context);
                    salesInvoiceService.Configure(_salesInvoiceDocument);
                    var exchangeService = new InvoiceEsfExchangeService(context, salesInvoiceService);

                    var result = await exchangeService.ExportSelectedInvoicesAsync(
                        invoiceIds,
                        saveDialog.FileName);

                    await LoadRowsAsync();
                    StatusText.Text = $"XML выгружен: {result.ExportedCount}";
                    MessageBox.Show(…);
                }
```

Проверка готовности сервиса теперь смотрит на найденный документ, а не на сервис с общим контекстом: `if (_salesInvoiceDocument == null) { … "Сервис выгрузки ЭСФ не готов. Обновите список." }`.

Поля `_salesInvoiceService` / `_exchangeService` удалены: они держали общий `AppDbContext` и переживали загрузку, из-за чего выгрузка могла пойти на том же соединении, что и фоновая загрузка списка.

## 2. `42703: столбец "line_analytics" не существует`

### 2.1. Причина

Колонка `line_analytics` появилась позже самих таблиц строк. В базе, где её нет, падал любой запрос, который её упоминал. `POSITION: 354` указывает на список колонок в `SELECT` — по позиции это запросы **счетов-фактур** ([Services/InvoiceService.cs](Services/InvoiceService.cs)) и **авансовых платежей** ([Services/AdvancePaymentService.cs](Services/AdvancePaymentService.cs)); строки ТМЗ были закрыты ранее, в [Services/InventoryDocumentLineService.cs](Services/InventoryDocumentLineService.cs).

### 2.2. Решение — проверка колонки без изменения схемы

Новый общий помощник [Services/TableColumnProbe.cs](Services/TableColumnProbe.cs):

```csharp
    /// <summary>
    /// Проверка наличия колонки в таблице — без изменения схемы базы.
    /// … База только читается: спрашиваем information_schema и строим SQL
    /// без отсутствующей колонки. Результат кэшируется на сеанс
    /// (ключ — строка подключения + таблица + колонка).
    /// </summary>
    public static class TableColumnProbe
    {
        private static readonly Dictionary<string, bool> Cache = new(StringComparer.OrdinalIgnoreCase);
        private static readonly object CacheLock = new();

        public static async Task<bool> HasColumnAsync(
            NpgsqlConnection connection,
            string table,
            string column,
            NpgsqlTransaction? transaction = null)
        {
            var key = $"{connection.ConnectionString}|{table}|{column}";
            lock (CacheLock)
            {
                if (Cache.TryGetValue(key, out var cached))
                    return cached;
            }

            await using var command = connection.CreateCommand();
            if (transaction != null)
                command.Transaction = transaction;

            command.CommandText = @"
                SELECT EXISTS (
                    SELECT 1
                      FROM information_schema.columns
                     WHERE table_schema = 'public'
                       AND table_name = @table
                       AND column_name = @column);";
            command.Parameters.Add(new NpgsqlParameter("table", table));
            command.Parameters.Add(new NpgsqlParameter("column", column));

            var exists = await command.ExecuteScalarAsync() is true;

            lock (CacheLock)
                Cache[key] = exists;

            if (!exists)
                SystemLogService.Warning(
                    $"В таблице «{table}» нет колонки «{column}»: данные читаются и пишутся без неё, " +
                    "схема базы не изменяется.", "Схема");

            return exists;
        }
    }
```

Шаблон применения — чтение:

```csharp

            await _context.Database.OpenConnectionAsync();
            try

                …

                    ? LineAnalytics.FromJson(reader.GetString(14))
                    : new LineAnalytics()
```

и запись (параметры собираются списком, «лишний» параметр просто не добавляется):

```csharp

                    INSERT INTO ""{LinesTableName}""

                    parameters.ToArray());
```

### 2.3. Что изменено по файлам

| Файл · метод | Изменение |
|---|---|
| `Services/TableColumnProbe.cs` (новый) | Проверка колонки одним запросом к `information_schema`, кэш на сеанс, одно предупреждение в системный лог |
| `Services/InventoryDocumentLineService.cs` · `GetLinesAsync`, `ReplaceLinesAsync` | Локальная проверка заменена на общий `TableColumnProbe`; SQL с колонкой/без, `Analytics` читается через короткое замыкание |
| `Services/InvoiceService.cs` · `GetLinesAsync` | Проверка перед SELECT, соединение закрывается в `finally` (раньше при исключении оставалось открытым) |
| `Services/InvoiceService.cs` · сохранение строк | INSERT собирается с `line_analytics` только при её наличии |
| `Services/AdvancePaymentService.cs` · `GetLinesAsync`, `GetLinesForDocumentsAsync` | То же для чтения одиночного и пакетного (список/журнал документов) |
| `Services/AdvancePaymentService.cs` · `SaveLinesAsync` | INSERT с колонкой/без, параметры списком |
| `Services/AdvancePaymentService.cs` · `ReadLine` | `Analytics` читается только если `reader.FieldCount > offset + 16` — при отсутствии колонки полей меньше |

Итог: если колонки нет — документы открываются и сохраняются, аналитика строк читается пустой. Если колонка есть (в том числе добавлена вами вручную) — работает как раньше, потерь нет.

## 3. Дубли «Посадка счетов-фактур уже выполнена — пропуск»

### 3.1. Причина

`InvoiceMetadataSeedService.EnsureAsync` вызывается из двух окон — [Views/MainWorkWindow.xaml.cs](Views/MainWorkWindow.xaml.cs) и [Views/ConfiguratorWindow.xaml.cs](Views/ConfiguratorWindow.xaml.cs). Каждый вызов на уже посаженной базе писал `Info`-строку «уже выполнена — пропуск», поэтому в логе появлялись две записи подряд. Плюс два окна могли запустить посадку одновременно на одном `DbContext` — та же гонка соединения, что и в ЭСФ.

### 3.2. Решение

```csharp
        // Один прогон посадки на процесс: два окна не должны сеять одновременно.
        private static readonly SemaphoreSlim SeedGate = new(1, 1);

        public async Task EnsureAsync()
        {
            // Окно рабочего режима и окно конфигуратора живут одновременно и оба
            // зовут посадку. Без этого замка они бы писали одни и те же записи
            // на одном DbContext, а в лог летела лишняя строка «уже выполнена — пропуск».
            await SeedGate.WaitAsync();
            try
            {
                if (await SeedStateService.IsAppliedAsync(_context, SeedStateService.InvoiceKey))
                    return;                     // тихий пропуск, без записи в лог

                … посадка …

                await SeedStateService.MarkAsync(_context, SeedStateService.InvoiceKey, "Посадка счетов-фактур");
                SystemLogService.Info("Посадка счетов-фактур выполнена.", "Seed");
            }
            finally
            {
                SeedGate.Release();
            }
        }
```

Теперь в логе одна строка и только тогда, когда посадка действительно произошла.

### 4.2. Сценарии

1. «Выгрузка ЭСФ»: открыть вкладку, сразу переключить чекбоксы «Счет-фактуры» / «Проводки», нажать «Обновить» несколько раз подряд — ошибки «A command is already in progress» нет, список загружается.
2. Выгрузка XML: выделить строки, «Выгрузить» — файл формируется, список обновляется.
3. «Счета-фактуры»: открыть документ с строками, сохранить изменения — нет `42703`; в системном логе одно предупреждение «В таблице … нет колонки line_analytics…».
4. «Авансовые платежи / Платёжная ведомость»: открыть документ, посмотреть строки (в т. ч. список с колонкой строк) — ошибки нет.
5. ТМЗ: поступление/выбытие/перемещение — как раньше.
6. Перезапуск приложения и смена режима «Рабочий ↔ Конфигуратор»: в логе нет строк «Посадка счетов-фактур уже выполнена — пропуск».
