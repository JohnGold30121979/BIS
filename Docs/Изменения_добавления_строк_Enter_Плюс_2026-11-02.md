# Строки документов: добавление, ввод сумм и аналитика счетов

Дата: 02.11.2026.

Изменены формы: выписка и регистрация счет-фактур (новый документ), авансовые платежи (добавление), ТМЗ (внутреннее перемещение, выбытие, поступление).

Enter явно передаёт текст активного редактора в модель, фиксирует ячейку и строку, пересчитывает суммы и переходит по существующим ячейкам и строкам. В конце таблицы новая строка не создаётся.

Правый плюс цифровой клавиатуры (Key.Add) без модификаторов добавляет строку в конец таблицы, ниже последней строки, и переводит в неё курсор. Кнопка добавления сохранена. Коллекции используют Add; сортировка столбцов отключена для сохранения порядка на экране.

В авансовых платежах Enter уже не создавал строку; это поведение сохранено.

Проверка: dotnet build BIS.ERP.csproj --no-restore -p:SkipProductVersionBump=true -v:quiet — успешно, ошибок нет. Осталось предупреждение CS0414 в AccountingReportsView.xaml.cs, не связанное с изменениями. Интерактивная проверка интерфейса не выполнялась.

Проверка вручную для каждой формы:

1. Enter в конце последней строки не меняет количество строк.
2. Правый плюс добавляет одну строку снизу и переводит в неё курсор.
3. Правый плюс при выборе первой строки также добавляет строку в конец.
4. Проверить порядок и номера после нескольких добавлений, сохранения и повторного открытия.

## Исправление ввода и пересчёта сумм

Обновлено 02.11.2026 по замечанию о вводе сумм.

- Общий DocumentGridEditing.Commit перед навигацией по Enter и добавлением правым плюсом явно вызывает UpdateSource для активного TextBox, затем CommitEdit для ячейки и строки. Это работает и для шаблонной ячейки счет-фактуры, и для последней ячейки без перехода фокуса. При ошибке валидации переход отменяется.
- В авансовых платежах после фиксации Enter явно обновляет итог документа.
- В счет-фактуре проверка ввода теперь строит итоговый текст с учётом позиции курсора и выделения. Выделенную сумму можно заменить цифрами без предварительного удаления Backspace; разрешено редактирование целой и дробной частей. Ограничение до двух дробных знаков сохранено.
- В ТМЗ количество, цена и ставка фиксируются по Enter или выходу из ячейки. Обновление модели на каждом символе отключено. Единый DecimalInputConverter принимает точку и запятую, форматирует цену с двумя дробными знаками.

Регрессионная проверка без запуска окон: Tests/DocumentGridEditingRegression. Проверены LostFocus-binding без смены фокуса, замена выделенной суммы, уведомление модели и пересчёт итога, точка/запятая и отклонение некорректного ввода для ru-RU и en-US. Результат: PASS.

Команда проверки: dotnet run --project Tests/DocumentGridEditingRegression/DocumentGridEditingRegression.csproj -p:SkipProductVersionBump=true

Дополнительная проверка вручную в каждой форме:

1. Ввести сумму и нажать Enter: сумма строки, налоги и итог документа должны обновиться без мыши.
2. Выделить всю сумму и набрать 1234,56; нажать Enter. Повторить с 7.89.
3. Выделить часть суммы, заменить цифрами; проверить редактирование до и после запятой.
4. Проверить последнюю ячейку последней строки: Enter фиксирует ввод и расчёт, но не добавляет строку.
5. Нажать правый плюс сразу после ввода: текущее значение фиксируется, новая строка появляется внизу.

## Аналитика счёта операции в строках

Сверено с исходником FoxPro из указанного каталога fin_vpf9. Подробные источники и различия описаны в документе «Аналитика_счетов_в_строках_сверка_FoxPro_2026-11-02.md».

Для обеих счет-фактур, авансовых платежей и всех трёх документов ТМЗ добавлены колонки справочников по связям счёта конкретной строки. Они располагаются рядом со счётом; при разных счетах видны все нужные колонки, но редакторы доступны только в соответствующих строках.

В ячейке — ручной ввод точного номера/кода и соседняя кнопка «?». Значение проверяется перед сохранением; хранится идентификатор записи, код и наименование. Поддерживаются также дополнительные активные связи из настройки «Связи счетов со справочниками».

В ТМЗ сохранён штатный выбор материала, штатный участок переключается по связи счёта; дублирующие колонки не создаются. В авансовых платежах сохранён текущий механизм валюты из шапки. Аналитика счёта затрат задаётся в строке отдельно от аналитики пары счетов в шапке.

Во все таблицы строк добавляется line_analytics (text, JSON), старые строки получают пустой набор. Изменены загрузка, отображение, проверка и сохранение. Механизм Enter / правого плюса из предыдущего исправления сохранён. Полный перенос аналитики сторон проводки FoxPro в проводки и отчёты BIS.ERP в эту задачу интерфейса не включён.

Проверки: Tests/LineAnalyticsRegression — колонки по счетам, ручной ввод, разрешение и проверка кодов, сохранение идентификаторов при сериализации, смена счёта, пользовательская связь, режим просмотра, штатный участок и порядок колонок. Проверка выполняется без подключения к рабочей базе. Полный цикл с реальным PostgreSQL и открытыми окнами не выполнялся.

Результат итогового запуска Tests/LineAnalyticsRegression: PASS. Повторная проверка Tests/DocumentGridEditingRegression: PASS. Сборка основного проекта, выполняемая тестовым проектом, завершилась без ошибок. В выводе остались предупреждения CS0414 (существующее неиспользуемое поле) и NU1900 (недоступен сетевой источник аудита NuGet).

using System.Windows.Controls;
using System.Windows.Input;

namespace BIS.ERP.Behaviors
{
    /// <summary>Фиксация текста редактора до навигации по таблице документа.</summary>
    public static class DocumentGridEditing
    {
        public static bool Commit(DataGrid grid)
        {
            // В шаблонной колонке CommitEdit не обновляет LostFocus-binding:
            // TextBox остаётся в фокусе, особенно в последней ячейке таблицы.
            if (grid.IsKeyboardFocusWithin && Keyboard.FocusedElement is TextBox box)
            {
                if (!CommitText(box))
                    return false;
            }

            return grid.CommitEdit(DataGridEditingUnit.Cell, true) &&
                   grid.CommitEdit(DataGridEditingUnit.Row, true);
        }

        internal static bool CommitText(TextBox box)
        {
            box.GetBindingExpression(TextBox.TextProperty)?.UpdateSource();
            return !Validation.GetHasError(box);
        }
    }
}

        private Task<List<Dictionary<string, object>>> Lookup(AccountAnalyticsLinkDefinition definition)
        {
            if (!_lookups.TryGetValue(definition.ReferenceCatalog, out var task) || task.IsFaulted)
                _lookups[definition.ReferenceCatalog] = task = _metadata.GetCatalogDataAsync(Catalog(definition).Id);
            return task;

        private static string Read(Dictionary<string, object> row, params string[] keys) =>
            keys.Select(key => row.GetValueOrDefault(key)?.ToString()).FirstOrDefault(value => !string.IsNullOrWhiteSpace(value)) ?? string.Empty;

        private string FieldText(Dictionary<string, object> row, AccountAnalyticsLinkDefinition definition, params string[] columns)
        {
            var fields = _catalogs.FirstOrDefault(item => item.Name.Equals(definition.ReferenceCatalog, StringComparison.OrdinalIgnoreCase))?.Fields;
            foreach (var column in columns)
            {
                var field = fields?.FirstOrDefault(item => item.DbColumnName.Equals(column, StringComparison.OrdinalIgnoreCase));
                if (field != null && !string.IsNullOrWhiteSpace(Read(row, field.Name, field.DbColumnName)))
                    return Read(row, field.Name, field.DbColumnName);
            }
            return string.Empty;
        }

        {
            var code = FieldText(row, definition, "personnel_number", "code", "number", "account_number");
            return string.IsNullOrWhiteSpace(code) ? Read(row, "Табельный номер", "personnel_number", "Код", "code", "Номер", "number", "Номер лицевого счета", "Лицевой счет") : code;
        }
        private string Name(Dictionary<string, object> row, AccountAnalyticsLinkDefinition definition)
        {
            var name = FieldText(row, definition, "full_name", "name", "description");
            return string.IsNullOrWhiteSpace(name) ? Read(row, "Наименование", "name", "ФИО", "full_name", "Наименование материала", "Наименование участка") : name;
        }

        private void Select(LineAnalyticValue value, Dictionary<string, object> row, AccountAnalyticsLinkDefinition definition)
        {
            if (!Guid.TryParse(Read(row, "Id", "id"), out var id))
                throw new InvalidOperationException("У выбранной записи справочника отсутствует идентификатор.");
            value.Select(id, Code(row, definition), Name(row, definition));
        }

        private async Task<bool> ResolveAsync(LineAnalyticValue value, AccountAnalyticsLinkDefinition definition, string input)
        {
            if (!value.IsApplicable || string.IsNullOrWhiteSpace(input)) return true;
            var rows = await Lookup(definition);
            // Пользователь мог продолжить ввод или выбрать другой счёт, пока загружался справочник.
            if (!value.IsApplicable) return true;
            if (value.Text != input)
                return value.Id.HasValue || string.IsNullOrWhiteSpace(value.Text);
            var matches = rows.Where(row => value.Id.HasValue
                ? Read(row, "Id", "id").Equals(value.Id.ToString(), StringComparison.OrdinalIgnoreCase)
                : Code(row, definition).Equals(input.Trim(), StringComparison.OrdinalIgnoreCase) ||
                  Read(row, "Id", "id").Equals(input.Trim(), StringComparison.OrdinalIgnoreCase) ||
                  $"{Code(row, definition)} - {Name(row, definition)}".Equals(input.Trim(), StringComparison.OrdinalIgnoreCase)).ToList();
            if (matches.Count != 1) return false;
            Select(value, matches[0], definition);
            return true;
        }

        private async Task PickAsync(ILineAnalyticsRow row, AccountAnalyticsLinkDefinition definition)
        {
            var value = row.Analytics[definition.Code];
            if (!value.IsApplicable || _pickerOpen) return;
            _pickerOpen = true;
            try
            {
                var rows = await Lookup(definition);
                var picker = new ReferenceSelectionDialog(rows);
                picker.ConfigureCatalogEditing(Catalog(definition), _metadata);
                if (await MdiDialogService.ShowInWorkspaceForResultAsync(Window.GetWindow(_grid), picker,
                        $"Выбор: {definition.ReferenceCatalog}") == true && picker.SelectedItem != null && value.IsApplicable)
                {
                    Select(value, picker.SelectedItem, definition);
                    _lookups.Remove(definition.ReferenceCatalog);
                }
            }
            finally { _pickerOpen = false; }
        }

        public async Task ValidateAsync()
        {
            Refresh();
            var index = 0;
            foreach (var row in _rows.OfType<ILineAnalyticsRow>())
            {
                index++;
                foreach (var definition in _registry.Definitions.Where(item => _columns.ContainsKey(item.Code)))
                {
                    var value = row.Analytics[definition.Code];
                    if (!await ResolveAsync(value, definition, value.Text))
                        throw new InvalidOperationException($"Строка {index}, «{definition.ReferenceCatalog}»: укажите точный номер/код или выберите запись через «?».");
                }
            }
        }
    }

## Исправление FormatException при открытии счет-фактур

02.11.2026. В SQL подготовки схемы литерал пустого JSON после C#-интерполяции превращался в две фигурные скобки. ExecuteSqlRawAsync повторно форматирует SQL через String.Format, поэтому возникал FormatException до отправки команды в PostgreSQL.

Для обеих счет-фактур, авансов и ТМЗ введено единое значение LineAnalytics.EmptySqlDefault = (json_build_object()::text). PostgreSQL создаёт тот же пустой JSON, но текст SQL не содержит конфликтующих скобок. Данные документов не изменяются этим исправлением.

Регрессионная проверка: Tests/SqlSchemaFormatRegression. Используется реальный EF Core IRawSqlCommandBuilder: исходный дефект воспроизводится, исправленные CREATE/ALTER проходят форматирование без подключения к базе.
