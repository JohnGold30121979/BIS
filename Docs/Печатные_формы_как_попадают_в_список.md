# Как отчёты попадают в список печатных форм

Документ отвечает на вопрос: почему в окне документа (счёт-фактура, кассовый ордер, платёжка)
в списке печатных форм видно одну форму, а не другую, и что нужно сделать, чтобы там появилась
новая.

Коротко: печатная форма документа — это запись в таблице `Reports` с флагом `IsPrintForm`.
Список для конкретного документа собирает `PrintFormService`; у обычных документов правило одно
(форма привязана к документу), у кассовых ордеров и счетов-фактур — с добавками, потому что
бланки ClosedXML берут данные из набора данных, а не из полей документа.

## 1. Какие колонки `Reports` на это влияют

| Колонка | Что означает | Как влияет на список |
| --- | --- | --- |
| `Code` | Код формы (`cash.receipt.closedxml`, `invoice.sales.foxpro`) | По нему работают соглашения (кассовые ордера, счета-фактуры) и пометки удаления |
| `Name` | Имя в диалоге выбора | По кассовым ордерам в нём ищутся слова «приход» / «расход» |
| `IsPrintForm` | Форма вообще является печатной | **Первое условие**: без него запись в списке не появится |
| `IsActive` | Форма включена | `includeInactive: false` (как в окнах документов) отсекает выключенные |
| `DataSourceType`, `DataSourceId` | Источник данных | Базовое правило: `DataSourceId` = идентификатор документа-источника. У бланков ClosedXML — `ReportSource` (объект набора данных) |
| `IsDefault` | Форма по умолчанию | Печатается кнопками без выбора; стоит первой в списке |
| `Order` | Порядок | Второй ключ сортировки после `IsDefault` |
| `SourceFormat` | `ClosedXml` / `Native` / `FoxProFRX` | Определяет путь печати; `ClosedXml` — вывод по макету и набору данных |
| `ClosedXmlLayout` | Макет бланка ClosedXML | Форма без макета в путь ClosedXML не попадёт |
| `ReportType` | Тип формы (`CashReceiptOrder`, `VatInvoiceVatKg`…) | По нему счета-фактуры отбирают свои бланки |

Сортировка списка везде одна: `IsDefault` (по убыванию) → `Order` → `Name`.

## 2. Кто собирает список

### 2.1 Обычные документы — `PrintFormService.GetPrintFormsAsync(metadataId, includeInactive)`

```csharp
Reports.Where(item => item.IsPrintForm && item.DataSourceId == metadataId)
```

Это базовое правило: форма привязана к документу напрямую. Так работают, например, платёжное
поручение и нативные формы кассовых ордеров.

### 2.2 Кассовые ордера — `GetCashOrderPrintFormsAsync(metadataId, isReceipt, includeInactive)`

Форма попадает в выборку, если выполнено **любое** из условий:

1. `DataSourceId` = документ «Расходный/Приходный КО» (базовое правило);
2. `Code` входит в `CashOrderPrintFormCodes` (`cash.receipt.native`, `cash.payment.native`);
3. `Code` начинается с `cash.receipt.` или `cash.payment.` — так в список попадают бланки
   ClosedXML (`cash.receipt.closedxml`, `cash.payment.closedxml`), у которых источник —
   набор данных, а не документ.

Дальше:

- формам **кроме** ClosedXML в памяти подставляется `DataSourceType = "Document"` и
  `DataSourceId` = документ (у бланков ClosedXML источник трогать нельзя — иначе печать
  не найдёт набор данных);
- отбор по типу ордера: приходный — код/имя со «приход» или `cash.receipt` и без «расход»/`cash.payment`;
  расходный — наоборот;
- отчёты «кассовая книга», «реестр приходов/расходов», «оборот…» из списка исключаются —
  у них свои кнопки в окне.

### 2.3 Счета-фактуры — `GetInvoicePrintFormsAsync(metadataId, includeInactive)`

Базовый список плюс бланки ClosedXML, если документ — **выданный** счёт-фактура
(`TableName = "doc_sales_invoice"`):

```csharp
Reports.Where(item => item.IsPrintForm
                      && item.SourceFormat == "ClosedXml"
                      && !string.IsNullOrEmpty(item.ClosedXmlLayout)
                      && (item.ReportType == "VatInvoiceVatKg" || item.ReportType == "VatInvoiceSt1"))
```

Почему отдельное правило: набор данных бланка читает `doc_sales_invoice`, поэтому в «Регистрации
счёт-фактур» (полученные) он не предлагается — там формы документа свои.

### 2.4 Платёжные поручения

Отдельного правила нет: работают формы, привязанные к документу (2.1).

## 3. Кто создаёт формы (сиды)

| Метод | Что заводит |
| --- | --- |
| `PrintFormService.SeedCashOrderFormsAsync` | Бланки кассовых ордеров: `cash.receipt.closedxml`, `cash.payment.closedxml` (ClosedXML, основные) и нативные `cash.receipt.native`, `cash.payment.native` |
| `PrintFormService.SeedPaymentOrderFormsAsync` | Платёжное поручение (нативная форма) |
| `PrintFormService.SeedInvoiceFormsAsync` | Формы счетов-фактур |
| `MetadataService.EnsureStandardReportsAsync` | Отчёты из описаний (`StandardReportDefinition`), в том числе ClosedXML-отчёты с `SeedClosedXmlLayout: true` |
| `DocumentationMetadataSeedService.EnsureAsync` (внутри — `EnsureReportAsync`) | Отчёты `assets.*` / `inventory.*` |

Сиды идемпотентны: существующая форма обновляется, а не заводится второй раз. Макет
(`ClosedXmlLayout`) заполняется только если он пуст — правки в конструкторе не перетираются.

## 4. Как форма удаляется и не возвращается

Код удалённой формы вносится в `DeletedStandardReports` (его читает
`StandardReportDeletionService.GetDeletedCodesAsync`). Сиды этот список уважают и повторно
форму не создают. Именно так убраны `invoice.sales.foxpro`, `invoice.purchase.foxpro`,
`cash.receipt.foxpro`, `cash.payment.foxpro` и legacy-отчёты: строка копируется в
`FrxBackup_*`, код помечается удалённым, строка отчёта удаляется.

## 5. Что видит пользователь

- **Чекбокс «Выбрать форму»** — открывает `PrintFormSelectionDialog` со списком, который
  передал вызывающий код (`forms`). Выбор запоминается в окне.
- **Кнопки вывода** («📊 Excel», «📄 Предпросмотр ПДФ» в счетах-фактурах и кассовых ордерах) —
  печатают выбранную форму, а если выбор не сделан или форма относится к другому типу документа,
  берут форму с `IsDefault`.
- Диалог сам ничего не фильтрует: что передали — то и показывает. Поэтому «пропала форма»
  почти всегда означает, что её отсеяло правило из раздела 2.

## 6. Как форма печатается

Два пути в `PrintFormService`:

1. **Шаблон** (`Reports.Template`, форматы `Native` / `FoxProFRX`) — данные собираются из полей
   документа (`BuildCashOrderDataAsync`, `BuildInvoicePrintData`), вывод — `BuildTemplateLayout*`.
2. **Макет ClosedXML** (`SourceFormat = "ClosedXml"`, `ClosedXmlLayout`) — данные берёт **набор
   данных** формы (`DataSourceType = "ReportSource"`): `ExportClosedXmlDocumentAsync` выполняет
   запрос набора как подзапрос с фильтром по документу. Ключевая колонка определяется по имени:
   `invoice_id`, `cash_order_id`, `document_id`, `record_id`. Перед выводом досчитываются
   `amount_in_words` (сумма прописью) и `date_text` (дата словами) — в SQL их не собрать.

Именно из-за второго пути бланк ClosedXML нельзя привязывать к документу: тогда печать ищет набор
данных по ссылке на документ и падает с «не найден набор данных».

## 7. Рецепт: добавить печатную форму документу

1. Определиться с путём:
   - бланк на макете ClosedXML — нужен набор данных и макет;
   - настраиваемая форма — шаблон (`Template`) и поля документа.
2. Для бланка ClosedXML: завести набор данных (`ReportDataSetService`) — в нём должна быть колонка
   с идентификатором документа; источник набора создаётся сам (`SyncMetadataSourceAsync`).
3. Завести (или дополнить) сид формы: `IsPrintForm = true`, `IsActive = true`,
   для бланка — `SourceFormat = "ClosedXml"`, `DataSourceType = "ReportSource"`,
   `DataSourceId` = объект набора, `ClosedXmlLayout` = макет
   (`ClosedXmlLayoutTemplates.CreateForReport` + `ClosedXmlReportRenderer.SerializeLayout`).
4. Если форма нужна документам по коду или типу — добавить её код/тип в правило из раздела 2
   (пример — `cash.receipt.` / `cash.payment.`).
5. Решить про `IsDefault`: у документа должна быть ровно одна основная форма, иначе кнопки
   без выбора напечатают не то, что вы ждёте.
6. Форму, которую нужно убрать, — не удалять «молча», а помечать в `DeletedStandardReports`,
   иначе сид вернёт её при следующем запуске.

## 8. Частые ошибки

| Симптом | Причина |
| --- | --- |
| Формы нет в списке | `IsPrintForm = false`, `IsActive = false`, `DataSourceId` не тот документ, либо код/тип не подходит под правила раздела 2 |
| «Не найден набор данных» | Бланк ClosedXML привязан к документу вместо `ReportSource` (или набор не создан) |
| Пустые клетки в бланке | В макете указано имя поля, которого нет в наборе данных; помогает проверка набора запросом в базе |
| Форма вернулась после перезапуска | Код не внесён в `DeletedStandardReports` — сид создаёт её заново |
| Печатается не та форма | У документа больше одной формы с `IsDefault = true` либо форма выбрана флажком «Выбрать форму» |
