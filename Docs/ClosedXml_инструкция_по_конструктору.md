# Визуальный конструктор ClosedXML: как собрать отчёт

Практическая инструкция по вкладке **«📊 ClosedXML макет»**: откуда берутся данные,
где хранится разметка, как собрать акт сверки и что модель пока не умеет.

Связанные документы: [`ExcelReportsProgrammatic.md`](ExcelReportsProgrammatic.md) (§13 — как это устроено в коде),
[`ReportingArchitecture.md`](ReportingArchitecture.md).

---

## 0. Где хранится разметка (JSON)

| Вопрос | Ответ |
| --- | --- |
| Таблица | `Reports` |
| Колонка | **`ClosedXmlLayout`**, тип `text NOT NULL DEFAULT ''` |
| Модель | `Models/Report.cs` → `Report.ClosedXmlLayout` |
| Кто создаёт колонку | [`RuntimeSchemaFixService`](../Services/RuntimeSchemaFixService.cs) — `ALTER TABLE "Reports" ADD COLUMN IF NOT EXISTS "ClosedXmlLayout" text NOT NULL DEFAULT ''` при запуске программы |
| Кто пишет | [`ReportService.SaveReportAsync`](../Services/ReportService.cs): новый отчёт — `Reports.AddAsync`; существующий — `CopyPrintFormSettings` (`target.ClosedXmlLayout = source.ClosedXmlLayout`) |
| Кто читает | конструктор (`ReportDesignerWindow`) и вывод отчёта (`AccountingReportsView`, формат `ClosedXmlExcel`) |

Проверка прямо в базе:

```sql
SELECT "Name", LENGTH(COALESCE("ClosedXmlLayout", '')) AS json_len
FROM "Reports"
ORDER BY json_len DESC
LIMIT 20;
```

Разметка сохраняется кнопкой **💾 Сохранить** в конструкторе. Отдельно ничего вводить не нужно.

## 1. Набор данных задаётся НЕ на этой вкладке

Вкладка «📊 ClosedXML макет» только раскладывает данные по листу. Данные приходят из других вкладок:

| Что | Где задаётся |
| --- | --- |
| **Источник данных** — таблица, справочник или SQL-набор | вкладка **«📋 Общие»**, поле «Источник»; кнопка **«+»** открывает редактор наборов данных отчётов, **«?»** — выбор источника |
| **Колонки набора** — какие поля выводить | вкладка **«📊 Поля»** |
| **Параметры** — период, организация, контрагент | вкладка **«⚙ Параметры»**; в макете подставляются через `{param.Имя}` |
| **Фильтры** — что отобрать | вкладка **«🔍 Фильтры»** |

Сверху вкладки ClosedXML есть строка **«Набор данных»**: текущий источник, число полей отчёта,
кнопки **«Выбрать источник»** (переходит на «📋 Общие») и **«Обновить поля»**.
Внизу редактора таблицы — список **«Поля набора данных»**; **двойной щелчок** подставляет поле
в выбранную строку колонок.

> **Правило имён полей.** После формирования отчёта колонки набора называются так, как указано
> в столбце **«Отображаемое имя»** на вкладке «📊 Поля». Но в макете можно писать **и «Имя поля»,
> и «Отображаемое имя»** — рендерер добавляет колонку-двойник. Регистр не важен.

## 2. Шаги сборки обычного отчёта

1. **«📋 Общие»** — сначала выберите **способ макета**, затем источник и название.
   Переключатель **«Способ макета»** оставляет на экране только то, что относится к выбранному способу:

   | Способ | Что видно | Что скрыто |
   | --- | --- | --- |
   | **ClosedXML — визуальный Excel** | вкладка «📊 ClosedXML макет» | вкладки «🔗 FRX поля» и «🧱 Нативный макет», поле «FRX-шаблон», тип отчёта «Макет Visual FoxPro FRX» |
   | **FRX — макет FoxPro (FRX/native)** | вкладки «🔗 FRX поля» и «🧱 Нативный макет», поле «FRX-шаблон» | вкладка «📊 ClosedXML макет» |

   Способ сохраняется в поле `Report.SourceFormat`: `ClosedXml` или `FoxProFRX`/`Native`.
   При открытии отчёта способ выбирается автоматически по его макету.
2. **«📊 Поля»** — двойным щелчком добавьте нужные колонки, задайте «Отображаемое имя».
   Поля, нужные только для группировки, можно скрыть галочкой «Видимость».
3. **«⚙ Параметры»** — добавьте период и прочие параметры (кнопка «Параметры из фильтров» создаёт
   их по ссылкам `{Имя}` в фильтрах).
4. **«📊 ClosedXML макет»**:
   - **«Новый пустой макет»** или **«Загрузить макет»** (готовые разметки — см. §7);
   - кнопками **+ Заголовок**, **+ Таблица**, **+ Строки**, **+ Подписи**, **+ Разрыв** соберите блоки;
   - **↑/↓** меняют порядок, **− Удалить** убирает блок;
   - блок **«Таблица»** после выбора полей заполняется колонками автоматически;
   - настройки листа справа: имя, ориентация, заморозка строк, шрифт, кегль, линии сетки.
5. **«📊 Предпросмотр ClosedXML»** — проверьте результат.
6. **💾 Сохранить** — разметка уходит в `Reports.ClosedXmlLayout`.
7. В списке бухгалтерских отчётов выберите формат **«ClosedXML Excel (визуальный макет)»**
   и нажмите «Сформировать».

## 3. Акт сверки: он уже собран как обычный отчёт

Акт сверки был «программным» отчётом: xlsx собирался кодом. Теперь его визуальный макет —
**обычный отчёт в базе**, а не код:

| Что | Где |
| --- | --- |
| Отчёт | **«Акт сверки (ClosedXML)»**, код `standard.finance.reconciliation-act-closedxml` |
| Тип | `ReportType = ReconciliationAct` — данные акта строит тот же расчёт, что и раньше |
| Способ | `SourceFormat = ClosedXml` |
| Макет | `Reports."ClosedXmlLayout"` — записывается один раз при первом запуске и дальше живёт в базе |
| Где править | конфигуратор → **генератор отчётов** → этот отчёт → вкладка **«📊 ClosedXML макет»** |

Код подставляет макет **только при первичном создании отчёта** (`MetadataService.EnsureStandardReportsAsync`
→ `EnsureStandardReportAsync`). Если макет уже есть в базе, он не перезаписывается: правки,
сделанные в генераторе отчётов, сохраняются.

Порядок работы:

1. откройте отчёт «Акт сверки (ClosedXML)» в генераторе отчётов;
2. вкладка **«📊 ClosedXML макет»** — макет уже загружен из базы, его можно менять мышью;
3. **💾 Сохранить** — правки уходят в `Reports."ClosedXmlLayout"`;
4. вывод (экран «Бухгалтерские отчеты» → «Акт сверки (ClosedXML)» → формат «ClosedXML Excel»)
   сразу использует сохранённый макет.

Макет повторяет программный Excel (`PrintFormService.BuildReconciliationActExcel`) строка в строку:

| Строка листа | Содержимое |
| --- | --- |
| 1 | `АКТ СВЕРКИ`, объединение A:H, жирный, по центру |
| 2 | заголовок акта из 1-й строки набора, A:H, жирный, по центру |
| 3 | период из 2-й строки набора, A:H, по центру |
| 4 | пустая |
| 5 | шапка из 8 колонок, заливка `#D9E6F2`, жирный, по центру |
| 6…N | тело: строки набора без «АКТ…», «Период…», без пустых и без итоговой фразы; «Пара счетов», «САЛЬДО», «ИТОГО» — жирным |
| N+1, N+2 | пустые |
| N+3 | итог задолженности (последняя строка набора), A:H, жирный |

### 3.1. Откуда берутся данные акта

Набор акта (`Services/ReconciliationActBuilder.cs`) — это **8 колонок**:

| № | Колонка | Что в ней |
| --- | --- | --- |
| 1 | `Наименование материала, вид операции` | текст операции и метки строк («Пара счетов…», «САЛЬДО НА…», «ИТОГО ОБОРОТОВ») |
| 2 | `Дебет` | код счёта дебета |
| 3 | `Кредит` | код счёта кредита |
| 4 | `Сумма Дт` | сумма по дебету или пусто |
| 5 | `Сумма Кт` | сумма по кредиту или пусто |
| 6 | `N докум` | номер документа |
| 7 | `Дата` | дата документа, `дд/ММ/гггг` |
| 8 | `Модуль` | код модуля (АРМ) |

Главное: **структура акта уже в данных**. Строки идут плоским потоком —
`АКТ СВЕРКИ …`, `Период: …`, пустая, затем на каждую пару счетов:
`Пара счетов : X - Y (наименование)`, `САЛЬДО НА <начало>`, строки операций,
`ИТОГО ОБОРОТОВ`, `САЛЬДО НА <конец>`, а в конце — строка задолженности.
Поэтому в макете не нужны группировки: нужны **правила выделения строк по содержимому**.

### 3.2. Как устроен встроенный макет

| Блок | Что делает |
| --- | --- |
| «Заголовок акта» | две строки, значения взяты **из данных**: «Из строки набора» = 1 и 2, поле — колонка 1. Верхняя — жирная, 12 пт, по центру, объединена A:H |
| «Таблица акта» | 8 колонок с настоящими заголовками, заливка шапки `#D9E6F2`, ширины 44 и 12, «не выводить нули» для сумм |
| «Подписи» | руководитель и главный бухгалтер |

Правила выделения (условное оформление по первой ячейке строки):

| Условие | Оформление |
| --- | --- |
| содержит `Пара счетов` | жирный |
| начинается с `САЛЬДО` | жирный |
| содержит `ИТОГО` | жирный |
| содержит `Задолженность` | жирный + объединение A:H |

Плюс **пропуск строк** `АКТ` и `Период` — они уже выведены блоком «Заголовок акта»,
в теле повторять их не нужно.

## 4. Приёмы настройки

### 4.1. Цитирование ячейки набора в текстовом блоке

В блоке «Заголовок»/«Строки» у ячейки есть два поля: **«Из строки набора»** (`TakeFromRow`,
1-based) и **«Поле набора»** (`TakeFromField`). Если они заданы, в ячейку попадёт значение
из этой строки и колонки набора — так в акт попадают заголовок и период, которых нет среди параметров.

### 4.2. Правила выделения строк

Работают только для блока «Таблица». Сравнение идёт с **первой непустой ячейкой строки**:

| Поле | Значение |
| --- | --- |
| Способ сравнения | `StartsWith`, `Contains`, `Equals` |
| Текст | что искать |
| Жирный / Курсив / Выравнивание / Заливка | что применить |
| Объединить метку до колонки | 0 — не объединять; N — объединить колонки 1..N (если справа пусто) |

### 4.3. Не выводить нули

У колонки есть признак **«Не выводить нули»** (`SuppressZero`): вместо `0,00` ячейка остаётся пустой —
как в акте сверки. Если суммы приходят как `NULL`, это и так даёт пустую ячейку.

### 4.4. Пропуск служебных строк

У таблицы есть список **«Пропускать строки, начинающиеся с»** (`SkipRowsStartingWith`).
Так из тела убираются строки, уже показанные в шапке.

### 4.5. Группировка и итоги

- **Группировать по** — поля через запятую, в порядке значимости;
- **Заголовок группы** — `{value}` (значения полей через ` / `), `{ИмяПоля}` (значение конкретного
  поля первой строки группы), `{param.Имя}`. Пример: `Пара счетов: {Дебет} - {Кредит} ({Наименование})`;
- **Подытог (метка)** и **Общий итог (метка)** пишутся **формулами** `=SUM(...)` только по строкам данных:
  заголовки групп и строки подытогов в сумму не попадают;
- соседние строки сжимаются в непрерывные диапазоны (`SUM(C5:C75,C78:C149)`), иначе формула
  превысила бы предельные 8192 символа Excel.

## 5. Чего пока нельзя выразить

Проверено по интерпретатору `Services/ClosedXmlReportRenderer.cs`.

| Что | Почему |
| --- | --- |
| **Многорядная шапка таблицы** (как «ОБОРОТЫ - сом» над «Дебет»/«Кредит» в оборотной ведомости) | шапка таблицы — одна строка заголовков |
| **Повторяющаяся шапка на каждую группу** и **многострочный «хвост» группы** (`ИТОГО ПО …`, `САЛЬДО НА НАЧАЛО`, `ОБОРОТЫ`, `САЛЬДО НА КОНЕЦ`) | у группы один заголовок и один подытог |
| **Арифметика кроме SUM**: сальдо на начало (сумма по строкам вне периода), сальдо на конец (`начало + Д − К`), разность, `SUMIF` | рендер умеет только `SUM` по строкам данных блока |
| **Объединение части строки данных** (1:4) с одновременным сохранением значений справа | объединение возможно, только если справа пусто |
| **Начать таблицу не с колонки 1** | таблица всегда пишется с колонки 1 |
| **Условный вывод блока** («показать строку, только если данных нет») | блоки выводятся всегда |

Практический вывод:

- **Акт сверки** — выражается полностью: структура приходит данными, нужны только правила выделения;
- **Оборотная ведомость по авансам** — не выражается: там повторяемые 4-строчные шапки блоков,
  4-строчные хвосты на каждого сотрудника и сальдо с арифметикой вне `SUM`.
  Пока это отдельный программный генератор `AdvancePaymentsTurnoverReportService`.

## 6. Частые ошибки

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Колонка пустая | имя в «Поле (DataTable)» не совпадает ни с «Имя поля», ни с «Отображаемым именем» | сверьтесь со списком «Поля набора данных» |
| В заголовке выводится текст поля, а не значение | не заданы «Из строки набора» / «Поле набора» | заполните оба поля ячейки |
| Строка задолженности не объединяется | справа в строке есть значения | уберите лишние значения или снимите объединение |
| Суммы не считаются в Excel | колонка пришла текстом | задайте числовой формат и проверьте тип поля в наборе |
| Нули мешают | не включено «Не выводить нули» | включите признак у колонки |
| Пропали строки набора | у полей снята галочка «Видимость» | включите видимость на вкладке «📊 Поля» |
| Разметка не читается: «таблица не содержит колонок с полями» | в блоке «Таблица» нет ни одной колонки с заполненным «Поле» | заполните колонки или нажмите «Загрузить макет» |
| «Не сохранён ClosedXML-макет» | для отчёта нет макета и он не акт сверки | соберите и сохраните макет |

## 8. Отдельный отчёт для ClosedXML в «Бухгалтерской отчётности»

В списке **«Отчет:»** (экран «Бухгалтерские отчеты») теперь два пункта про акт:

| Пункт | Что делает |
| --- | --- |
| **Акт сверки** | программный акт: доступен выбор «Вариант акта сверки» — макеты из метаданных (FRX/native), формат вывода любой |
| **Акт сверки (ClosedXML)** | тот же расчёт по тем же данным, но отчёт помечается как ClosedXML: FRX-варианты не применяются, в `Report.ClosedXmlLayout` кладётся встроенный визуальный макет, формат вывода **автоматически** переключается на «ClosedXML Excel» |

Порядок работы:

1. **Отчет:** → «Акт сверки (ClosedXML)»;
2. задайте период и организацию («Организация:» — конкретная или «Все организации»);
3. **«Сформировать»** → **«Открыть»** — откроется `.xlsx`, собранный визуальным макетом;
4. чтобы изменить макет — откройте отчёт в конструкторе, вкладка «📊 ClosedXML макет».
