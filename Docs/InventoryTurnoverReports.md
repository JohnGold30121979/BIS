## Что добавлено в BIS.ERP

В **«Бухгалтерских отчётах»** доступны **«Оборотная ведомость по материалам»** и **«Оборотная ведомость по материально ответственным лицам»**. Первая группирует строки по материалу и счёту хранения. Вторая дополнительно показывает участок и ответственное лицо. Обе дают количество и сумму на начало, приход, расход и остаток на конец. Итоговая строка складывает суммы. Количества разных материалов и единиц измерения в общий итог не складываются.

Отчёты показывают движения текущей инфобазы. Фильтр по организации скрыт, поскольку движения материалов группируются по участку и ответственному лицу. В ведомости по материалам можно исключить перемещения внутри счёта хранения. При включённой отметке стороны перемещения сворачиваются в пределах одного документа, материала и счёта. Переход между разными счетами остаётся в оборотах. В ведомости по ответственным лицам обе стороны всегда видны.

Единица измерения берётся из текущей карточки материала. Начальный остаток складывается из проведённых движений до начала периода, поэтому для сверки с FoxPro в BIS.ERP должны быть проведены сопоставимые начальные данные. Отдельные варианты FoxPro, например сальдовая ведомость, печать без сумм и отбор по объекту строительства, этой правкой не переносились.

### Настройка через конфигуратор

У каждой ведомости есть **системный набор данных** и **редактируемый макет ClosedXML**. В конфигураторе можно открыть отчёт, выбрать источник, настроить поля и макет, изменить оформление и отметку «Показывать в бухгалтерской отчётности». Конструктор получает поля и параметры из штатного набора данных. Сохранённый макет и источник существующего отчёта при посадке сохраняются. Формула бухгалтерского расчёта реализована в системном наборе данных. Если требуется другой запрос, можно привязать другой совместимый источник с полями, на которые ссылается макет.

В бухгалтерском окне даты берутся из полей периода. В первой ведомости переключатель внутренних перемещений передаётся как параметр `ExcludeInternalTransfers`. Для своего источника с тем же назначением следует поддержать параметры `PeriodStart`, `PeriodEnd` и, при необходимости, `ExcludeInternalTransfers`.

Миграция `2026.11.10.05` регистрирует отчёты на существующих базах после создания справочников. Новая инфобаза получает те же определения через стандартную посадку отчётов. Наборы и макеты хранятся в существующей структуре метаданных. Отдельная таблица оборотных ведомостей не создаётся.

### PostgreSQL и C#. Остатки и обороты

[InventoryTurnoverReport.cs](<D:/C#/BIS.ERP/BIS.ERP/Services/InventoryTurnoverReport.cs>) читает представление `inventory_material_movements`. Движения раньше начальной даты входят в остаток на начало. Конечная дата включается целиком через границу следующего дня. Положительное движение образует приход, отрицательное — расход. Расход выводится положительным числом.

```sql
COALESCE(SUM(quantity_change) FILTER (WHERE movement_date < @start), 0) AS opening_quantity,
COALESCE(SUM(quantity_change) FILTER (WHERE movement_date >= @start AND quantity_change > 0), 0) AS receipt_quantity,
-COALESCE(SUM(quantity_change) FILTER (WHERE movement_date >= @start AND quantity_change < 0), 0) AS issue_quantity
```


Обе формулы используют порядок **начало + приход − расход**. Первая считает количество, вторая — сумму.

## Как проверить

1. После применения миграции открыть «Бухгалтерские отчёты», выбрать ведомость по материалам и указать период. Нажать «Сформировать», затем «Excel».
2. Для контрольного материала провести приход **10 единиц на 100** до начала периода. Внутри периода переместить **4 единицы на 40** между ответственными лицами на одном счёте и списать у получателя **2 единицы на 20**.
3. В ведомости по материалам ожидать **10 / 100** на начало, **4 / 40** по приходу, **6 / 60** по расходу и **8 / 80** на конец. При исключении внутренних перемещений приход станет **0 / 0**, расход — **2 / 20**, остаток сохранится **8 / 80**.
4. В ведомости по ответственным лицам ожидать на конец **6 / 60** у отправителя и **2 / 20** у получателя.
5. В конфигураторе открыть макет одной ведомости, изменить видимую подпись в шапке, сохранить и снова экспортировать отчёт. Проверить, что Excel использует сохранённую подпись. Сравнить поля и параметры в карточке набора данных.
